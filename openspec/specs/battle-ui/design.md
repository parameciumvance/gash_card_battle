# battle-ui — 設計

目前只整理了網站名稱與圖示、背景紋路、首頁與設定頁、決策互動、卡片元件、借用效果入口、戰術的使用魔物與搭檔的裝備對象、場上魔書翻閱、魔書網格排版、更新內容、行動記錄抽屜、新房間清空記錄、事件動畫、對手行動聚焦展示、回合和時機指示、規則頁、意見回報與語言;其餘畫面設計以 `frontend/` 程式與測試為準。

## 網站名稱與圖示

- 名稱「Gash Card Battle Online」:`<title>` 寫在 `index.html`,頂欄與首頁標題取自 i18n 的 `app.title`;四種語言相同、不翻譯(專有名稱),`build_zh_cn.py` 不轉換。原本沿用原作卡牌遊戲的日文名稱,容易被誤認為官方商品,改為自己的名稱。
- 網頁圖示 `frontend/favicon.svg`:魔書紅圓角方塊、金色五圓紋,以 `<link rel="icon">` 引用。線寬以 16px 可辨識為準,比背景紋路 `emblem.svg` 粗很多,兩者顏色、底色也不同,各自一檔。只有 SVG:主流瀏覽器都支援;要支援舊版 Safari 或 iOS 主畫面圖示(`apple-touch-icon`)時再補 PNG。
- **標題字**:首頁 `.wordmark.large`、頂欄 `.wordmark.small`(排成一行),結構寫在 `index.html`;徽章直接用 `favicon.svg`,與網頁圖示永遠一致。GASH 魔書紅、CARD BATTLE 深藍、ONLINE 琥珀色,三行沿同一條中線置中。字距會在字尾多出一段空白,大字的字形左右留白也會放大,只置中外框會讓墨色偏右;各行以等於字距的左內距平衡,測試以 canvas 量的墨色邊界檢查三行中心一致。`app.title` 只作 `aria-label`。
  - 字型 Oswald(OFL)以 Google Fonts `text=` 取標題字母的子集,約 2.5KB,自架於 `frontend/fonts/`(附授權檔),不向第三方請求。改標題字的字母時要重新取子集。

## 背景紋路

- 魔書封面的五圓紋:`frontend/emblem.svg`,依封面比例自行繪製的線條(四角與中央五個圓,圓心是沙漏形的四個頂點與交點),不使用照片或卡圖。
- 淡色由 SVG 內的 `stroke-opacity` 控制,改深淺只改 SVG。
- 套用在 `body`(首頁、設定頁,`fixed` 置中)與 `#board`(對局盤面,置中於中線附近),都疊在原本的底色上。尺寸 `--emblem-size`(最大 560px,手機為 82vw)。

## 首頁與設定頁

- **結構**:首頁(`#landing`)只放入口按鈕,不放任何設定欄位。NPC 對戰、與朋友對戰、本機測試共用一個設定頁視圖(`#setup`),頂端是返回與標題,下面三個面板一次顯示一個(`openSetup(mode)`)。牌組構築與規則沒有設定,直接進入。
  - 用整頁而不是覆蓋層:手機上比較好操作,也和構築器一樣是獨立畫面。
- **自由調查時間**:本機測試模式(`mode=local`、`entry-local`、`isLocal()`)對玩家顯示的名稱,四種語言見 `ui.landing.local`;錯誤訊息 `error.room.not_local`、`error.room.not_joinable` 也用這個名稱。規格與程式中的「本機房」「本機測試模式」是技術名稱,沒有跟著改。
  - 改名與排序的理由:曾有玩家把原本的「本機測試模式」當成 NPC 對戰,替對手按了 pass 卻回報成 NPC 的行為。新名稱不像一種對戰模式;簡介開頭就寫「沒有電腦對手」;入口排在牌組構築之後,不再緊接在兩種對戰之後。依使用者決定。
- **返回進行中的對局**:`refreshResumeRooms()` 在每次 `show("landing")` 時掃描 `gash-room-*`,以記錄的 token(本機模式用玩家 0)並行請求 `/api/rooms/{code}/state`;失敗的移除記錄、`game_over` 的不列出,其餘在入口卡片上方列出(模式、對手、房號、回合或等待對手),點選走 `resumeRoom`。`resumeGen` 讓較早的查詢結果不覆蓋較新的。離開房間本來就不刪記錄,所以「離開」後可以返回。
- **標題回首頁**:頂欄 `#title`(`role="link"`、可聚焦,Enter / 空白鍵)呼叫 `goHome()`:在房間中走 `leaveRoom()`,否則網址換回 `/` 並顯示首頁。窄螢幕只隱藏標題文字、保留徽章。
- **與朋友對戰**:建立 / 加入合併成一個面板,上方兩段式切換,暱稱與牌組兩種模式共用,只有計時(建立)與房號(加入)不同。切換只改顯示,不清除已填的值。加入失敗時顯示錯誤並留在設定頁,可直接修正房號。
- **賽季選單**:與朋友對戰的建立模式、NPC、本機設定頁與牌桌頁的開桌設定各有一個(`season-*`,選項來自 `data/seasons.json` 的 `selectable`,缺省 `default`)。
  - 牌組選項記下名稱、賽季(預組取自 `GET /api/decks` 的 `season`,本機魔書由頁序計算)與是否不合法,`applySeasonLimits()` 依對應的賽季選單(`DECK_SEASON_SELECT`)決定禁用與「第 N 賽季起可用」標示;選中的變成不可用就回到 level1。NPC「隨機」只送所選賽季可用的候選。
  - 與朋友對戰的加入模式與牌桌頁不依賽季禁用,改為每個選項都標示賽季:賽季由房間或牌桌決定,牌桌頁同一個牌組欄位要用來加入各種賽季的桌子。牌桌頁改在按鈕上限制:魔書超出開桌賽季時空桌「入座」禁用、超出該桌賽季時「對戰」禁用,並在桌下說明。
  - 以房號加入不另設確認畫面:加入前沒有取得房間設定的流程,改以 `deck.season` 錯誤訊息告知房間賽季;多一次查詢仍要處理加入失敗,收益不大。牌桌頁本來就有列表,所以直接在桌面顯示賽季(短寫「第1季」)。
- **加入連結**:`?join=房號` 開啟加入模式並預填房號,由加入者選好暱稱與牌組再加入,不自動加入:加入後立即開局,沒有機會再換牌組。按返回時網址換回 `/`,重新整理不會再回到加入模式。
- **記住選擇**:localStorage `gash-setup` 存各模式的選單值(`npc: {deck, opp, level, season}`、`friend: {deck, timer, mode, season}`、`local: {deck0, deck1, season}`、`tables: {deck, timer, season}`),鍵與欄位的對應集中在 `SETUP_FIELDS`。`restoreSetup()` 先還原賽季、套用賽季限制,再還原牌組,記住的牌組超出賽季時自然回到缺省。
  - 在選單變更時就存,不是開始時才存:玩家可能選好牌組後先去構築器看一眼,回來時應保持原本的選擇。
  - `renderLanding()` 每次重新產生選單後還原;記住的值不是可選的選項(牌組已刪除或不合法)就維持缺省。
  - 加入連結打開的加入模式不覆蓋記住的建立 / 加入偏好;房號不記住,避免誤加入舊房。
  - 暱稱另存在 `gash-nick`,開始時才存;本機測試的兩個暱稱不存也不預填(兩個欄位共用一個記住的暱稱並不合理)。
- **免責聲明**:首頁入口下方的頁尾 `#landing-disclaimer`,小字低對比;只在首頁顯示,不佔用對局與手機畫面。README 開頭放同樣的中文聲明。
  - 兩句:①非官方、與原作者及 BANDAI 無關且未經授權(本專案沒有取得任何許可),免費不營利;②權利屬於雷句誠、BANDAI 及各權利人,權利人可透過意見回報聯絡。
  - 權利人寫「及各權利人」而不逐一列出(小學館、東映動畫、富士電視台等),避免遺漏或寫錯官方標示。
  - 日文是權利人會看的版本,用日文慣用說法,不逐字翻譯。
  - 「意見回報」以 `{feedback}` 帶入首頁入口名稱,各語言一致;依使用者決定不做成連結。
  - 措辭與使用者討論後定稿;若取得授權或改變性質,要同步修改,改動前先確認。
- **對戰中人數**:`#landing-foot` 最上方的 `#landing-online`,位在入口與免責聲明之間;人數來自 `GET /api/online`(計數規則見 `online-room/design.md`「對戰中人數」)。
  - 標籤寫「對戰中」不寫「在線」:首頁本身沒有連線,看首頁的人不會算到自己,寫「在線 0 人」會與看的人正在線上矛盾。依使用者決定。
  - 0 人顯示「目前沒有人對戰」,行首圓點由綠色改灰色,不隱藏這一行:如實告知目前沒有其他玩家,版面也不會因數字有無而跳動。這是 Agent 的選擇,確認狀態 `Inferred`。
  - 更新時機:`show()` 每次切換畫面都呼叫 `syncOnline()`。在首頁且頁面可見時立即抓取,之後每 30 秒一次;離開首頁或頁面隱藏(`visibilitychange`)時停止,回到頁面且仍在首頁時立即抓取。規則頁、意見回報等覆蓋層開在首頁上時照常更新。
  - 取得失敗時隱藏這一行,不留舊值也不當成 0;重新抓取期間保留上一次的值,避免每次回到首頁都先消失再出現。請求交錯時以 `onlineSeq` 只採用最後一次發出的結果。
  - 英文 `In battle now: {n}`:`t()` 不支援複數,用不必變化的句型。
- **垂直置中**:首頁用 auto margin 置中,不用 `justify-content: center`;內容比畫面高(手機)時才會從頂端排起可捲動,不會往上溢出被頂欄蓋住。
- **瀏覽器歷史**:全站只用 `replaceState`,進入設定頁不改網址;手機返回手勢會離開網頁。要支援返回手勢,需要連對局中的返回一起設計,尚未處理。

## 牌桌頁(game-tables)

- 首頁「牌桌」入口開啟牌桌頁(`#tables` 視圖);`syncTables` 只在牌桌頁且頁面可見時每 5 秒 `GET /api/tables`,與首頁的對戰中人數同樣做法。
- 牌桌畫成俯視的桌子(全用 CSS,不用圖檔):上下兩個座位夾著方桌(圓角矩形的木框 + 綠色絨布),桌面寫桌號、狀態、計時(短寫「60 秒」)與等待時間。座位有人時顯示暱稱(上方為開桌者),沒人時為虛線的「空位」;有人等待時空位發光,提示可以坐。結束後的桌面降低彩度。
- 暱稱沿用全站記憶(`gash-nick`);牌組與開桌計時記在 `gash-setup.tables`。開桌計時只有 30 / 60 / 120 秒。
- 入座回 409 `table.taken` 時,`#tables-confirm` 顯示實際的開桌者、計時與賽季,按「對戰」以 `expect: "waiting"` 再入座;`api()` 的錯誤帶 `detail` 才拿得到這些欄位。
- 入座後 `SESSION.table` 記桌號:等待畫面隱藏房號與加入連結(牌桌房不能用房號加入),顯示「離開」。
- 對局結束時,行動欄(本來是空的)放「再戰 / 離開」與對方的選擇、剩餘秒數(來自 `room.table`);收到 WebSocket 的 `table_moved` 時存下新房的 session,以 `resumeRoom` 進入新房(等待中或已開局),觀戰者改觀戰新房。

## 決策互動

- **不用蓋住畫面的對話框**:決策者的行動欄改為決策區塊(`choicePromptEl`):標題、來源卡、擲幣結果、提示句、按鈕(開啟魔書 / 棄牌區、純選項)。決策期間場面、魔書、棄牌區、作用中效果都可查閱。非決策者維持摘要。
  - 決策對話框(`#dialog-overlay`)只剩客戶端自己的前置選擇:指令戰術選使用者(`pickSlotThen`)與棄牌區清單(`showDiscard`)。
- **選擇狀態**:`render()` 開頭以 `pickState()` 算出全域 `PICK`(只對決策者),依選項的 `zone` 分成場上(`玩家:uid:mamodo|partner`)、魔書(`玩家:頁碼`)、棄牌區(`玩家:索引`)、按鈕、退回列出的卡。選項卡號等於魔物槽的搭檔(且不是魔物本身)時標在搭檔卡上。
- **在原位置選**:可選目標加 `.pickable`(金光,和可用卡的綠光區分);點了開放大檢視,`pickButtons(ctx)` 在既有行動按鈕前加「選擇」。不在場上的卡(魔書網格、棄牌區)用 `ctx.kind = "pick"`,目標不再可選時放大檢視自動關閉。空頁沒有卡面可放大,點了直接選。
  - 用放大檢視多一步:可以先看完整效果,選擇送出後無法撤回,避免誤觸。
- **魔書網格**:`showBookReview(p)` 同時用於查閱與選擇(`BOOK_VIEW` 記開啟中的是誰的魔書,`render()` 時依新狀態重繪)。自己的魔書有全部卡面;對手的魔書只有選項中的頁有卡面,其他頁是卡背——檢視對手魔書(M-011 / E-016 / E-017)時例外,見下。從網格選完自動關閉,回到場面。
- **選擇提示**:`pickHint(p, zone)`——目前的決策在該玩家魔書 / 棄牌區有目標時,網格標題下(`#book-review-hint`)與棄牌區對話框(notes、來源卡區塊)顯示決策的通用標題與來源卡名;單純查閱時不顯示。
- **自動開啟**(`autoOpenPick`,每批演出結束後):決策的可選目標都在同一本魔書或同一個棄牌區、場上沒有目標時自動開啟它;以 pending 的 kind、決策者、來源、選項為鍵,同一決策只自動開啟一次,關閉後由提示的按鈕再開。開啟要等這批事件的疊加演出(放卡、棄牌)播完:`Anim.overlaySettleMs` 估計長度,記成最早可開啟時間 `pickOpenNotBefore`;同一批經 HTTP 與 WS 各到一次時,第二次沒有新事件,也要等到那個時間,否則會蓋住第一次的演出。原本「不自動開啟以免蓋住場面」的決定已推翻:網格可關閉,而連續決策(M-025:棄牌區 → 魔書空頁)每步都要多按一次(使用者指定)。有場上目標的決策不自動開啟。
- **檢視對手魔書**:網格顯示對手所有未離開頁的卡面。挑卡決策期間,非候選頁的卡面取自即時的 `book_revealed`(`REVEALED`,只送給檢視者);沒有可選的卡時,引擎停在 `end_book_review`,它的選項附整本卡面,重新整理後也有。提示有「結束檢視」與開啟對手魔書的按鈕;檢視結束(選定或結束檢視)後不再提供卡面,網格隨之關閉。
  - 放大檢視的 z-index 在網格之上,網格中的卡才能放大選擇。
  - 開啟時(`BOOK_VIEW` 原本不是這位玩家)捲到 `pos` 所在的對頁;開啟期間 `render()` 重建網格前記下 `#book-review` 的 `scrollTop`、重建後還原,不打斷玩家正在看的位置。標題列 `#book-review-head` 為 sticky,捲到中段時標題與「關閉」仍在上緣。
- **退回**:沒有 `zone` 的卡片選項直接列在決策區塊中,點了即選,避免新的選項來源沒標位置時卡住。

## 卡片元件(`cardEl`)

- 文字卡面:卡圖、卡名、日文名、資訊列 `.cmeta`(傷害、A/D、中級 / 上級、干擾)、效果文、卡號 `.cnum`,以及魔力 / 費用的數值徽章 `.val-badge`。魔力與費用只以徽章呈現,資訊列不重複列出(card-value-badges-and-battle-stage)。
- 數值徽章與分色:`cardEl` 對有魔力的卡(魔物的魔力;戰術的魔力加值寫「+N」、特殊寫「特殊」)與有費用的戰術 / 事件一律產生徽章(缺卡圖也有)。`valueChange(base, current, lowerIsGood)` 比較卡面與呼叫端傳入的目前數值(場上魔物、翻開頁),不同時以 `val-good` / `val-bad`(對持有者有利 / 不利;費用低為有利)著色徽章;沒傳入時顯示卡面數值、中性色。
  - 魔力徽章在左下(卡名下方),字級、行高與底距和右下的卡號標籤相同(專案負責人要求魔力不小於卡號),內含 `.val-label`(「魔力」)與 `.val-num`:放大檢視顯示兩行,其他卡面以 CSS 隱藏標籤、只寫數值,避免小卡面上換行或蓋住卡名。
  - 費用徽章只寫數值、蓋住卡圖右上的費用格。`.card` 是 container query 容器(`container-type: inline-size`),徽章以 `100cqw`(卡片內容寬 = 卡圖寬)換算位置,各場合卡寬不同(盤面、卡池、頁位、金手指、放大檢視)也對齊;需要支援 container query 的瀏覽器。
  - 盤面以外的卡面在底部預留一列(`padding-bottom`):左下魔力徽章、右下卡號,不蓋住效果文;盤面、卡背與固定尺寸的卡維持原本內距;放大檢視一律為卡號預留,有魔力徽章時(`.has-power`)再加高為兩行徽章的高度。盤面卡片 `isolation: isolate`,卡內徽章不會浮到行動區上。常駐效果失效中以 `opts.badges` 的 `blocked-mark` 標在卡圖左下(左上是疊放張數)。
- 放大檢視的 `zoomDetails`:魔物的魔力、翻開頁 / 任意頁戰術的費用與卡面不同時列快照的 `power_breakdown` / `cost_breakdown`(沿用 `infoRow` 與 `breakdown.*`;卡面費用 `card` 與魔物魔力同為不帶正負號的基礎值),以及該卡的 `blocked_effects`(「〈卡名〉的效果被〈來源〉擋下」)。中級 / 上級以 `.cclass` 標籤併入資訊列(中級綠底、上級紅底),因為它和費用、A/D 一樣是卡片屬性;盤面隱藏資訊列,自然不顯示。干擾(ジャマー)效果圖示同樣以 `.cclass.ctag-jammer` 標籤(紫底)併入資訊列(jammer-tag,2026-11-07):依卡片資料的 `effect_icon` / `effect_icons` 判斷,不依引擎的逐卡登記,所以尚未開放的卡也有;多個效果圖示的卡(M-080)只標一次。標籤文字繁中「干擾」、日文「ジャマー」、英文「CUT-IN」——英文版卡面的圖示就印 CUT-IN,「Jammer」是音譯不好懂,英文的規則頁與效果文也統一稱 CUT-IN(使用者指出)。BATTLE / NO BATTLE 不加標籤。
- 卡號預設是右下角、深色底的小標籤(與頁位頁碼 `.pno` 同樣式),在底部預留列中;右上角留給卡圖的費用格與費用徽章(原本卡號在右上,蓋住費用格,改以徽章呈現費用後兩者重疊,專案負責人選擇移到右下)。放大檢視同樣是深色底標籤,在最底下的右側、14px,與左側的兩行魔力徽章同一列(專案負責人要求兩者一致);對戰盤面隱藏。魔書頁位放了卡時,P1 / P32 的頁碼只顯示「P1」「P32」(完整說明留在 `title` 與空頁)。
- 選項 `detail`:在費用格下方的卡圖右側加「詳情」按鈕,`stopPropagation` 後以 `zoom(num)` 開純展示檢視,不觸發放卡、選取。牌組編輯器的卡池與頁位使用;金手指視窗是 top layer 的 `<dialog>`,放大檢視蓋不上去,所以不用。

## 場上魔書翻閱

- 狀態 `BOOK_BROWSE`:玩家 → `{start, pos}`,`start` 為檢視中的對頁起點(0 = 只有第 1 頁、2…30、32 = 只有第 32 頁),`pos` 為開始翻閱時的目前頁;沒有項目即在目前頁。只存在前端,重新整理後回到目前頁。引擎的 `pos` 一律是偶數且 ≥ 2,所以目前對頁一定落在同一套對頁上。
- 只有快照含 `book` 的一方可翻(`bookBrowsable`)。翻閱中的頁以 `browsedPageEl` 畫:已離開的頁為卡背,其餘為不帶 ctx 的卡面(點擊開純展示檢視)。例外:進行中「從魔書挑頁」決策的目標頁(`PICK.book`)以 `{kind: "pick", zone: "book"}` 發光可選,空頁目標點卡背即選;P-015 的任意頁戰術以 `{kind: "any_page"}` 提供「攻擊」。
- 事件卡與非戰鬥戰術在快照 `condition_ok` 為 false 時停用「使用」(`ui.condition`)。
- 開始階段:行動欄依翻閱的對頁決定翻幾張(`(browseStart(tp) ?? pos) - pos` 的一半),只顯示對應的一個按鈕;不在 0..`maxFlip` 時改顯示 `ui.flip_browse_hint`。能翻的張數與翻閱的上限都以第 32 頁為界,剩餘頁數不足時右鍵會先停用。
- 自動回到目前頁:重繪時 `pos` 與記錄不同就刪除項目。為了讓翻頁動畫量測到翻動前的目前對頁,`applyPayload` 在交給 `Anim.apply` 前,若批次含該玩家的 `pages_flipped` / `pages_turned`,先刪除項目並以前一個快照重繪一次。
- 鍵盤(`BOOK_KEYS`):← → / Home / Esc;目標為 `selfPlayer()`,本機模式為 `awaitedPlayer()`。焦點在輸入元件、帶修飾鍵,或放大檢視、決策 / 資訊 / 魔書網格 / 規則 / 匯入匯出視窗、金手指開著時不處理。
- 左右鍵半疊在書皮兩緣、「回到目前頁」在上緣,不改變魔書區尺寸。

## 戰術的使用魔物與搭檔的裝備對象

- 可使用戰術的魔物以快照的 `users` 為準(`spellUsers`),前端不自行判斷戰術相容;可選 = 未被封鎖且 MP 足以支付該魔物使用時的費用。
- 只有一隻可選時直接送出;兩隻以上時(攻防、非戰鬥戰術相同)進入前端的場上選擇。一律送出 `slot_uid`。
- 行動記錄:`book_card_used` 依卡片類型描述,戰術為「使用戰術」,事件帶 `mamodo` 時寫出使用的魔物(`log.spell_used_by`);事件卡維持「使用事件卡」。
- **前端的場上選擇** `LOCAL_PICK`:沿用引擎決策的畫面(`pickState` 在沒有引擎決策時由它建出 `PICK`,`local: true`),候選在場上發光、點開放大檢視按「選擇(費用)」,不可選者點開時停用並顯示原因;選擇期間放大檢視只顯示「選擇」;行動欄顯示提示與「取消」;收到新快照即清除。用場上選擇而不用對話框,是因為同名魔物(兩隻 M-024)在對話框中無法區分。
- 搭檔卡:候選為快照的 `targets`(`pickPartnerTarget`),流程同上;前端不自行比對搭檔與魔物的對應(家族由引擎判定,M-047 視為ガッシュ・ベル)。魔物與搭檔的「放出」依快照 `play_block` 停用,原因沿用 `error.play.*`。
- 任意頁的卡(`any_page_spells`,P-015 / M-037 / P-037 / Ex-037 / PR-006):行動欄只放一個按鈕開魔書網格,可用的頁發光;只有一張時為「從魔書使用〈卡名〉」,多張時為「從魔書使用(N 張可用)」(`ui.any_page_cards`)。原本 M-037 每頁一個按鈕,P-037 可用的卡很多時會塞滿行動列,season3-effects-4 改為一個按鈕。網格中放大檢視 ctx 為 `{kind: "any_page"}`,按鈕沿用翻開的頁(`pageButtons`:攻擊、事件卡、非戰鬥戰術);按下時先關網格(網格層級在上)再選使用魔物。場上魔書翻閱翻到該頁時同樣發光可用,是「翻閱只看不操作」的唯一例外。

## 魔書網格排版

查閱魔書(含挑頁)、牌組構築器(`deck-builder`)與金手指的魔書網格共用同一套排版,都在 `style.css`:
- **固定欄寬的 CSS grid**:`grid-template-columns: repeat(auto-fill, <對頁寬>)`,每欄一組對頁,各列上下對齊;不用 flex 換行(P1 單頁較窄,第一列會多塞一組,之後每列錯開)。
  - 構築器與金手指的對頁寬由 `--slot-w`(頁位寬:構築器 92px、手機 76px,金手指 100px)計算:`2 × --slot-w + 12px`。改頁位寬只改這個變數。
  - 查閱魔書的對頁寬由 `--review-card-w`(96px,`.review-cell` 與其中的卡片、卡背都用此寬)計算:`2 × --review-card-w + 15px`。
- **P1 與 P32 各佔一欄**:P1 `justify-self: end`、P32 `justify-self: start`,如實體魔書的右頁與左頁;17 個欄位依序排下,P32 落在最後一列的第一欄。

- 窄螢幕(≤700px)的 `#log-panel` 是 `#layout` 直欄的最後一個 flex 子項。收合時只靠 CSS 顯示 `#log` 的最後 4 條(`.ev:not(:nth-last-child(-n+4))` 隱藏),每條單行省略,高度固定,不會隨記錄內容擠動盤面;頁籤 `#log-title` 只顯示標題,點擊展開 / 收合。

- 展開與新增記錄時把 `#log` 捲到最底,顯示最新的記錄。

## 新房間清空記錄

- 記錄以事件序號去重(`logSeq`,動畫為 `animSeq`):序號小於游標的事件視為已顯示。換房間時必須呼叫 `resetLog()` 清空 `#log` 並歸零兩個游標，否則新房間從 0 開始的事件全被略過。

## 效果被限制時的記錄

- 效果依效果文「不發生」或「量變成 0」時,引擎發出說明原因的專用事件,行動記錄寫出原因,不沿用一般的「效果發動」:P-010 等「合計 1 次」限制為 `page_turn_restricted`,E-018 在上一個回合自己已用過減少對手 MP 的效果時為 `opp_mp_reduction_restricted`。
- 理由:E-018 原本只記「效果發動」,對手 MP 不變、畫面上只看得到使用者自付的「MP -2」,有玩家誤認為對手 MP 沒被扣的 bug(2026-10 回報)。這個限制仍算「使用了減少對手 MP 的效果」,照樣記入下一回合的判定。

## 事件動畫管線(`frontend/anim.js`)

```text
Anim.apply(events, prevState, renderFn, actor)   每批事件排隊,前一批播完才處理下一批
  量測(重繪前的位置)
  時間軸:依事件順序
    卡片聚焦 / 文字聚焦            ← 對手行動聚焦展示
    擲硬幣 / 魔力對決對峙 / 保護移動 / 傷害能量(阻塞式)← 動畫開啟時
  重繪
  疊加式動畫(翻頁、飛卡、MP、負傷、棄牌)← 動畫開啟時
```

- **棄牌**:`mamodo_discarded` 與 `card_discarded`(以事件的 `slot` / `page` 量起點,看不到的魔書頁用魔書)的卡,自原位置縮小飛向該玩家的「棄牌區」(`.discard-btn`),600ms。
- **CSS 自訂屬性**:演出元素的轉場時間用 `--fly-ms` 等自訂屬性時,一律以 `style.setProperty` 設定;`Object.assign(el.style, {"--x": …})` 不會生效,轉場會變成瞬移。
- 同一批事件從指令回應與 WebSocket 推送各到一次,以 `seq` 去重,先到的播放;兩條路徑都帶同一個 `actor`(見 `battle-api/design.md`)。
- 盤面在整批的聚焦與阻塞式演出播完後才重繪,呈現「先因後果」。
- **保底上限**:阻塞演出以 `blockingLimit(ev)` 決定逾時——擲硬幣 1.5 秒;對峙為演出長度 + 1 秒;傷害能量為能量 + 兩段保護者動作 + 1 秒;保護移動為兩段保護者動作 + 1 秒。不能用固定值:演出超過上限時盤面會提早重繪,與演出疊在一起。
- **快 / 落後**:對峙、能量、保護的長度都依演出設定的聚焦速度「快」或排隊落後(`pending >= 2`)縮短。
- **魔力對決對峙**(`showdown`):全畫面暗背景(點擊跳過)、中央上下兩組「魔物+戰術」(以 `cardEl` 繪製),依 `topPlayerIndex()` 從各自那一側滑入,中間 VS。
  - 時段依總長 T(標準 2.5 秒、快 1.2 秒)比例:滑入 20% → 合計滾動 30% → 勝方衝撞 / 敗方震動 12% → 結果大字 38%。
  - 卡來自 `showdown` 事件的 `attack_mamodo` / `attack_spell` / `defense_mamodo` / `defense_spell`,不依賴前一個快照。
  - 不防禦時防禦方只放「不防禦」虛線框(沒有特定的魔物);魔物效果攻擊的戰術位置放明細 `fixed` 項的來源卡。
  - 結果文字:攻擊成功 / 防禦成功(同值加小字「同值・防禦方勝」)/ 攻擊無效;被無效的一方蓋「無效」戳記。
- **傷害能量**:`damage_dealt`、`mamodo_injured`、因傷害的 `mamodo_discarded` 各插一段阻塞演出,發光球自畫面中央飛向該方 `.book-cover` 或該魔物槽,命中爆光。起點固定在中央,因為傷害來源不一定在場上。傷害音效隨這一格,文字聚焦另起一格。戰鬥傷害通常要先等保護決策,能量多半在決策後那一批。
- **保護**(`protected`,事件帶 `target` / `target_slot` / `target_player`):保護者在 `player` 的場上,對象在 `target_player` 的場上(P-027 以對手的魔物保護時兩者不同,保護者從對手場上移到受方魔書前,再回到對手的原位)。保護決策的選項依各自的 `player` 在對應的場上發光,不需另外處理。
  - 複製保護者的盤面元素,放進只負責移動的 `.fx-guard-wrap`(以中心定位;卡保留自己的 class,負傷者維持橫置),移到對象正前方並朝中央偏移;原元素暫時隱藏。
  - 接著打在它身上的能量改打在複製品。命中後:負傷則原地轉成橫置再回原位;送墓則原地淡出。
  - 回到原位後複製品留著,重繪後才移除(`clearGuardLeftovers`),避免露出重繪前的舊樣子。沒有能量時在重繪前回原位。
  - 複製品不在 `#board` 底下,盤面卡片的尺寸與隱藏規則也套到 `.fx-guard`。

## 檢視對手頁面對話框(E-014 / M-018)

- `applyPayload` 在 `Anim.apply` 回傳的 promise 完成後(聚焦、阻塞演出、重繪都結束),從這批新事件挑出含 `cards` 的 `pages_peeked`,以 `showPeek` 經資訊對話框(`showInfo("peek", …)`)顯示,按鈕文字為「確定」。
- 只對即時批次(`actor` 不為 null):開局、金手指同步、重連的 welcome 都沒有行動者;`fetchMissedEvents` 補回的事件只進記錄,不經動畫管線,因此重新整理後不會重跳。
- 是否跳出只看事件是否帶 `cards`:伺服器已依視角過濾(本機全視角原樣回傳),前端不比對 viewer。被檢視方與觀戰者收到的事件沒有 `cards`,只留記錄。
- 檢視不是決策,對局不等待對話框;卡片可點開放大檢視(`#zoom-overlay` 疊在 `#info-overlay` 之上)。
- 同一列的卡等高(`.peek-item .card { flex: 1 }`):效果文長短不同時,魔力徽章與卡號仍對齊在底部(使用者指出,mj12-cards 期間修正)。

## 對手行動聚焦展示

- **分類表集中在 `anim.js`**:
  - `CARD_EVENTS`:卡片聚焦的事件,以及要展示的卡號。
  - `TEXT_EVENTS`:文字聚焦的事件。
  - 未列入的事件不聚焦,只進行動記錄。新增事件時在這裡補上。
- **時間軸**:
  - `turn_started` 一律插入一格回合開始橫幅(不論 `actor`,只看聚焦設定與追趕),自成一格;開局的第 1 回合也會顯示。
  - 卡片事件開新的一格;之後的文字事件併入為結果行。
  - 擲硬幣 / 魔力對決會結束目前這格,之後的文字另起一格。
  - 說明文字沿用行動記錄的 `logLine(ev)`,卡圖、卡名、效果文取自 `CARDS` / `ZH`。
- **要不要聚焦**:
  - `actor` 不是自己:卡片與文字事件都聚焦。
  - `actor` 是自己:只取不利結果(`unfavorable`)。
  - `actor` 為 null(金手指、開局):不聚焦。
  - 本機模式與觀戰視為沒有自己(`selfPlayer()` 為 null)。
  - MP 增減只在 `reason` 為卡號(效果造成)時列出,支付費用不列。
- **效果來源卡格**(effect-visibility):`effectSource(ev)` 依 `SOURCE_FIELD` 從事件取來源卡號(`source` / `card` / 卡號格式的 `reason`)。來源卡與目前卡片格的卡不同時另起卡片格(標題「效果生效」,`effect_blocked` 為「效果被擋下」),不經 `actor` 的不利過濾;相同時併入。常駐效果、待命 / ステイ與戰鬥後附加效果的事件本來就帶來源,所以不需要新的「效果發動」事件;P-013 因自己的行動觸發時原本只是一行併在別格的文字,玩家沒發現。`Anim.timeline` 匯出供測試直接驗證分格。
- **停留時間**:標準 2000ms(只有 pass 的格 1000ms),快為一半。
  - 排隊 ≥ 2 批時自動用快。
  - ≥ 5 批時跳過該批聚焦(最後一批仍播)。
  - 分頁在背景時不聚焦。
- **遮罩**:`#spotlight` 蓋住盤面,點擊即結束目前這格,也避免按到尚未重繪的過時按鈕。`data-ms` 記錄這格的停留時間(測試用)。
- `Anim.idle()`:目前排隊的播放全部結束時完成,測試用來等開局橫幅播完。

## 演出設定

- 存於 localStorage:`gash-spotlight`(normal / fast / off,缺省 normal)、`gash-motion`(on / off / system,缺省 system)。
- `motionOff()`:設定優先,system 時依 `prefers-reduced-motion`。
- CSS 動畫只看 `html.motion-off`(由 `applyMotionClass()` 在啟動、設定變更、系統偏好變更時切換),不直接用 media query,遊戲內的「開」才能蓋過系統偏好。
- 聚焦不屬於動畫:動畫關時仍顯示,只因 `motion-off` 而沒有淡入。
- 瀏覽器測試的 fixture 預設 `gash-spotlight=off`(本機模式雙方都會聚焦,遮罩會擋住操作);聚焦的測試另外開啟。
- `gash-sound`(on / off,缺省 on):音效開關,見「音效」。

## 音效(`frontend/sound.js`)

- **Web Audio 即時合成**:每個音效是幾個短音(波形、起訖頻率、音量包絡)與帶通噪音的組合,播放時才建立節點;不使用音檔,沒有授權與下載量的負擔。主增益固定約 0.25,不提供音量調整,要靜音用設定關掉。
- **啟用**:瀏覽器要求使用者互動後才能出聲,第一次 `pointerdown` / `keydown` 時建立並 `resume()` `AudioContext`;之前(例如重新整理後直接回到對局)的音效靜默略過。
- **對照表**:`CUES` 把事件對到音效種類,`PRIORITY` 由重到輕排列,`pick(events, me)` 在一組事件中取最重要的一個。與 `anim.js` 的聚焦分類各自獨立:聚焦只展示對手行動與對自己不利的結果,音效則自己的行動也響。`mp_changed`、`turn_started`、待命與修正等不響(太頻繁,回合開始由「輪到你」涵蓋)。
- **時間點**(在 `Anim.run` 內,跟著畫面):
  - 時間軸每一格記錄它包含的事件(`step.events`),該格出現時播放;擲硬幣與魔力對決在阻塞演出開始時播放。
  - 沒有被任何一格或演出用掉的事件,在重繪時合為一個時間點播放。
  - `actor` 為 null 的批次(開局、金手指、重連的全量快照)不播放。
  - 音效不看聚焦與動畫設定,只看 `pref("sound")`。
- **輪到你**:重繪後比較 `awaitedPlayer(prevState)` 與 `awaitedPlayer(S)`,從別人變成自己時播放 `your_turn`;同一批已有行動音效時延後 350ms。只在有自己的視角(`selfPlayer()` 不為 null)播放,本機模式與觀戰不播。
- **測試**:`Sfx.played` 記錄每次決定播放的音效名稱(音效開啟時才記,不論瀏覽器是否允許出聲),瀏覽器測試以它驗證,不量測實際聲音。

## 停用按鈕的原因(disabled-reasons)

- 放大檢視的停用按鈕一律附原因(`.zoom-reason`,在按鈕旁;觸控沒有 hover)。新手回饋:賈修的效果在非戰鬥時灰掉卻沒有說明。
- 啟動效果:`abilityUsableNow(p, ab, used, block)` 先看快照的 `ability_block`(`ABILITY_BLOCK_KEYS` 對應文字,MP 帶數值),再看時機(`waitReason`:等待決策 → 開始階段 → 戰鬥中未到效果步驟 → 不是自己的行動),最後退回規格判斷(沒有 `ability_block` 時)。卡的固定限制(只能戰鬥中等)優先於時機,玩家先知道卡的用法。
- MP 不足統一用 `ui.spell.mp`(「MP 不足(目前 m,需要 n)」,`mpReason`),效果、魔物效果攻擊 / 防禦、事件卡與戰術一致。
- 翻開頁:`pageButtons` 沒有任何按鈕、不是防禦步驟的防方時,以 `idlePageButton` 加主要動作的停用按鈕(放出 / 使用 / 攻擊 / 防禦,原因見 change design D4)。原本「不可行動時無按鈕」,點開也看不出為什麼不能用;使用者選擇顯示停用按鈕(Confirmed)。發光只看啟用的按鈕,盤面不變。

## 進入戰鬥確認的用語(battle-in-options)

- 用語依規則原文(atwiki 規則頁「④バトル・インの確認」):步驟是「バトル・インの確認」(回合玩家問「バトル・インしていいですか?」),「バトル・イン」是回合玩家使用攻擊效果進入戰鬥;非回合玩家插入行動時確認無效。原本的「戰鬥開始確認 / バトル開始の確認 / BATTLE start check」與「迎戰 / 受けて立つ / Accept」都不是規則用語(「迎戰」是使用者早期翻譯バトル・イン的用詞)。
- 三個用語分開(使用者採用):步驟「進入戰鬥確認 / バトル・インの確認 / Battle-in check」;非回合玩家的按鈕「同意進入戰鬥 / バトル・インを認める / Allow battle-in」(他是同意對方進入戰鬥,不是自己進入戰鬥);進入戰鬥「進入戰鬥 / バトル・イン / Battle in」(行動記錄「進入戰鬥!…」)。
- 新手回饋「迎戰」之後才選防禦而混淆:附註改為「接著宣告防禦;或插入行動使確認無效」(使用者要求同意進入戰鬥的選項也提醒可以插入行動),對決舞台的提示說明可以同意進入戰鬥、下一步宣告防禦,或用其他行動讓確認無效。
- 不提供「進入戰鬥,不防禦」:進入戰鬥後到防禦步驟之間,引擎還要處理攻擊的宣告時效果(擲硬幣的「不能防禦」、加魔力、攻方的選擇、防方的ジャマー),不能完全合併成一步;曾實作預先決定不防禦,使用者決定不加只合併一半的選項。

## 自動 pass(auto-pass)

- 使用者回饋:非回合玩家能用的行動不多,卻在回合玩家每個行動之後、進入戰鬥確認、防禦步驟、效果步驟輪流時都被詢問,只能一直按 pass。新手回饋也希望一眼看出有沒有能做的事。
- 快照 `idle.auto` 存在(沒有其他可用行動)時,`scheduleAutoPass` 以 `event_count` 與指令為鍵建立倒數(同鍵不重建),等 `Anim.idle()` 後開始;100ms 一個 tick 累計 3 秒(`AUTO_PASS_MS`;使用者試過後由 2 秒改為 3 秒),`ZOOM` 或 `CARD_MENU` 開著時歸零(查看卡片時暫停、關閉後重新倒數 3 秒,使用者決定)。送出前再確認鍵相同、沒有送出中的指令(`SENDING`)、開關仍開;玩家自己回應後狀態前進、鍵不同,倒數自然失效,不會重複送出。
- 開關在行動欄(回應按鈕旁),對局中的玩家(含本機模式)一直顯示,觀戰者不顯示;`localStorage` 的 `gash-auto-pass`,所有模式預設開啟(使用者決定,知悉資訊外洩)。窄螢幕也顯示完整的句子,縮小為 11px、可換行(最初只顯示「自動」,使用者回饋看不出意思;13px 的完整句子會超出畫面)。倒數中顯示「即將自動 pass…」。
- `idle.has_actions` 時行動欄提示「有可以使用的效果或行動」,不列出內容(使用者決定)。
- 參考遊戲王 Master Duel 的「發動確認」(Auto / ON / OFF):有沒有能發動的卡由系統判斷,停頓同樣會透露資訊,交給玩家設定。這裡只做開關,關閉就等於每個時機都詢問。
- 瀏覽器測試預設關閉(`conftest` 的 `AUTO_PASS_OFF_SCRIPT`,只在尚未設定時寫入),否則既有測試的回應會被自動送出;自動 pass 的測試自行開啟。

## 頂欄的換行(topbar-wrap)

- 使用者回報(日文、寬度約 800px):回合、階段、等待狀態被壓成一字一行的直排,「CARD BATTLE」拆成兩行,按鈕被推出畫面。原因是 `#topbar` 只有 ≤700px 才換行,按鈕 `flex-shrink: 0` 不讓寬度,可縮小的文字欄位被壓到 min-content;按鈕陸續增加(演出、語言、作用中效果、金手指、棄權)後,約 700–1300px 已經塞不下。

- 中等寬度頂欄變兩行(第一行標題與狀態,第二行按鈕);若覺得太佔空間,再考慮把次要按鈕收進選單(使用者選了改動最小的做法)。
- 測試(`tests/test_topbar_wrap_ui.py`)以 Range 的行框數判定單行:垂直範圍重疊的行框算同一行(標題字大小不同、同一基線)。

## 後果預告(consequence-preview)

- 新手回饋(評論 8–10):資訊透明度進步了,下一步是「按下去會發生什麼」。使用者決定只提示會離場或可能敗北的後果(Confirmed)。
- **保護**:`pickWarning(ctx)` 以 `pickValue` 找到決策選項,選項有 `leaves` 時回傳「⚠ 保護後這隻魔物會被棄掉({原因})」;原因 `injured` 為「已負傷」,卡號為「{卡名} {卡號}」。`pickButtons` 把它放在「選擇」按鈕的 `warning`,卡片行動選單(`.card-menu-warning`)與放大檢視(`.zoom-warning`)畫在按鈕上方,詳情面板(`.detail-warning`)畫在卡面下方。警告不取代「選擇」:卡片行動選單本來就要再按一次「選擇」,已經是確認點,不另加確認步驟(Confirmed)。
- **翻頁**:開始階段的翻頁按鈕依 `flip_end_loses[張數]` 加附註「⚠ 翻頁後,本回合結束時將因無頁可翻而落敗」(`addBtn` 的兩行附註,`.flip-loses` 以危險色顯示)。
- 不保護會使魔書耗盡的提示原本就有(「保護決策顯示傷害」),不重複。

## 指令送出中(command-busy)

- `send()` 期間 `SENDING` > 0,`<body>` 加 `sending`:CSS 對行動欄、決策對話框、放大檢視的按鈕與 `.pickable` 設 `pointer-events: none`。以 CSS 一處涵蓋,不逐一改 `disabled`(入口多、每次重繪重建,漏改就失效);鍵盤等 CSS 擋不到的途徑由 `send()` 開頭的檢查擋下。新手回饋:回應前畫面不變,以為沒按到又按一次,第二次被拒並跳錯誤。
- 「處理中…」(`.sending-note`,`ui.sending`)在送出 200 毫秒後才放進行動欄,避免快速回應時閃現;行動欄重建時若已過延遲則保留。回應或錯誤時(含連線失敗)一律解除。
- 只包對局指令;金手指有自己的 `CHEAT.busy`,建房、牌桌選擇不變。

## 終局(endgame-clarity)

- **魔書進度**:`pos > book_size` 時區塊標題的魔書進度整段換成「魔書耗盡」(`ui.book_exhausted`),不接在「魔書」之後,避免「魔書 魔書耗盡」。
- **勝負原因**:`endReasonText(winner, reason)` 以 `ui.reason.*` 的 `{player}` 帶入敗方(`1 - winner`)的 `pname`;頂欄、行動記錄、結算面板共用。原本「對手魔書無法再翻頁」是勝方視角,敗方與觀戰者看到時讀不通(新手回饋)。
- **最後一對頁警示**:`renderActionBar` 在 `iControl(turn_player)` 且快照 `end_flip_loses` 時放 `.end-flip-warning`(佔滿一行,紅底);觀戰者與對手不顯示。Pass 的附註在「非戰鬥、輪到回合玩家、`consecutive_passes === 1`」時換成 `ui.pass_note.end_flip_loses`(此時 pass 就結束戰鬥階段)。對手 pass 結束回合使自己落敗的情況,由警示本身說明。
- **結算面板**:用資訊對話框(`showInfo`,kind `result`),狀態更新時由 `renderTopbar` 重繪(牌桌對方的選擇會變)。
  - 時機:`applyPayload` 在演出與飛卡特效結束後呼叫 `maybeShowResult`;`RESULT_SEEN` 記住已自動跳出的房號,同一局只跳一次,接回已結束的房間也會跳出。只在對局畫面顯示:`show()` 切到其他畫面時關閉,`maybeShowResult` 在對局畫面隱藏時不跳出(牌桌對方離開、自己成為開桌者進入等待畫面時,舊的終局快照還在)。
  - 關閉後頂欄勝負文字旁出現 `.result-reopen`「結算」重新開啟。
  - 內容只用快照:勝利 / 落敗(玩家視角)或「{玩家} 獲勝」(本機、觀戰)、原因、回合數、雙方剩餘頁數(`book_size - pos`,下限 0)與場上魔物數、NPC 牌組。「關鍵戰鬥」不做:要挑出關鍵的一場需另訂標準,行動記錄已可點開每場魔力勝負(Confirmed,使用者同意)。
  - 按鈕:`LAST_SETUP` 記住這次載入中最後一次 `startNpcWith` / `startLocalWith` 的開局 payload(只在記憶體),模式相同且是玩家(NPC 視角 0、本機 all)時提供「再戰」/「再來一場」,以同一個 payload 開新房(NPC 隨機牌組送的是候選清單,伺服器重新抽選);沒有就只有「返回首頁」(`leaveRoom`)。牌桌改放既有的 `tableChoiceEl`,動作列不再顯示。朋友對戰的再戰需要雙方同意與新房流程,不在範圍內(Confirmed)。

## 分頁的對局身分(fix-session-identity)

- 身分(房號、座位、token)寫入 `sessionStorage["gash-session"]`(分頁各自一份、重新整理後仍在)與 `localStorage["gash-room-<房號>"]`(瀏覽器記得的房間);`loadSession(code)` 先用分頁身分(同一房時),否則用 `localStorage`。`leaveRoom` 清除分頁身分。
- 原因:v1.3.0 只存 `localStorage`,同一個瀏覽器另一個分頁加入同一房會蓋掉,重新整理後身分變成對方(使用者回報)。限制:同一個瀏覽器兩方都在時,首頁返回 / 新分頁接回的是最後寫入的一方。
- 測試:多分頁時背景分頁的 requestAnimationFrame 暫停,`wait_for_function` 用 `polling=100`。

## 接回對局的連線失敗與心跳(fix-reconnect)

- `roomGone(err)`:只有 `room.not_found` / `room.bad_token` 代表房間不在或身分無效。`api()` 收到非 JSON(代理錯誤頁)拋出不帶錯誤碼的錯誤;`fetch` 失敗原樣拋出,兩者都不刪身分。原本任何錯誤都刪身分回首頁:網路不穩或 Cloudflare 502 / 524 時,玩家回不了仍在進行的對局,牌桌也一直顯示他的名字(使用者回報)。
- `resumeRoom` 非 `roomGone` 的錯誤:顯示 `#reconnect-overlay` 並依 `RECONNECT_DELAYS_MS`(2、4、8、15、30 秒,之後 30 秒)重試;「回首頁」停止重試、保留身分。`refreshResumeRooms` 同樣只在 `roomGone` 時移除記錄。
- WebSocket 心跳:`onopen` 起每 25 秒送 `"ping"`,`onclose` 停止;伺服器接收迴圈本來就忽略內容。部署經 Cloudflare Tunnel,閒置的 WebSocket 約 100 秒會被切斷。
- 測試可用 `window.__reconnectDelays`、`window.__wsHeartbeatMs` 縮短時間。

## 棄權與對手沒有回應(forfeit-and-absence)

- 頂欄「棄權」(`#forfeit`,離開房間旁):玩家視角、對局中、非自由調查時間才顯示;以決策對話框確認(可取消),經 `roomAction("forfeit")` 送出。
- `R.unresponsive[對手]` 時行動欄最上方 `.absence-prompt`:「結束對局(判對手落敗)」「繼續等」,與輪到誰無關都顯示。
- WebSocket 以 4404(房間已關閉)或 4401(房間不存在 / 身分無效)關閉時不重連,移除記錄、`leaveRoom`、提示;4401 原本會無限重連。
- 勝負原因 `ui.reason.forfeit` / `ui.reason.absent` 點名敗方(`endReasonText`)。

## 規則頁

- **內容**:`frontend/i18n/rules.<lang>.json`,依語言分檔,結構為 `sections[{id, title, blocks}]`。block 有五種:段落 `p`、條列 `list`、範例卡 `figure`、圖示對照 `icons`、賽季表 `seasons`。渲染一律用 DOM,不拼 HTML。
- **與規則的關係**:規則頁是依本遊戲實作寫給玩家讀的說明,權威仍是 `game-engine` 規格。
  - 規格或卡池改動時(新增機制、改變流程),要同步更新規則頁。
  - 測試檢查每種語言的內容都不出現卡池外的機制(石版、W / VS / S / H 魔物、MJ12、巴爾肯、飛行,依語言的稱呼,見 `tests/test_i18n_languages.py` 的 `ABSENT`)。卡池擴充到這些機制時,要從禁止清單移除並補上說明。
  - 繁中、英文、日文三種撰寫的內容檔段落 id、順序與 block 種類一致;改一種語言的段落結構時,其他語言要一起改。簡中 `rules.zh-CN.json` 由 `tools/build_zh_cn.py` 自繁中產生,改了繁中要重跑。
- **連結**:`RULE_LINKS`(`app.js`)把時機指示的步驟與行動欄提示對應到段落 id;測試檢查每一步、每一條提示都有連結,且指到存在的段落。`openRules(sectionId)` 開啟覆蓋層並捲動到段落,目錄依內容區頂端的段落標示。
- **卡面圖示**:
  - 卡圖是另外安裝的外部資源,repo 不放任何由卡圖衍生的圖檔。
  - `ART_BOXES` 記錄範例卡(M-001、S-001、S-026、M-026)上各圖示的像素框(以 465×679 卡圖為準),範例卡的框線標記與圖示對照的 CSS 裁切共用它;換卡圖版本時只需調整這裡。
  - 每張範例卡先以 `Image` 探測,載入失敗時改用文字標籤並提示卡圖未安裝。
- **賽季表**(`renderRuleSeasons`):
  - 由 `data/seasons.json` 與卡片資料產生,不寫在內容檔:補卡或調整範圍時只改定義檔,四種語言一起更新。內容檔只放說明文字與表頭、註記的標籤(`seasons` 物件,比照 `figure`)。
  - 範圍從 001 開始累積到該賽季的上限;該賽季沒有的前綴顯示「—」。前綴欄順序固定為 M、S、P、E、PR、Ex,定義檔出現新前綴時接在後面。
  - 「新增產品」:一個產品的賽季是收錄卡中最晚的卡的賽季(`cardSeason`),順序依 `pool-filters.json`。虛擬產品 Ex 卡與特典カード跨賽季,不列(範圍由 Ex、PR 欄表示);再收錄產品本來就不在 `pool-filters.json`。不直接用 `products` 的排序號當賽季,因為那是呈現用的分組。
  - 只列 `selectable` 的賽季(season4-card-data,2026-11-07):第 4 賽季的定義先加入、效果分批實作期間還不能選,表上若出現這一列,會和「目前不能選」的註明矛盾;開放時把 4 加入 `selectable` 就會出現。不採用「列出但標示尚未開放」:這一列的範圍與產品對還不能用的玩家沒有幫助。
  - `special` 的卡都在表下註明,同一賽季的卡併成一句(以 `ui.sep.list` 分隔):屬於可選賽季的(Ex-100、Ex-101 → 3)用 `note_selectable` 只寫所屬賽季,因為它們的卡號不在該賽季的 Ex 範圍內,表格本身看不出來;屬於不可選賽季的(Ex-000、Ex-099 → 4)用 `note` 另註目前不能選。英文的 `note` 因為一句列多張卡,改成「Season {n} cards (not selectable yet): {card}.」。
  - 入口:四個設定頁的賽季選單旁的「?」與構築器的賽季標示,都 `openRules("seasons")`。
- **用語**:卡片圖示一律用卡面上的稱呼(「攻(A)」「防(D)」「BATTLE」「NO BATTLE」「CUT-IN」;中文說明依序為非戰鬥、戰鬥、干擾,ジャマー的中文用「干擾」(使用者指定,2026-11-07),效果文的「ジャマー効果」譯為「干擾效果」),行動欄提示也一樣。「攻(A)」「防(D)」在攻防用的戰術與事件卡、非戰鬥戰術上意思不同,規則頁的「卡面圖示」一節說明。

## 意見回報

- **設定**:`app.js` 開頭的 `FEEDBACK`(`formUrl`、`contextEntry`、`issuesUrl`)。表單網址公開無妨,所以放前端常數、不放伺服器設定;`formUrl` 空白時只顯示 GitHub 管道。
- **環境資訊**:`feedbackContext()` 產生給開發者看的一行文字,不翻譯,格式 `lang=…; mode=…; room=…; turn=…; phase=…; ua=…`(沒有對局時只有 `lang`、`ua`;`ua` 放最後,因為它本身含「; 」)。
  - 帶房號:有房號才能對照伺服器記錄,而且加入連結本身就含房號。
  - 不帶 token、暱稱、牌組內容。
  - 以 Google 表單預填網址帶入(`?usp=pp_url&<contextEntry>=…`);對話框另外顯示同一份文字並可複製,給用 GitHub 的人貼上。
- **對話框**:沿用資訊對話框(`showInfo("feedback", …)`),純展示,不影響對局;外部連結開新分頁。
- **GitHub Issue Forms**:`.github/ISSUE_TEMPLATE/` 的問題回報、卡片效果不符、建議三種範本都有 `environment` 欄位;`config.yml` 以 `contact_links` 連到表單。
- **表單**:不要用檔案上傳題(需要 Google 登入)。換表單或改欄位時,要同步 `FEEDBACK` 與 `config.yml`。
- 遊戲內直接送出、附對局記錄(方案 B)尚未實作,見根目錄的 `todo.md`。

## 語言

- **語言清單**:`frontend/i18n/languages.json`(`[{code, name}]`,順序即選單順序,`name` 是各語言自己的稱呼)。每種語言有三個檔:介面字典 `i18n/<lang>.json`、規則頁 `i18n/rules.<lang>.json`、卡片文字 `data/cards.<lang>.json`。新增語言只要補這三個檔並登記到清單。
- **偵測**:localStorage `gash-lang` 有值且在清單中就用它;否則依 `navigator.languages` 逐一比對,取第一個能對應者;都不符合為 `en`。
  - 簡中別名(`zh-cn`、`zh-sg`、`zh-my`、以 `zh-hans` 開頭)→ `zh-CN`(`isSimplifiedChinese()`)。
  - 其他依主語言(`-` 前)比對清單,所以 `zh-HK`、`zh-Hant-*` 與只有 `zh` 都落在排在前面的 `zh-TW`(使用者決定預設繁中)。
  - 不預設中文:看不懂中文的人第一眼就要能用。
- **載入**:`loadLanguage()` 在 `boot()` 中與卡片數值、預組、meta 平行載入;字典或卡片文字載入失敗時整組退回 `zh-TW`,規則頁另外退回。`<html lang>` 設為目前語言,CSS 以 `body:lang(ja), [lang="ja"]` 換日文字型(避免漢字以中文字形顯示);中、英模式下的日文原名小字也標 `lang="ja"`。
- **切換**:頂欄 `#lang-toggle`(「🌐 + 目前語言稱呼」,所有畫面都在)開啟資訊對話框列出語言;選擇後寫入 `gash-lang` 並 `location.reload()`。
  - 重新載入走既有的接回路徑:對局(`?room=`)、觀戰、構築器、加入連結都回到原處,行動記錄由伺服器補回全部事件後以新語言重建;設定頁不在網址中,會回到首頁。
  - 不就地重繪:每個已渲染的元件(行動記錄、對話框、聚焦展示、構築器)都要能重建才行,容易漏;重新載入一次就全部正確,接回路徑也有測試。
  - 語言只存在瀏覽器,伺服器不知道玩家的語言;同房玩家與觀戰者各自使用自己的語言。
- **卡片文字**:全域 `TEXT` 是目前語言的卡片文字。`cname()` 對魔物以 `ui.card_with_attr` 加上效果名區分同名魔物(中、日「名稱《效果名》」,英「Name (Effect)」);放大檢視用 `cname()`,盤面小卡只顯示卡名(版面有限)。卡名下方的日文原名小字只在非日文時顯示。
- **錯誤碼**:`api()` 失敗時,字典有 `error.<code>` 就用它,否則用伺服器的 `message`。字典裡的錯誤訊息是每個錯誤碼一條通用訊息,不帶伺服器訊息中的動態參數(卡號、頁數);錯誤 `detail` 的欄位會當成字串參數傳入,目前只有 `error.deck.season` 用到 `{season}`。`tests/test_i18n_languages.py` 掃描伺服器程式中的錯誤碼(`IllegalCommand`、`DeckError`、`RoomError`、`_npc_http_error`、`"code": …`),要求四種語言的字典都有;新增錯誤碼時補繁中、英文、日文三種撰寫的訊息,再執行 `tools/build_zh_cn.py` 產生簡中。
- **日文用語**:「バトルしていないとき」「バトル以外」統一為「非バトル」(介面字典與規則頁;卡片效果文不動),與「バトル中」對稱,也放得進回合轉盤的中心(使用者指定)。
- **預組名稱**:`GET /api/decks` 回傳 `name_key` 時,前端以目前字典解析(`presetName()`),字典沒有才用伺服器的 `name`。
- **標點與分隔**:清單分隔、卡片資訊分隔、頂欄分隔、括號與「玩家:標題」也走字典(`ui.sep.*`、`ui.paren`、`ui.choice_title`、`ui.you_suffix`),英文用半形與空白。
- **用語**:中文一律稱「魔書」「戰術」「戰術卡」(專案負責人指定),畫面文字、卡片中譯、README、規格與設計文件、程式註解與伺服器訊息都相同;歸檔的 change 是歷史紀錄,保留當時的「魔本」「術」。「術語」「技術」等一般詞不受影響。日文採規則書用語(スタートフェイズ、ターンプレイヤー、魔書、戰術、パートナー、捨て札、負傷状態、かばう、スタンバイ、ステイ、ジャマー、表 / 裏);英文對齊卡圖與 TTS 卡表(START PHASE、turn player、Spell Book、SPELL、MAMODO、Partner、Event、Power、Injured、PROTECT、STANDBY、STAY、Discard Pile、heads / tails)。卡面圖示各語言都用卡面上的稱呼:「攻(A)」「防(D)」(英文 A (Attack) / D (Defense))、BATTLE、NO BATTLE、CUT-IN。
- **魔物效果攻擊 / 防禦**:不用戰術卡、以魔物的效果攻擊或防禦(M-027、M-046、M-039 等「合計魔力Xで攻撃 / 防御する」)一律稱「魔物效果攻擊」「魔物效果防禦」(英文 MAMODO-effect attack / defense,日文「魔物の効果で攻撃 / 防御」),不用「無戰術攻擊」「直接攻擊」等說法(專案負責人決定;它是「魔物の効果」,受相關限制、每回合 1 次)。
  - 英文標籤較長,手機版時機指示用較短的英文標籤(No BATTLE、BATTLE:、Check)維持單行;頂欄按鈕不換行。
- **簡體中文**:三個檔都由 `tools/build_zh_cn.py` 自繁中產生,不手動編輯(轉換規則見 `card-data/design.md`)。選單上繁中稱「繁體中文」、簡中稱「简体中文」:有兩種中文時必須區分。
- **翻譯狀態**:日文與英文是初版翻譯,尚未經母語者校對;簡體中文是自動轉換,尚未校對。測試只保證條目、參數、段落與涵蓋一致,不檢查品質。

## 自由調查時間的輔助提示

- **金手指的目前頁**:面板上方 `#cheat-current` 摘要雙方目前翻開的頁;網格以 `cheatMark` 標記目前翻開的兩頁(`cheat-open`,框線與「目前」)與已離開魔書的頁(`cheat-gone`)。資料取自快照的 `pos` / `consumed_pages`,不取自草稿:提示代表目前的對局狀態,草稿裡換了卡也不會變。`debug-state` 不必擴充。
- **保護決策的傷害**:`choicePromptEl` 讀 `pending.info.damage`,以 `protectDamageText` 在標題下加一行(魔書傷害值,會耗盡時加註;魔物將負傷或將進入棄牌區)。資訊來自公開脈絡,對手與觀戰者也看得到。
- **先攻**:本機模式固定玩家 1 先攻,記錄 `first_player_set` 寫「自由調查時間:玩家 1 先攻」。
