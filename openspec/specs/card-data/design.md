# card-data — 設計

目前整理了卡片文字檔(顯示用的多語文字)、第三彈資料(含收錄產品與預組)與卡圖(來源與格式);抓取、`cards.json` 轉換以 `tools/` 程式、README「資料管線」與測試為準。

## 卡片文字檔

- **分層**:遊戲邏輯只讀 `data/cards.json`(日文權威)。顯示用文字依語言分檔:`data/cards.zh-TW.json`、`data/cards.zh-CN.json`、`data/cards.en.json`、`data/cards.ja.json`,結構相同(卡號 → `{name, name_ja, attr, effect}`),改動只影響顯示。
- **日文 `cards.ja.json`**:由 `tools/build_card_texts.py` 自 `data/cards_ja.csv` 產生,不手動編輯;測試以同一函式(`build_ja`)重新產生並比對。
  - 魔物與搭檔的效果名不在 `attr_ja`,而是 `effect_ja` 開頭《》括起的文字,工具取第一個《》作為 `attr`。`effect` 是原文全文,所以日文效果文本身也帶著《效果名》。
- **英文 `cards.en.json`**:
  - `name` / `attr` 由同一工具自 TTS 卡表(`openspec/specs/card-data/Zatch Bell CCG List for TTS.xlsx`,「The Table」工作表)寫入,「-」為 null;日文 `attr` 為空時英文也為空。卡表屬性欄缺漏(「-」)而日文資料有元素的戰術(S-091 / S-092),由 `element_names` 以卡表中同元素其他戰術的英文補上;卡表對同一元素出現兩種英文時工具報錯,不自行選擇,也不在工具裡寫固定對照表(英文名稱跟著卡表,例如「Down Force」);同一卡號有 e / j 兩版時名稱相同,取第一筆。卡表的名稱照用,不另行修正(例:S-011 卡表寫「Ion Gravirei」)。
  - `effect` 是依 `effect_ja` 手寫的翻譯,存在檔中,工具重新執行時保留。
  - 不照抄卡表或卡圖(民間英譯版)的英文效果文:兩者與日文效果文有出入(見 `card-effects` design「行為決定與理由」),遊戲行為依日文效果文,畫面文字應與行為一致。卡表的英文只作用語參考。
  - 寫法:「」括起的卡名 / 戰術名改為該卡的英文 `name` 並保留引號;效果類型用規則頁的英文稱呼(Declare use →、Reduce MP by N →、Discard this card →、While this card is in play →);開頭的《效果名》省略(與中文一致,效果名已在卡名中)。用語對齊卡圖:MAMODO、SPELL、Spell Book、Power、Partner、Event、[STANDBY]、[STAY]、[COUNTER]、PROTECT、Injured、Healthy、Discard Pile、heads / tails。
- **簡體中文**:`tools/build_zh_cn.py` 把繁中的卡片文字、介面字典、規則頁三個檔轉成簡中,不手動編輯;測試以同一函式(`build()`)重新產生並比對,繁中改了沒重跑就會失敗。
  - 轉換:OpenCC `tw2sp`(字形 + 大陸用語,例如「圖示→图标」「連結→链接」「咖哩→咖喱」)。轉換前把 `TERMS` 的詞換成私用區佔位字元,轉換後換回指定寫法:保留遊戲術語「宣告」(不轉為「声明」),修正誤轉(「進階→高端」、「顯示」被斷詞、「複製→拷贝」、「文字→文本」),替換「預設→默认」「帳號→账号」。
  - 譯名只轉字形(賈修・貝爾→贾修・贝尔),使用者決定先不改用大陸譯名;之後要換譯名時加進 `TERMS`。
  - `name_ja` 不轉換:日文漢字會被改掉。`app.title` 不轉換:網站名稱是專有名稱,各語言相同。
  - `opencc-python-reimplemented` 只是 dev 依賴,執行時不需要。OpenCC 詞典升級可能改變輸出,同步測試會抓到,檢查差異後重跑工具。
- **測試**(`tests/test_i18n_languages.py`):三個檔都涵蓋 `cards.json` 全部卡號且 `name`、`effect` 非空;同一個日文元素在繁中、英文各只有一種譯名、有元素的戰術屬性不為空、日文沒有元素的戰術沒有屬性(第二彈繁中曾把 S-029〜S-031 譯成「電擊」,與其他雷屬性的「雷」不一致,也曾自訂「火焰」「武術」等屬性與指令戰術的「指令」,都沒被發現,已依日文修正);`name_ja` 與 `cards_ja.csv` 一致;英文 `name` / `attr` 與卡表一致;英文 `effect` 不含假名(避免漏翻)。
- **效果文直譯**(`l12-translation`,2026-10-31):繁中與英文的效果文都是 `effect_ja` 的直譯,不依實作改寫,不加入或省略條件;效果名、卡名、戰術名依使用者比照代理版譯名的校對,不改。第 1、2 彈的繁中最初依英文資源翻譯,曾加入日文沒有的條件(M-005「此魔物進行攻擊」、M-031「與負傷」),與實作的簡化一致而沒被發現,已全部依日文重譯。
  - 用語:【MP減少N→】【宣告使用→】【將此卡棄掉→】【此卡在場上→】、【持續】【待命】【反擊】、魔書 / 戰術 / 戰術卡、「魔物的效果」、放到場上、棄掉 / 棄牌區、負傷狀態 / 健康狀態、保護、擲硬幣:正面時、本場戰鬥中、本回合的下一場戰鬥中;「」括起的卡名換成該卡的繁中 `name`。
  - 戰術卡的固定句型全部卡片一致:「相手の魔本にダメージ。」→「對對手的魔書造成傷害。」,「【カウンター】魔力勝負で勝ったとき、」→「【反擊】魔力勝負獲勝時,」,「魔力勝負で勝ったとき、相手の攻撃を無効にする」→「魔力勝負獲勝時,將對手的攻擊無效」;不另加「以攻擊方 / 防禦方獲勝時」的規則說明。
  - 固定譯法(`l3-translation`,2026-10-31;需求「效果文的固定譯法」):「この効果は…使える」→「此效果在…時可以使用」、「次の効果の1つを使う」→「使用以下效果的其中1個」、「次の効果の両方を使う」→「使用以下兩個效果」、「次の効果の両方を、この順で使う」→「依序使用以下兩個效果」、「次の効果の、片方または両方を、この順で使う」→「依序使用以下效果的其中1個或2個」、「そうしたなら」→「這麼做時」、「N枚めくる / もどす」→「翻 / 回翻…N張」、「好きなページ」→「任意頁」、「〜を選び、場に出す / 捨て札にする」→「選擇…,放到場上 / 棄掉」、「この効果は、次のターンのスタートフェイズまで【スタンバイ】し、次のターン中【ステイ】する」→「此效果在下回合的開始階段之前【待命】,在下回合中【持續】」、「術1つ」→「1個戰術」、「術カード」→「戰術卡」。日文有「」就保留「」:卡名換成繁中名稱,「かばう」「健康状態」「負傷状態」「ステイ」「スタンバイ」→「保護」「健康狀態」「負傷狀態」「持續」「待命」。
  - 第 3 彈之後(197 張)也已逐張與日文對照(`l3-translation`):修正意思出入(S-084 / S-100 的主詞、S-076 / S-077「直接」、S-067 / S-097 漏「できる」、Ex-022 / Ex-027 / PR-007「そうしたなら」等)並統一固定譯法,共改 93 張(含第 1、2 彈的 M-030)。
- **翻譯狀態**:日文為原文;英文效果文為初版翻譯,尚未經母語者校對,全部卡片已逐張與日文核對;簡體中文是自動轉換,尚未校對。

## 第三彈卡片資料

- **來源**:atwiki 的四個商品頁:LEVEL:3「金色の超呪文」(35)、カードセット「ガッシュ・ベルと仲間達」(1189)、「ゼオンと最凶魔物達」(1190)、「魔本ファイル」(58,只取 M-032〜M-034;頁上其他卡屬於之後的彈)。商品頁與 booster 頁同格式,`scrape_ja_effects.py --range` 只抓範圍內的卡號。atwiki 搜尋會回 403,商品頁編號是逐一試出來的,寫在工具的 docstring。
- **資料頭的新寫法**(都以對舊 135 張重新解析零差異驗證過):
  - 元素「土」;「ダメージ?」表示傷害依效果決定(S-061)。
  - 資料頭分成三行(S-093):第三行要每個 token 都能分類才算資料頭,否則退回當效果文,避免把效果文首句誤吞。
  - 必填欄位滿足後,單獨一行的效果 icon / 回合標記(S-086 的「非バトル」)也屬於資料頭。
  - 中間段落的行接在第一段後交給資料頭解析:M-039 的「バトル防御」在第二段開頭。
  - 戰術尾行「第X の術」(S-100)。S-098 頁面漏刊 power,登記在已知缺漏清單(「特殊」)。
- **已知效果文錯誤**:`scrape_ja_effects.KNOWN_TEXT_ERRORS` 登記 atwiki 上已確認的錯誤(錯誤原文 → 修正後)。解析後找到原文就取代;找不到就報錯,因為來源可能已修正或改寫,要人工確認後更新登記,而不是默默套用。目前只有 S-069(「防御に使ったとき」與「攻撃に使ったとき」兩段標題寫反,依卡圖與 TTS 卡表英文確認,2026-10-15 使用者確認)。修正時直接改 `cards_ja.csv`(保留 CRLF 換行)後重跑轉換與文字工具,不重抓整個網站。
- **`damage_variable`**:卡面「ダメージ?」轉為 `damage: null` + `damage_variable: true`,不用字串「?」,讓 `damage` 維持整數或 null,引擎與 NPC 的數值判斷不受影響。前端卡面顯示「傷害 ?」。
- **收錄產品**(2026-10-27 起):`sets` 由 `cards_ja.csv` 的 `sets_ja` 產生,存產品代號(`build_cards_json.PRODUCTS`:`level-1`、`level-2`、`mahon-file`、`level-3`、`cardset-gash-nakama`、`cardset-zeon`、`level-s`、`tbb1`、`tbb2`、`re`、`file-1`),轉換不再讀 xlsx。

  - 存代號而不是日文產品名:代號同時是產品圖檔名(`frontend/products/<代號>.webp`)與介面字串鍵(`product.<代號>`),日文名含冒號與中點不適合。
  - 對照表沒有的產品名直接中止轉換:抓進新產品頁時要先決定代號,以及要不要列進篩選(`frontend/pool-filters.json`)。

- **尚未開放的卡**(`data/pending_cards.json`):資料先收錄、效果分批實作;清單中的卡不能組進牌組(引擎 `deck.card_pending`,建房與 NPC 都經過同一驗證),構築器卡池與產品篩選不列出(只含尚未開放卡的產品也不列出)。用清單而不是在 `cards.json` 加欄位:`cards.json` 由工具產生,開放狀態是實作進度,不是卡片資料。每個效果實作 change 完成時自清單移除。
- **文字**:繁中卡名沿用既有譯名;效果文沿用舊卡寫法(造成傷害的戰鬥戰術冠「以攻擊方獲勝時,」、「以防禦方獲勝時,將對手的攻擊無效」、「無論魔力勝負結果」、「檢視」、「翻…頁」、「此事件卡僅於…時可使用」;搭檔效果名帶《》)。繁中與英文效果文都是 AI 初版,使用者抽查後同意先上,待校對。

## 賽季

- **定義檔 `data/seasons.json`**:`seasons` 記各賽季每種卡號前綴的最大編號(卡號以最後一個 `-` 拆成前綴與數字;某賽季沒有列出的前綴表示該賽季不含此前綴的卡),`special` 直接指定賽季(Ex-100、Ex-101 → 3;Ex-000、Ex-099 → 4),`selectable` 是對局可選的賽季,`default` 是未指定時的賽季。上限由使用者提供(2026-10-28),對應各賽季的發售範圍:第 1 賽季 LEVEL:1;第 2 賽季加上 LEVEL:2、魔本ファイル、魔本拡張シート LEVEL:1;第 3 賽季加上 LEVEL:3、兩個カードセット、LIMITED EDITION Ⅰ、スペシャルボックス、拡張シート LEVEL:2。
  - 第 4 賽季與 PR 範圍(使用者提供,2026-11-07):第 4 賽季加上 LEVEL:4、拡張シート LEVEL:3、電撃フェスタ2004春の陣 プロモーションシート(Ex-000、049、050、099)與 PR-012、013;DX赤い魔本 スペシャルカードエディション(2003 年 12 月上旬)的附錄卡 Ex-100、101 屬第 3 賽季。PR 依發行時期調整為第 1 賽季到 PR-002、第 2 到 004、第 3 到 010、第 4 到 013,所以 PR-005〜007 由第 2 改第 3 賽季、PR-011 由第 3 改第 4 賽季;預組魔書沒有用到。LIMITED EDITION Ⅱ(M-086〜090)屬第 5 賽季,還沒收錄。
- **推導**:一張卡的賽季是 `special` 的指定,否則是包含它的最早賽季,都沒有時為空;魔書的賽季是各卡賽季的最大值。引擎 `gash.engine.seasons` 與前端 `decks.js` 的 `cardSeason` / `deckSeason` 讀同一份檔案(前端經 `/data/seasons.json`)。
- **為什麼是獨立檔案**:與 `pending_cards.json` 同理,`cards.json` 由工具從 atwiki 產生,賽季是對局用的分類;以範圍而不是逐卡欄位記錄,補卡時不必逐張填,也不會與範圍不一致。前後端都要用,所以不寫死在程式裡。
- **構築驗證**:`validate_deck(pages, db, season)` 在未知卡、尚未開放之後檢查賽季(`deck.season`);沒有指定賽季時不檢查,啟動時的預組驗證不受影響。
- **Ex 卡號**:定義檔的前綴依 atwiki 寫成 `Ex`,與卡片資料一致(見「第 3 賽季卡片資料」)。

## 大會規則的 PR 卡限制

- 「プロモーションカードは1種類につき1枚まで入れられる」(atwiki「ルール」pages/87「大会ルール」)。不設開關,所有構築驗證一律適用(使用者決定,2026-11-01;大會規則的另一條見 `game-engine` design「大會規則」)。
- 範圍是卡號 `PR-` 開頭的卡(使用者確認);`Ex-` 擴張卡不是プロモーションカード,仍依同號 ≤4。同一節列出的使用不可卡(X-001〜X-004、KIRE 等)不在本專案的卡池內。
- `validate_deck` 在同號 ≤4 之後檢查(`deck.pr_copies`),所有構築驗證共用這個函式;前端 `decks.js` 有對應的即時提示(`deck.err.pr_copies`)。現有預組都沒有重複的 PR 卡。

## 卡圖

- **來源**:維護者的公開 Google Drive 資料夾 `1cXx4gpa41HiycU4hIN74xbp1Aj3hiE-k`,檔名 `{卡號}.webp`;擴張卡的檔名是大寫 `EX-xxx.webp`,工具對應到卡號 `Ex-xxx`,存成 `Ex-xxx.webp`(不改使用者維護的資料夾)。`cards.json` 不含卡圖連結(2026-10-26 移除 `image_url`)。
  - 為什麼不用 TTS 卡表的連結:那些 Drive 檔案不歸本專案管理,有的非公開(M-050、P-130、P-146、PR-029 轉到登入頁)、有的已失效(E-146),缺圖無法補。2026-10-26 把卡表全部 1557 列的卡圖轉成 WebP 上傳到資料夾(使用者另補 M-050),之後以資料夾為準,補圖、換圖只在資料夾操作,不改 repo。
  - 遊戲用的 `{卡號}.webp` 是卡表中 j 版優先的那一列;其他版本以原始編號命名(如 `M-xxxe.webp`),同一編號出現兩次的第二張加 `_2`,工具不使用。
  - **取得清單**:公開資料夾的 `embeddedfolderview` 頁面列出全部檔案(實測 1557 筆一次回傳,沒有分頁),解析出「檔名 → 檔案 ID」後以 `uc?export=download` 下載,不需要 API 金鑰。不用 Drive API(要管金鑰),也不在 repo 放對照表(每次補圖都要改 repo)。這是非正式介面,頁面解析不到任何檔案時工具直接報錯結束,而不是把每張卡記成失敗。
  - 資料夾 ID 寫成工具常數:它是專案唯一的卡圖來源,不是部署設定。
- **格式**:WebP q80(有損、保留透明通道),檔名 `{卡號}.webp`,尺寸與原圖相同(465×679)。系統只認這一種格式:前端的 `artUrl()`、`/api/meta` 的張數、下載工具的續抓都只看 `.webp`。
  - 原圖是 RGBA PNG,四角透明做圓角,所以不能用 JPEG。
  - 135 張實測:原圖約 90MB;q80 約 11MB(每張約 83KB),q88 約 15MB,無損每張約 460KB。效果文區塊放大兩倍比對,q80 與原圖看不出差別。
  - 不支援其他格式並存:換格式時所有環境重新下載,不在執行時轉換或退回舊格式。
- **轉檔位置**:資料夾中的檔案已是 WebP,`tools/download_images.py` 依檔頭判斷後原樣存檔,不再壓縮一次;下載到其他格式時才在記憶體中轉成 WebP(`to_webp()`)。`pillow` 只是 dev 依賴,執行環境(映像檔)不需要。
- **測試**(`tests/test_download_images.py`):解析資料夾頁面;WebP 原樣存檔、其他格式轉檔保留尺寸與透明圓角;資料夾中沒有的卡與登入頁記入失敗清單;續抓只跳過已有 `.webp` 的卡;頁面解析不到檔案時報錯。以固定的頁面樣本與假的下載函式代替 Google Drive,不連網。
