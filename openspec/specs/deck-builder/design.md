# deck-builder — 設計

目前只整理了卡池篩選;對頁編輯、合法性提示、儲存與文字碼以 `frontend/app.js`、`frontend/decks.js` 與測試為準。

## 卡池篩選

- **共用**:`renderCardPoolFilters(holder, filters, onChange, opts)` 建篩選列,`renderCardPool` 以 `poolCardMatches` 比對;構築器(`B`)與金手指(`CHEAT`)各自持有一份篩選狀態(`newPoolFilters()`:類型集合 `ftypes`、魔物 `fmamodo`、產品 `fproduct` 與賽季 `fseason`(`null` 為全部)、目前展開的網格 `fopen`),函式不判斷呼叫端;唯一的差別由 `opts.pending` 傳入(見「尚未開放的卡」)。
- **比對**:類型空集合不篩選、勾多個時符合任一;魔物、產品、賽季未選不篩選;賽季為累計(卡片賽季 ≤ 所選賽季,`cardSeason` 見 `card-data/design.md`「賽季」);跨組全部符合。指令戰術在魔物組以 `__none__`(「無」)代表。只勾「事件」時(`mamodoFilterPaused`)魔物組不套用、按鈕停用,選擇保留。
- **篩選列**:一行:4 顆類型徽章(`aria-pressed` 切換鈕,圖示旁有類型名稱)+ 魔物、產品、賽季三顆按鈕(`FILTER_MENUS`,`aria-expanded`),按鈕摘要為目前選擇的圖示與名稱(賽季用短標示「第2季」,讓窄螢幕的篩選列放得下)。網格是篩選列下方的浮層,同時只開一個;網格內點選即選擇並收起,焦點回到按鈕;點網格外(document 的 `pointerdown`,每個 holder 只掛一組)或 Esc 收起。建好後只以 `sync()` 更新狀態,不整個重繪,鍵盤焦點不會跑掉。窄螢幕(≤700px)徽章與按鈕改為上圖下字以維持一行。
- **圖示**:
  - 每個圖示旁都有文字(類型名稱、魔物名稱、產品名稱)。
  - 類型徽章與魔物圖示從卡圖裁切(`artCrop`,與規則頁的圖示共用;座標在 `ART_BOXES.type` 與 `MAMODO_ART`,所有卡同版型)。類型徽章先放「魔 / 使 / 術 / 鍵」,`probeArt` 確認卡圖可載入才換成裁切;魔物圖示在卡圖無法載入時移除,只留名稱。探測結果有快取,重繪不閃。
  - 魔物代表卡:家族中卡號最小、卡池列得出的魔物卡;沒有時只顯示名稱。名稱取代表卡卡名並去掉結尾的括號註記(`familyLabel`)。
  - 產品圖 `frontend/products/<代號>.webp`(進 git,經 `/static/products/` 提供;`frontend/assets/` 在正式站是卡圖 volume,不能放),取自維護者的產品照片,長邊 400px;載入失敗就移除圖,只留產品名稱。
- **排序**:`renderCardPool` 以 `comparePoolCards` 排列:類型依 `POOL_SORT_TYPES`(魔物 → 搭檔 → 戰術 → 事件 → MJ12;MJ12 只排序、沒有類型篩選鈕,所以不在 `POOL_TYPES`),同類型依卡號;原本是卡號字串排序,事件(E-)會排在最前。卡號比較一律用 `compareCardNumbers`:原有前綴(M- / P- / S- / E-)在前,接著 Ex-、PR-(`NUMBER_PREFIX_RANK`),同前綴依編號;魔物代表卡與家族排列也用它(字串比較會讓 Ex-028 排在 M-005 前面)。
- **設定檔 `frontend/pool-filters.json`**:`products` 每個內層陣列是一排(一個賽季的系列),只列出的產品會顯示;`mamodo` 是家族順序,沒列出的依代表卡卡號接在後面(新彈加入的魔物不會因為忘了改設定而消失);`mamodo_merge` 把家族併入另一家族(`filterFamily`),只影響篩選,不改 `cards.json` 的 `related_mamodo`。放在 `frontend/` 是因為它是介面呈現的設定,不是卡片資料。

- **產品分排與換行**(2026-10-28):一排是一個賽季的系列。
  - 排序:第 1 賽季 / 第 2 賽季 / 第 3 賽季 / 特典卡。
  - 第 3 賽季有 7 個產品,放不下時依寬度換行。
  - `.filter-row` 以懸掛縮排表示續行:整排 `padding-left`,第一格負 `margin-left`。
  - 手機上第 3 賽季分三行,桌面分兩行。
  - 不採用固定每行 3 格:桌面浪費空間,也不必為了寬度在設定檔拆排。
  - 新產品在卡片開放前,構築器照常列出(見「尚未開放的卡」),金手指不列。
  - 第 4 賽季(season4-card-data,2026-11-07):第 3 賽季那一排末尾加 DX赤い魔本(附錄卡 Ex-100、Ex-101 屬第 3 賽季);新增第 4 排 LEVEL:4、拡張シート LEVEL:3、電撃フェスタ2004春の陣;特典卡那排變成第 5 排。DX赤い魔本 的產品圖取自使用者提供的網路圖片,其他照舊取自產品照片。

## 尚未開放的卡(pending-cards-preview,2026-11-07)

- 使用者希望在效果實作前就能預覽新卡。構築器卡池顯示尚未開放的卡,但不能加入魔書;金手指維持不顯示,因為它把卡直接放進對局,而引擎還不會處理部分新卡(如 MJ12)。
- `poolCards(withPending)`:構築器傳 true(全部的卡),金手指傳 false(`openCards()`)。卡池列表、魔物網格、產品網格都用它,所以只含尚未開放卡片的產品與魔物家族在構築器也會列出;網格項目不另做調暗(網格是篩選用的,卡片本身有標示;使用者採納)。
- 卡片加 `pending` 樣式(調暗、灰階,詳情按鈕與「尚未開放」標記除外),無障礙名稱帶「尚未開放」。點選或 Enter / Space 不放卡,改為 toast 提示;「i」詳情按鈕照常放大檢視。
- 不設 `aria-disabled`:依 ARIA,它會連帶把卡片內的詳情按鈕標成停用(螢幕閱讀器讀成不能按,Playwright 也點不到)。
- 只是畫面上的保護;匯入牌組代碼等方式放進魔書時,構築規則照樣以 `deck.card_pending` 擋下。
- 選第 1~3 賽季時,第 4 賽季的新卡照賽季篩選濾掉;Ex-100、Ex-101 屬第 3 賽季,選第 3 賽季時以尚未開放的樣式出現。

## 魔書的賽季標示

`#builder-season` 在魔書名稱旁顯示「第 N 賽季起可用」(`deckSeason`,空頁不計),由 `renderValidation()` 隨內容更新;空魔書不顯示。它只是資訊,不加入合法性提示:構築時不知道魔書要用在哪個賽季。

## 行為決定與理由

- **賽季篩選為累計**(「卡池賽季篩選」)— `Project Decision`(2026-10-28)。選第 N 賽季顯示該賽季可用的全部卡,用途是「做一副能在第 N 賽季用的魔書」;只看某時期新加入的卡可以用產品篩選。使用者在 explore 中選定。

- **只有類型多選,魔物與產品單選**(「卡池篩選的選取方式」)— `Project Decision`(2026-10-27)。最初三組都做成多選,使用者實際試用後決定只保留類型多選。單選時點選即收起網格,按鈕上能完整顯示所選項目的圖示與名稱。
- **金色のガッシュベル併入ガッシュ・ベル**(「魔物篩選圖示與順序」)— `Project Decision`(2026-10-28)。使用者不要金色のガッシュベル(M-047)單獨成為選項;拿掉後選ガッシュ・ベル時一併顯示 M-047,否則魔物篩選找不到這張卡。只在篩選合併,卡片資料的對應魔物不變(遊戲規則上是否視為同一魔物不在此決定)。
- **魔物名稱去掉括號註記**(同上)— `Project Decision`(2026-10-28)。ロブノス(分身体)、バルトロ(アーマー体)的括號是卡片形態,篩選的是家族。
- **卡池依 魔物 → 搭檔 → 戰術 → 事件 排序**(「卡池排序」)— `Project Decision`(2026-10-28)。使用者指定;與類型徽章的順序一致,事件不再排在最前。
- **卡號順序:原有前綴、Ex-、PR-**(「卡池排序」「魔物篩選圖示與順序」)— `Project Decision`(2026-10-29)。第 3 賽季開放 Ex- 卡後,字串排序讓卡池從 Ex-001 開始、ブラゴ的代表卡變成白板的 Ex-028;使用者同意依原有前綴 → Ex- → PR-(與產品分排中拡張シート在特典卡之前一致)。第 3 賽季的新家族(ニャルラト、ノリトー・ハッサミー、グリサ、パティ、キッド)依卡號加在設定檔魔物順序的最後。
- **圖示旁留文字**(「卡池圖示篩選列」)— `Project Decision`(2026-10-27)。使用者試用後要求;魔物插圖與產品盒圖不一定一眼認得。

- **有選魔物時不顯示事件**(「卡池篩選的對應魔物」情境「類型含事件與其他類型時事件不顯示」)— `Project Decision`(2026-10-27)。事件沒有對應魔物。類型改成多選後,同時勾「事件」與其他類型時有兩種做法:事件不受魔物篩選(顯示全部事件)或嚴格比對(不顯示事件)。使用者選後者,與單選時代「類型全部 + 選某魔物時不顯示事件」一致;要看事件把魔物清回「全部」即可。只勾「事件」時仍停用魔物篩選,沿用既有規則。
- **再收錄產品不列出**(「產品篩選分排」)— `Project Decision`(2026-10-27)。TBB1、TBB2、REVISED EDITION、FILE:1、LEVEL:S 收錄的都是前面各彈的卡,列出來只是重複;每張卡都至少屬於一個列出的產品,不會有篩不到的卡。產品依彈數分排(LEVEL:1 / LEVEL:2、魔本ファイル第1弾 / LEVEL:3、ガッシュ・ベルと仲間達、ゼオンと最凶魔物達),由使用者指定。2026-10-28 改為一排一個賽季的系列(第 2 賽季加入拡張シート LEVEL:1;第 3 賽季加入 LIMITED EDITION Ⅰ、スペシャルボックス、魔本ファイル第2弾、拡張シート LEVEL:2),特典卡自成最後一排;太長時換行縮排而不拆排(使用者決定)。
- **「Ex 卡」是依卡號前綴的虛擬產品**(「Ex 卡產品」)— `Project Decision`(2026-11-01)。使用者要一次看所有 Ex- 卡;卡片資料的 `sets` 不變,前端 `productHas` 對代號 `ex` 改以卡號 `Ex-` 開頭判定(列出與篩選共用),與特典卡並排在最後一排。兩個魔本拡張シート照樣保留(使用者決定),所以 Ex- 卡同時出現在原本的拡張シート與 Ex 卡兩處。圖示比照 `promo.webp` 以介面配色產生「Ex」字樣。
- **單選再點一次取消、「全部」放大**(「卡池篩選的選取方式」)— `Project Decision`(2026-11-01)。使用者試用後要求:原本取消只能點網格上方的小「全部」按鈕;現在再點已選項目也能取消,「全部」按鈕至少 40px 高。
- **彈出網格而不是橫向捲動列**(「卡池圖示篩選列」)— `Project Decision`(2026-10-27)。30 個魔物與 6 個產品排成一列太長,手機上只看得到幾個;篩選列維持一行,點按鈕才展開。

## 卡池文字搜尋(builder-search)

- 新手回饋(評論 6、10):卡池很長,只有圖示篩選。構築器(`B`)與金手指(`editor`)的篩選狀態加 `fquery`,`poolCardMatches` 先比對文字再套用其他篩選(且)。
- 比對字串(`searchText`,以卡號快取):卡號、去掉連字號的卡號、目前語言的 `name`、`name_ja`、`attr`、`effect`,經 `searchNormalize`(`NFKC` + 小寫)後以「包含」判斷,所以全形英數與全形連字號也能找到(`Ｓ－０９２`)。語言切換會重新載入頁面,快取不必失效。
- 不比對日文效果文(雜訊太多);不做「目前魔物可用戰術」篩選,既有的對應魔物篩選已涵蓋(使用者決定)。
- 搜尋框在篩選列上方獨立一行(篩選列的規格是一行,窄螢幕放不下再多一個輸入框)。篩選列只畫一次、之後以 `sync()` 更新,輸入時不會被重建而失去焦點。Esc 在有文字時清空並停止傳遞(金手指是 `<dialog>`,不關閉視窗,同篩選網格)。

## 魔書組合的提醒(deck-warnings)

- 新手回饋希望有組牌提示;使用者認為策略由玩家自己發掘,只檢查一定不能運作的組合:沒有魔物能使用的戰術(指令戰術除外)、沒有對應魔物的搭檔。不做「對應魔物排太後面」等策略檢查。
- 引擎 `deck_warnings(pages)`(`engine/deck.py`):以一場固定的對局為環境,把魔書中每張魔物卡放成假設的場上魔物,沿用 `_spell_usable_by`(家族、`RULE_SPELL_COMPAT` 的 M-029、`SPELL_COMPAT` 的 M-023 / M-036 都只依卡片資料,假設盤面上判斷準確)。對局中由搭檔效果產生的 `spell_compat_attr`(P-029)掃描魔書中各卡的效果樹找 `AllowAttrSpellsThisTurn`,有該家族的魔物時視為能使用。前端若只依 `related_mamodo` 判斷會誤報這些相容規則。
- `POST /api/decks/warnings`(32 頁,可含空頁)回傳 `[{kind, page, card}]`。欄位叫 `kind` 而不是 `code`:i18n 測試把原始碼中的 `"code": "..."` 當作錯誤代碼檢查翻譯,提醒不是錯誤。
- 構築器的 `renderValidation` 以魔書內容為鍵快取提醒(`DECK_WARN`),只採用最後一次請求的結果;以 `.warn`(琥珀色)列在違規之後,「魔書合法」與儲存不受影響。提醒不放進 `validate_deck`,線上房與 NPC 的驗證不變。
- 之後新增以其他方式讓魔物使用戰術的效果時,要在 `deck_warnings` 補上,否則會誤報(只是提醒,不影響合法性)。

## 「其他」類型、標籤篩選與 Ex / PR 排序(pool-tags-and-order)

- 類型徽章第 5 顆「其他」(`POOL_TYPES` 的 `other`,`poolType`):主要 4 種以外的類型(MJ12,之後的バルカン)都算,不必每多一種類型就加一顆;圖示暫用 MJ-001 左上,缺圖文字「他」。
- 標籤篩選(`FILTER_MENUS` 的 `tag`,`filters.ftags` Set,`POOL_TAGS`):干擾(效果圖示,與資訊列的干擾標籤同一判斷)、石版(`stone_tablet`,與資訊列的石版標籤同一判斷;和干擾排在第一列但各自一組、不互斥,使用者 2026-11-11 決定,stone-tag-filter)、中級 / 上級(`class`)、8 種屬性(`attr_name`,依卡數多寡排)。多選、網格保持展開;同組互斥(中級 / 上級、各屬性),不同組同時符合(使用者要求同組互斥後,跨組改為同時符合,與其他篩選組一致)。勾選的 tile 前面方框打勾,類型徽章勾選時右上角 ✓(使用者:「多選要用打勾讓那些有選更清楚」)。
- 排序(`comparePoolCards`):Ex- / PR- 以外依類型再依卡號;Ex- 全部依編號接在後面(不分類型),PR- 最後依編號(使用者選擇)。`compareCardNumbers` 不變,魔物網格沿用。
- 篩選列是 container(`container-type: inline-size`):寬度不到 700px 時徽章與選單改緊湊版(圖示在上、文字在下),手機與 1440px 以下的桌面都在一行內(使用者選擇)。規則要寫在基本規則之後,否則同權重被蓋掉。
- 使用者回饋後:點在展開的網格與它的按鈕以外(含篩選區內的空白處)就收起;標籤網格每組一列;最後加「重置」(清除所有篩選與搜尋,沒有篩選時停用);選單按鈕撐滿剩下的寬度。
