# deck-builder — 設計

目前只整理了卡池篩選;對頁編輯、合法性提示、儲存與文字碼以 `frontend/app.js`、`frontend/decks.js` 與測試為準。

## 卡池篩選

- **共用**:`renderCardPoolFilters(holder, filters, onChange)` 建篩選列,`renderCardPool` 以 `poolCardMatches` 比對;構築器(`B`)與金手指(`CHEAT`)各自持有一份篩選狀態(`newPoolFilters()`:類型集合 `ftypes`、魔物 `fmamodo` 與產品 `fproduct`(`null` 為全部)、目前展開的網格 `fopen`),函式不判斷呼叫端。
- **比對**:類型空集合不篩選、勾多個時符合任一;魔物、產品未選不篩選;跨組全部符合。指令戰術在魔物組以 `__none__`(「無」)代表。只勾「事件」時(`mamodoFilterPaused`)魔物組不套用、按鈕停用,選擇保留。
- **篩選列**:一行:4 顆類型徽章(`aria-pressed` 切換鈕,圖示旁有類型名稱)+ 魔物、產品兩顆按鈕(`aria-expanded`),按鈕摘要為目前選擇的圖示與名稱。網格是篩選列下方的浮層,同時只開一個;網格內點選即選擇並收起,焦點回到按鈕;點網格外(document 的 `pointerdown`,每個 holder 只掛一組)或 Esc 收起。建好後只以 `sync()` 更新狀態,不整個重繪,鍵盤焦點不會跑掉。窄螢幕(≤700px)徽章與按鈕改為上圖下字以維持一行。
- **圖示**:
  - 每個圖示旁都有文字(類型名稱、魔物名稱、產品名稱)。
  - 類型徽章與魔物圖示從卡圖裁切(`artCrop`,與規則頁的圖示共用;座標在 `ART_BOXES.type` 與 `MAMODO_ART`,所有卡同版型)。類型徽章先放「魔 / 使 / 術 / 鍵」,`probeArt` 確認卡圖可載入才換成裁切;魔物圖示在卡圖無法載入時移除,只留名稱。探測結果有快取,重繪不閃。
  - 魔物代表卡:家族中卡號最小的開放魔物卡;家族沒有開放的魔物卡時只顯示名稱。名稱取代表卡卡名並去掉結尾的括號註記(`familyLabel`)。
  - 產品圖 `frontend/products/<代號>.webp`(進 git,經 `/static/products/` 提供;`frontend/assets/` 在正式站是卡圖 volume,不能放),取自維護者的產品照片,長邊 400px;載入失敗就移除圖,只留產品名稱。
- **排序**:`renderCardPool` 以 `comparePoolCards` 排列:類型依 `POOL_TYPES`(魔物 → 搭檔 → 戰術 → 事件),同類型依卡號;原本是卡號字串排序,事件(E-)會排在最前。
- **設定檔 `frontend/pool-filters.json`**:`products` 每個內層陣列是一排,只列出的產品會顯示;`mamodo` 是家族順序,沒列出的依代表卡卡號接在後面(新彈加入的魔物不會因為忘了改設定而消失);`mamodo_merge` 把家族併入另一家族(`filterFamily`),只影響篩選,不改 `cards.json` 的 `related_mamodo`。放在 `frontend/` 是因為它是介面呈現的設定,不是卡片資料。

## 行為決定與理由

- **只有類型多選,魔物與產品單選**(「卡池篩選的選取方式」)— `Project Decision`(2026-10-27)。最初三組都做成多選,使用者實際試用後決定只保留類型多選。單選時點選即收起網格,按鈕上能完整顯示所選項目的圖示與名稱。
- **金色のガッシュベル併入ガッシュ・ベル**(「魔物篩選圖示與順序」)— `Project Decision`(2026-10-28)。使用者不要金色のガッシュベル(M-047)單獨成為選項;拿掉後選ガッシュ・ベル時一併顯示 M-047,否則魔物篩選找不到這張卡。只在篩選合併,卡片資料的對應魔物不變(遊戲規則上是否視為同一魔物不在此決定)。
- **魔物名稱去掉括號註記**(同上)— `Project Decision`(2026-10-28)。ロブノス(分身体)、バルトロ(アーマー体)的括號是卡片形態,篩選的是家族。
- **卡池依 魔物 → 搭檔 → 戰術 → 事件 排序**(「卡池排序」)— `Project Decision`(2026-10-28)。使用者指定;與類型徽章的順序一致,事件不再排在最前。
- **圖示旁留文字**(「卡池圖示篩選列」)— `Project Decision`(2026-10-27)。使用者試用後要求;魔物插圖與產品盒圖不一定一眼認得。

- **有選魔物時不顯示事件**(「卡池篩選的對應魔物」情境「類型含事件與其他類型時事件不顯示」)— `Project Decision`(2026-10-27)。事件沒有對應魔物。類型改成多選後,同時勾「事件」與其他類型時有兩種做法:事件不受魔物篩選(顯示全部事件)或嚴格比對(不顯示事件)。使用者選後者,與單選時代「類型全部 + 選某魔物時不顯示事件」一致;要看事件把魔物清回「全部」即可。只勾「事件」時仍停用魔物篩選,沿用既有規則。
- **再收錄產品不列出**(「產品篩選分排」)— `Project Decision`(2026-10-27)。TBB1、TBB2、REVISED EDITION、FILE:1、LEVEL:S 收錄的都是前面各彈的卡,列出來只是重複;每張卡都至少屬於一個列出的產品,不會有篩不到的卡。產品依彈數分排(LEVEL:1 / LEVEL:2、魔本ファイル第1弾 / LEVEL:3、ガッシュ・ベルと仲間達、ゼオンと最凶魔物達),由使用者指定。
- **彈出網格而不是橫向捲動列**(「卡池圖示篩選列」)— `Project Decision`(2026-10-27)。30 個魔物與 6 個產品排成一列太長,手機上只看得到幾個;篩選列維持一行,點按鈕才展開。
