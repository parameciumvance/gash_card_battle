# Design

## Context

- 既有的結束方式:棄權(自由調查不能、未開局回 409)、雙方沒有回應時關房、牌桌的離開、閒置 2 小時回收。「回到首頁」只離開畫面。

## Decisions

### D1:誰能關閉

| 房間 | 條件 | 結果 |
|---|---|---|
| 自由調查(`local`) | 持有玩家 token | 刪除 |
| NPC 房 | 真人座位的 token | 刪除(先取消 NPC 驅動 task) |
| 朋友房(`online`,不是牌桌) | 建房者、對手尚未加入 | 刪除(房號失效) |
| 朋友房對局中 / 已結束 | — | 409 `room.close_started`(對局中請棄權) |
| 牌桌的房間 | — | 409 `room.close_table`(走牌桌的離開) |
| 觀戰者 | — | 403 `room.close_spectator` |

刪除沿用 `_close_room`:移除房間、牌桌空出(不會發生,牌桌已排除)、以 4404 關閉 WebSocket。

### D2:首頁的關閉按鈕

- 每一項右側一顆「關閉」按鈕(與點選回到對局分開)。依 `room.mode`、`room.table`、`room.started` 決定動作:
  - 可直接關閉(D1 前三列):呼叫 close,不確認(使用者決定;等待中的朋友房比照)。
  - 對局中的朋友房:頁面內確認(「棄權並移除」/「取消」),確定後呼叫既有的 forfeit。
  - 牌桌:等待中呼叫 `/api/tables/{n}/leave`(不確認,沒有對手);對局中同朋友房以確認後棄權。
- 成功後移除 `gash-room-<房號>` 並重新整理清單。失敗時顯示錯誤訊息(依錯誤碼的翻譯),記錄保留。
- 伺服器回應房間已不存在(`room.not_found`、`room.bad_token`)時照樣移除記錄;其他錯誤以 toast 顯示、保留記錄。
