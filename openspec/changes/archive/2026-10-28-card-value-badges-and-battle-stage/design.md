## Context

背景見 proposal.md。現況(`frontend/app.js` 的 `cardEl`):

- 資訊列 `.cmeta` 由費用、魔力(魔物)、魔力加值(戰術)、傷害、A/D 組成,與卡面不同的費用 / 魔力以 `val-good` / `val-bad` 著色;盤面卡片以 CSS 隱藏整個資訊列。
- 數值徽章 `.val-badge` 只在呼叫端傳入 `opts.cost` / `opts.power`(盤面的場上魔物、翻開頁)時產生;魔力徽章在左下、內容「魔力 N」,費用徽章蓋住卡圖的費用格、只寫數值。放大檢視以 CSS 隱藏徽章(`#zoom-card .card .val-badge`)。
- 對決舞台 `renderBattleStage` 只以文字呈現;快照的 `battle_in`(`spell`、`slot`)與 `battle`(`attack_spell` / `attack_slot` / `defense_spell` / `defense_slot`、無效旗標、明細)已足以找出雙方的魔物與戰術卡。魔力勝負對峙演出(`anim.js` 的 `faceoffGroup`)已有「魔物+戰術」一組的組法,含無戰術攻擊的固定魔力來源卡。

## Goals / Non-Goals

**Goals:**
- 魔力與費用在所有卡面只以徽章呈現,資訊列不重複。
- 放大檢視的魔力徽章兩行,其他小卡面只寫數值。
- 戰鬥中,舞台持續顯示雙方的攻防卡面。

**Non-Goals:**
- 不改傷害、A/D 的呈現位置(仍在資訊列)。
- 不改魔力勝負的對峙演出、數值明細、行動記錄。
- 不改快照與後端。

## Decisions

### 1. `cardEl` 一律產生徽章

- 魔物有卡面魔力時一律產生魔力徽章;戰術 / 事件有費用時一律產生費用徽章。呼叫端傳入目前數值(`opts.power` / `opts.cost`)時依目前數值著色,沒有傳入時顯示卡面數值、不著色。
- 資訊列移除費用與魔力;傷害、A/D、中級 / 上級保留。戰術的魔力加值寫成「+2000」、「特殊」寫成「特殊」,放在同一個魔力徽章(專案負責人要求戰術與魔物一致)。
- 移除「放大檢視隱藏徽章」的 CSS;放大檢視的著色改由徽章負責(原本資訊列數字的著色一併移除)。
- 盤面原本「只有一個徽章」(費用或魔力擇一)的邏輯改為各自獨立:魔物只有魔力、戰術 / 事件只有費用,實際上不會同時出現。

### 2. 魔力徽章的寫法依卡面大小

- 放大檢視(`#zoom-card`):兩行「魔力」/ 數值(以兩個元素排列,不靠換行字元)。
- 其他固定尺寸的卡面:只寫數值,單行。以 CSS 依容器切換(徽章內同時放標籤與數值,小卡面隱藏標籤),不在 `cardEl` 判斷場合。
- **替代方案**:徽章移到卡圖右下角並一律兩行(explore 中試過,不蓋卡名)。專案負責人選擇維持左下、小卡面只顯示數值。

### 2-1. 卡號標籤移到右下角,底部預留一列

實作中截圖發現:卡池、構築器頁位、金手指的卡號標籤原本在右上角,剛好蓋住卡圖的費用格;費用改以徽章蓋在費用格上後,兩者重疊、卡號被遮住。專案負責人選擇把卡號標籤移到卡片右下角;盤面以外的卡面一律在底部預留一列,左下放魔力徽章、右下放卡號,右上角只留費用格(與卡圖印刷位置一致)。放大檢視的卡號原本就在內容最底下,不受影響。
**替代方案**:卡號留在上方往左移(手機的構築器頁位 72px 寬,放不下);盤面以外不顯示費用徽章(缺卡圖時就看不到費用)。

### 2-2. 費用徽章以 container query 對齊

各場合的卡寬不同(盤面 104px、卡池 118 / 106px、金手指 120px、頁位 88 / 72px、放大檢視 300px 等),原本以根層級的 `--card-w` 計算費用格位置,只在盤面對齊。改為 `.card { container-type: inline-size }`,徽章以 `100cqw`(卡片內容寬 = 卡圖寬)換算,所有場合都對齊。需要支援 container query 的瀏覽器(Chrome 105、Safari 16、Firefox 110 以上)。

### 3. 舞台的攻防卡面

- 舞台每一側為一組固定尺寸的縮小卡面(魔物、戰術),以 `cardEl` 產生(沿用徽章與卡名),點擊開純展示放大檢視。尺寸以 CSS 變數分桌面組與手機組(與盤面框格的做法一致)。
- 魔物卡由魔物槽(`attack_slot` / `defense_slot`,戰鬥開始確認時為 `battle_in.slot`)從場上找出;找不到(已離場)時只顯示戰術卡。
- 無戰術攻擊的固定魔力來源卡,沿用對峙演出的判斷(明細中 `kind === "fixed"` 的來源);把這段邏輯抽成兩處共用的函式,避免規則分歧。
- 文字標籤(「攻擊:玩家《戰術》」)與合計魔力保留在卡面旁;戰術名可點的既有行為保留。
- 防禦方的狀態:`battle.step === "defense"` 時顯示「等待防禦宣告」;已過防禦步驟且沒有防禦魔物槽時顯示「不防禦」;字串沿用既有的 `ui.battle_no_defense_yet` 與 `anim.showdown.no_defense`。

### 4. 對峙演出的魔物效果防禦(驗收中回報)

魔力對決對峙演出原本以「有沒有戰術」判斷防禦方是否防禦,魔物效果防禦(M-039)因此顯示「不防禦」。改為以 `showdown` 事件的 `defense_mamodo` 判斷:有防禦魔物就顯示魔物,戰術位置顯示「魔物效果防禦」(新字串,四語)。與舞台卡面同一類資訊,併入本 change;修改「魔力對決對峙演出」並補情境。

## Risks / Trade-offs

- [舞台開啟時盤面高度變化變大(原本約 64px,加上卡面後更高)] → 舞台本來就在戰鬥開始 / 結束時開合;卡面尺寸取小,手機組再縮。以瀏覽器測試確認窄螢幕時行動列仍固定在底部、盤面可捲動。
- [小卡面只寫數值,魔力與費用要靠位置區分] → 魔力在左下、費用在右上的費用格,位置固定;放大檢視有完整標籤。
- [既有測試依賴資訊列的費用 / 魔力文字或徽章的「魔力 N」] → 依新呈現改寫,在 tasks 列出。
