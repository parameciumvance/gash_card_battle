## Context

- 前端動畫由 `frontend/anim.js` 的 `Anim.apply(events, prevState, renderFn)` 處理,每批事件排隊依序播放:
  - 量測 → 阻塞式演出(擲硬幣、魔力對決,各約 800ms,每項有 1.5 秒逾時保底)→ 重繪 → 疊加式演出(翻頁、飛卡、MP、負傷、棄牌)。
  - `prefers-reduced-motion` 時全部跳過直接重繪。
- 同一批事件會從指令回應與 WebSocket 推送各到一次,以 `seq` 去重,先到的播放。伺服器處理指令時先推送、再回應,所以自己的動作也常常從推送先到;推送訊息裡沒有標明是誰發起的。
- 量(NPC 自我對戰,預組對局平均每局):
  - 卡片使用類約 50 次(放卡 11、使用魔本中的卡 8、發動效果 6、宣告攻擊 19、宣告防禦 6)。
  - 其他重要事件約 55 次。
  - pass 約 77 次(對手約一半)。
- 專案負責人確認:
  - 只聚焦對手;對自己不利的結果也聚焦。
  - 對手 pass 也顯示。
  - 聚焦在「減少動態效果」時保留。
  - 頂欄加聚焦速度與動畫開關。

## Goals / Non-Goals

**Goals:**

- 對手的每個動作,以「一個動作一格」的方式在中央呈現原因與結果。
- 不讓盤面長期落後伺服器狀態。
- 玩家可在遊戲內關閉聚焦與動畫。

**Non-Goals:**

- 伺服器計時因聚焦而延長(聚焦時間照常計入回合計時)。
- 重播或回看已播過的聚焦(行動記錄已可回看)。

## Decisions

### D1:伺服器在推送與回應帶 `actor`

- `_broadcast(room, events, actor)` 把 `actor` 放進 `update` 訊息;`post_command` 的回應也帶同一個值。
- 來源:
  - `post_command`:token 對應的玩家。
  - NPC 驅動:NPC 座位。
  - 逾時代打:`awaited_player`。
  - 金手指:`null`。
  - `join` 開局:`null`。
- 替代方案「前端從事件內容推測行動者」:事件的 `player` 欄位語意不一(有時是受影響者),而且一批裡混有雙方。不採用。

### D2:聚焦步驟的組成(前端)

`Anim.apply` 多收 `actor`,在量測後把這批事件整理成時間軸,依序播放:

```text
依事件順序:
  卡片類(A)且要聚焦          → 開新的一格卡片聚焦(卡圖、卡名、效果文、說明)
  文字類(B)且要聚焦          → 目前有卡片格:併入為結果行;否則開新的一格文字聚焦
  擲硬幣 / 魔力對決(阻塞式)  → 結束目前這格,插入既有演出;之後的 B 另起一格
播完全部 → 重繪 → 疊加式動畫
```

- 「要聚焦」:
  - `actor` 不是自己 → A、B 都聚焦。
  - `actor` 是自己 → 只取對自己不利的 B:
    - `damage_dealt`,或 `pages_turned` 前翻,對象是自己。
    - `mamodo_injured` / `mamodo_discarded`,對象是自己的魔物。
    - `card_discarded`,是自己的卡且原因不是費用。
    - `mp_changed`,自己減少且原因是對方的效果。
    - `attack_negated` / `defense_negated`,使其無效的是對方。
    - `game_ended` 一律聚焦。
  - 本機模式與觀戰者視為「沒有自己」。
  - 金手指(`actor` 為 null)不聚焦。
- `mp_changed` 只在「對方的效果讓某方增減」時列為結果行,自己付費用不列,避免雜訊。
- 說明文字沿用 `logLine(ev)`,不另寫一套模板;卡片的卡圖、中文卡名與效果文取自既有的 `CARDS` / `ZH`。
- 分類(哪些事件是 A、哪些是 B)集中成一張表,放在 `anim.js`。

### D3:停留時間、跳過與追趕

- 標準:每格 1000ms,pass 500ms;快:各減半。每格另加 1.5 秒的逾時保底(沿用現有做法)。
- 聚焦遮罩蓋住盤面,點一下立即結束這一格;盤面在整批播完後才重繪,不會按到過時的按鈕。
- 追趕:`Anim` 記錄排隊中的批數。
  - 排隊 ≥ 2 批時,停留時間改用「快」。
  - ≥ 5 批時,跳過聚焦,只保留最後一批的聚焦。
- 分頁在背景時(`document.hidden`)不聚焦,直接重繪,回到前景後不會補播一長串。

### D4:演出設定

- 頂欄新增「演出」按鈕,開啟小面板:
  - 聚焦:標準 / 快 / 關。
  - 動畫:開 / 關 / 跟隨系統。缺省為跟隨系統,即 `prefers-reduced-motion`。
- 存在 localStorage(`gash-spotlight`、`gash-motion`),變更立即生效。
- `anim.js` 的 `reduced()` 改為 `motionOff()`,讀設定再退回系統偏好。聚焦只看聚焦設定;動畫關時聚焦改為無淡入淡出。
- CSS 原本以 `@media (prefers-reduced-motion: reduce)` 關掉所有 CSS 動畫,會蓋過遊戲內的「動畫:開」。改為由 `app.js` 依 `motionOff()` 切換 `html.motion-off`,CSS 只看這個 class;系統偏好改變時也會重新套用。

### D5:NPC 節奏

- `NPC_QUIET_DELAY` 0.3 → 0.7 秒、`NPC_ACTION_DELAY` 0.9 → 1.3 秒,略長於標準聚焦(pass 500ms、其他 1000ms)。
- 跟不上時由 D3 的追趕處理。

### D6:測試環境

- 既有瀏覽器測試以本機模式操作,本機模式雙方都會聚焦,遮罩會擋住點擊。
- 測試的 page fixture 以 `add_init_script` 預設 `gash-spotlight=off`;聚焦的測試另外開啟。
- `reduced_motion="reduce"` 照舊,讓動畫跳過。

## Risks / Trade-offs

- [聚焦時間計入對手或自己的回合計時] → 標準約 1 秒一格,30 秒計時影響有限;玩家可改「快」或「關」。
- [一批事件很長時(如 S-036 對多隻魔物的傷害)聚焦很多格] → 結果行併入同一格;真的太長時由點擊跳過與追趕處理。
- [分類表遺漏新事件] → 未分類的事件不聚焦,只進行動記錄;新增事件時在分類表補上。
