## Context

金手指位於 frontend/app.js 的 renderCheatFields、cheatRefresh、cheatApply，目前由雙方 JSON textarea 產生 book/mp 請求。既有構築器以全域 B 管理選取與篩選，透過 cardEl 呈現卡圖；builderMutated 會寫入 DeckStore 草稿並執行一般構築驗證。直接開啟構築器會混入牌組儲存與首頁導航，不適用於對局內編輯。

## Goals / Non-Goals

**Goals:**

- 在本機對局內，以卡圖完成雙方魔本逐頁替換、頁位交換與 MP 編輯。
- 共用既有卡圖、篩選概念與頁位呈現，保持對局草稿獨立。
- 保留既有 debug-state API、自由配置、失敗保留內容與成功同步行為。

**Non-Goals:**

- 不加入整本替換、預組／已存牌組載入、匯入匯出或 JSON 編輯。
- 不改一般構築規則，不加入金手指的永久儲存。
- 不修改其他戰局欄位、線上權限或後端 API。

## Decisions

### 1. 對局內大型編輯視窗

以可捲動的大型視窗承載玩家切換、MP、32 頁魔本、卡池與操作列。寬螢幕左右呈現魔本與卡池，窄螢幕上下排列，頁碼與選取狀態保持清楚；開啟期間遮擋一般對局操作。相較沿用小側欄，卡圖更容易辨識；相較跳轉一般構築器，不會引入牌組管理流程。

### 2. 共用呈現，獨立狀態與操作

沿用 cardEl 與缺圖替代處理；將需要共用的卡池篩選／呈現與頁位呈現抽為接受資料及回呼的輔助函式，避免依賴 B 或固定的構築器 DOM。一般構築器保留原本操作與 DeckStore 路徑，金手指持有獨立的雙方 book/mp 副本、目前玩家、每方選取頁及篩選狀態。相較整套複製，可減少卡池邏輯分歧；不進行與本功能無關的全面重構。

### 3. 以替換為主要操作

點頁位選取，再點卡池卡圖替換該頁；完成後保留該頁選取。點另一頁直接切換選取，再點同頁取消選取，不移除卡片；未選頁時提示先選頁，不自行覆寫第一頁。頁位拖曳只在目前玩家魔本內交換兩頁，其他頁保持原位，成功後清除選取。32 頁從伺服器完整載入，不提供刪頁或清空功能。一般構築器的再點移除與點另一頁交換行為不適用金手指，兩者操作回呼分開。

### 4. 明確的草稿生命週期

每次開啟從 GET debug-state 取得最新雙方狀態，載入成功前不可編輯或套用。玩家切換先保留 MP 與卡片修改，不發送請求。取消、關閉或離開房間丟棄記憶體草稿；重新開啟重新讀取。重新整理成功後以伺服器狀態覆蓋雙方草稿並清除選取，失敗保留草稿。普通盤面更新不覆蓋草稿。

套用前只驗證雙方各 32 個有效卡號，沿用 MP 的既有 API 契約，POST 送出雙方 book/mp。請求期間停用會改變草稿的控制及重複提交；成功採用回應作為新草稿並顯示成功，失敗顯示錯誤保留原稿。本機模式沒有持續 WebSocket，POST 成功後使用既有 state 與 events 端點讀回盤面，交由 applyPayload 同步；讀回失敗須區分為「已套用但盤面同步失敗」。關閉編輯器後仍可同步同一房間盤面，但不得改寫新開啟的草稿。非同步回應必須確認仍為同一房間及同一次開啟，避免關閉後的舊回應污染新視窗。

### 5. 沿用最小驗證

金手指不呼叫 validateDeckPages 作為套用門檻，不限制同卡張數、魔物數、首頁／末頁類型或術的頁位。後端仍是卡號存在與頁數的最終裁決；一般構築器維持原本驗證。

## Risks / Trade-offs

- [共用函式影響一般構築器] → 狀態與操作回呼分開，回歸驗證篩選、選牌、移除、交換及草稿儲存。
- [手機卡池與魔本較長] → 響應式排列、可捲動內容，操作列與選中頁提示保持容易找到。
- [草稿期間其他連線改變戰局] → 延續既有整包覆寫契約，使用者可重新整理取得最新狀態；本次不新增衝突合併或版本 API。
- [取消或刷新丟失未套用修改] → 明確按鈕文案說明取消不套用、重新整理覆蓋修改；不以背景更新自動清除草稿。

## Migration Plan

只需部署前端資產，不需資料遷移或後端更新；回退前端即可恢復原 JSON 介面。實作完成後驗證本機成功／失敗流程、線上與觀戰入口限制及一般構築器回歸。
