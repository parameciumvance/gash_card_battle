## Context

前端現況:`render()` 全量重繪(innerHTML 清空重建),狀態更新來自兩條路 — 自己指令的 POST 回應、與 WS 推送(`update` 帶事件批次+快照)。事件帶全域 seq,`appendLog` 已以 seq 去重。佈局為上下兩個 player-zone(head → 場區橫排 → 魔本頁),MP 是文字數字。

視覺目標(探索已定案):鏡像牌桌、魔物+搭檔垂直配對、MP token、四種動畫(翻頁/飛卡/魔力對決/擲硬幣)、魔本主題。

## Goals / Non-Goals

**Goals:**
- 佈局傳達桌面空間感:雙方魔物隔中線對峙、搭檔在魔物身後、魔本最遠。
- 遊戲關鍵時刻有演出;動畫資料源=事件流,本機/對手/觀戰三種來源同一管線。
- 全量重繪架構不動 — 動畫以 overlay 與短暫阻塞窗實現,不引入 DOM diff 框架。
- `prefers-reduced-motion` 完整退場(直接呈現最終狀態)。

**Non-Goals:**
- 音效、卡片插畫重繪、行動裝置直式佈局、構築器互動改版(只吃新視覺語彙)。
- 逐事件輪播重演(棋譜模式)。

## Decisions

### D1. 佈局:對角牌桌 + 固定框格(依使用者回饋修訂)

```
zone-top(對手)  : [搭檔列 → 魔物列](置中)      [魔本對頁+MP托盤](右上角)
battle-stage(中線): 對決舞台(平時發光細線,對決時展開)
zone-bottom(我方): [魔物列 → 搭檔列](置中)      [魔本對頁+MP托盤](左下角)
```

- 場區固定 3 欄:魔物列與搭檔列各自成列、同欄索引垂直配對(搭檔朝己方外側);空欄顯示虛框;搭檔欄與魔物欄同高(150)、搭檔卡與魔物卡同尺寸。
- 魔本區與場區同一橫帶(壓低全場高度),雙方魔本對角相對;雙方魔物列貼中線對峙。
- **框格全固定**:魔物欄/搭檔欄 104×150、對頁頁位、MP 托盤 172×76、盤面卡片(按鈕沉底、超出裁切)皆固定尺寸,不因內容伸縮。MP 托盤疊於魔本前方(朝中線側:對手書下、我方書上),魔本側最小寬度=內容寬,不與場區重疊。
- 魔本對頁恆為兩頁位(pos, pos+1):卡片離開頁面後該頁位顯示壓暗卡背(`/static/back.jpg`);超出書末為虛框空位。
- 視角翻轉邏輯(線上自己在下)不變;疊放魔物(變身後)在魔物卡上顯示堆疊層數角標。

### D2. MP token 托盤

- `mp-tray` 元件:一顆 token = 1 MP(圓形、魔本主題金色),每排 8 顆、滿兩排(16)後折疊為「● ×N」。
- 增減動畫:`mp_changed` 事件觸發 — 增加時 token 從魔本位置飛入托盤,減少時飛出淡出;疊加式不阻塞。
- 數字仍以 tooltip/角標並存(可讀性保底)。

### D3. 動畫層:事件驅動、overlay 實作、混合阻塞

- 新模組 `anim.js`:`playEvents(events, state) -> Promise`。事件批次進來後:
  1. 掃描批次,分為疊加類(fire-and-forget)與阻塞類(依序 await)。
  2. 疊加類立即觸發(翻頁、飛卡、MP token、負傷紅閃)— 盤面同時完成重繪,特效蓋在 overlay 層。
  3. 阻塞類(`coin_flipped`、`showdown`)暫緩 `render()`:先在對決舞台演出(500–800ms),演完才重繪至最終狀態;同批多個阻塞事件依 seq 依序播。
- 事件→動畫對照:
  | 事件 | 動畫 | 類型 |
  |---|---|---|
  | `pages_flipped`/`pages_turned` | 對頁 3D rotateY 書頁翻轉;傷害來源(damage_dealt 相鄰)加紅閃 | 疊加 |
  | `card_played` | 卡片自魔本頁位 FLIP 位移飛至場上欄位,放大後落定 | 疊加 |
  | `mp_changed` | token 飛入/飛出托盤 | 疊加 |
  | `mamodo_injured`/`mamodo_discarded` | 卡片紅閃+橫倒 / 灰化飛向棄牌區 | 疊加 |
  | `coin_flipped` | 中央 3D 硬幣 rotateX 旋轉落定正/反,停留一拍 | 阻塞 |
  | `showdown` | 攻防術卡滑向中線、雙方合計數字滾動、勝方金光/敗方震動 | 阻塞 |
- FLIP 位移:重繪前記錄來源 rect(魔本頁位),重繪後取目標 rect(場上欄位),clone 卡片放 overlay 層做 transform 過渡。
- `prefers-reduced-motion` 或使用者連點(跳過鍵):`playEvents` 直接 resolve,盤面即時呈現。
- 觀戰與對手行動:WS `update` 進來同樣先過 `playEvents` 再重繪 — 三種視角一致。

### D4. 魔本主題

- CSS 變數集中主題色(`--felt`(桌墊)、`--book-red`、`--gold`、`--glow`),深色桌墊底紋(CSS gradient 質感,不引入圖檔)。
- 魔本對頁列包在紅金書皮框(圓角+書脊中縫),對手側同樣書皮但內容為卡背。
- 中線對決舞台:平時為細發光分隔線,`battle`/`battle_in` 存在時展開為舞台區(取代現行 battle-strip 文字條,資訊保留)。
- 卡片 hover 浮起+陰影、可點按鈕統一光效;構築器只吃變數色不改結構。

### D5. 驗證策略

- 後端測試不動(115 綠)。
- headless 瀏覽器 E2E:驗證佈局結構(對手區列順序魔本→搭檔→魔物、我方相反;搭檔槽在正確側;MP token 數量=MP 值;折疊行為)、動畫不破壞流程(打完整場戰鬥、reduced-motion 模式下也通)、對手視角經 WS 收事件時動畫管線無 JS 錯誤。
- 動畫視覺本身以截圖抽查(翻頁中格、對決舞台、硬幣)人工確認。

## Risks / Trade-offs

- [全量重繪與 FLIP 動畫的時序競態(來源 rect 在重繪後即失效)] → 統一入口:`applyPayload` 先量測、後重繪、再播放;阻塞類事件期間暫緩重繪。
- [阻塞窗期間玩家送指令] → 阻塞僅 0.5–0.8s 且按鈕照常可按(指令照發,只是畫面演出稍晚);計時器裁決在伺服器不受影響。
- [動畫 bug 卡死畫面] → 所有阻塞動畫帶 1.5s 硬性 timeout fallback 直接重繪;E2E 以 reduced-motion 與正常兩模式都跑完整局。
- [MP 高值 token 佔版] → 兩排折疊已定案;折疊閾值 16。

## Migration Plan

純前端,單一變更內完成:佈局重構 → MP token → 主題 CSS → 動畫層(疊加→阻塞)→ E2E。無資料、無 API 變更。
