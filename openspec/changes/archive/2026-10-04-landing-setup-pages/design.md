## Context

- 首頁(`#landing`)目前有 6 張入口卡:本機測試、NPC 對戰、建立房間、加入房間、牌組構築、規則。前 4 張直接含表單欄位,各自有「開始」按鈕;`renderLanding()` 一次填好所有文字、選單與按鈕行為。
- 視圖切換由 `show(id)` 在 `landing / waiting / layout / builder` 之間切換;全站只用 `history.replaceState`,不新增瀏覽器歷史。
- 牌組選單由 `deckOptions(sel)` 產生(預組在前、自訂牌組在後,不合法者禁用),缺省是第一個選項(level1)。從構築器返回時會呼叫 `renderLanding()` 刷新選單,所選的值因此被重設。
- 只有暱稱會被記住(`gash-nick`,在 NPC / 建房 / 加入送出時存);本機測試的兩個暱稱不存也不預填。
- 加入連結 `?join=房號`:實作是停在首頁、預填房號,讓加入者先選牌組;規格情境卻寫「自動加入該房」,且沒有測試。
- 直接呼叫 `startLocal()` / `startNpc()` 的測試很多(它們讀 `#deck-local-0`、`#name-npc` 等欄位);點首頁按鈕的只有 `tests/test_npc_ui.py` 與 `tests/test_rules_ui.py`。

## Goals / Non-Goals

**Goals:**

- 首頁一眼看完所有入口,手機上不用捲很長。
- 設定集中在各模式自己的設定頁;建立 / 加入房間合併為「與朋友對戰」。
- 常用的選擇不必每次重選。

**Non-Goals:**

- 手機返回手勢 / 瀏覽器歷史(要連對局中的返回一起設計,另案)。
- 等待對手畫面、構築器、規則頁本身的改動。
- 伺服器與 API 的改動。

## Decisions

### D1:設定頁是一個新視圖,內含三種模式的面板

新增 `#setup` 區塊,加入 `show()` 的視圖清單。區塊頂端是「返回」按鈕與標題(模式名稱),下面是 `#setup-npc`、`#setup-friend`、`#setup-local` 三個面板,一次只顯示一個。`openSetup(mode)` 切換面板並顯示 `#setup`。

- 不用覆蓋層對話框:手機上整頁比較好操作,也和構築器一樣是獨立畫面。
- 不拆成三個視圖:頂端的返回與標題共用,`show()` 只多一個 id。

### D2:首頁入口是按鈕

每個入口改為 `<button class="entry" id="entry-…">`,內含名稱與簡介兩個 `<span>`(按鈕內不放 `h2`,避免不合法的巢狀)。順序:`entry-npc`、`entry-friend`、`entry-local`、`entry-builder`、`entry-rules`。`entry-create`、`entry-join` 移除。按鈕本身可用鍵盤操作,不再另放「開始」按鈕。

### D3:欄位 id 的沿用與合併

- NPC 與本機測試的欄位 id 不變(`name-npc`、`deck-npc`、`deck-npc-opp`、`npc-level`、`name-local-0/1`、`deck-local-0/1`),只是搬進設定頁;`startNpc()`、`startLocal()` 不需改讀取方式,直接呼叫它們的既有測試不受影響。
- 與朋友對戰的暱稱與牌組兩種模式共用,`name-create` / `name-join` 合併為 `name-friend`,`deck-create` / `deck-join` 合併為 `deck-friend`;`timer-select`、`join-code` 沿用。`createRoom()`、`joinRoom()` 改讀合併後的欄位。

### D4:與朋友對戰的建立 / 加入切換

面板上方是兩段式切換(建立房間 | 加入房間),下方依序是:目前模式的說明(沿用 `ui.landing.create_desc` / `join_desc`)、暱稱、牌組、模式專屬欄位(建立:回合計時;加入:房號)、送出按鈕(文字為「建立房間」或「加入房間」)。切換只改顯示,不清除已填的值。

加入失敗(房號不存在、房間已滿)時顯示錯誤並留在設定頁,可直接修正房號再試;原本會跳回首頁,在設定頁流程中等於要重新點入並重填。

- 不採「上下兩區都顯示」:兩種用途擠在一起,加入的人還會看到無關的計時。
- 不採「先選建立 / 加入再進表單」:多一次點擊,而兩者的欄位幾乎相同。

### D5:網址與返回

- 進入設定頁不改網址(維持 `/`);在設定頁重新整理會回到首頁,選擇已被記住(D6),不會遺失。
- `?join=房號`:開啟與朋友對戰設定頁的加入模式並預填房號。按「返回」時把網址換回 `/`(`replaceState`),避免重新整理又回到加入模式。
- 仍不使用 `pushState`(見 Non-Goals)。

### D6:記住上次的選擇

- 存在 localStorage 的 `gash-setup`,內容為各模式的選單值:`npc: {deck, opp, level}`、`friend: {deck, timer, mode}`、`local: {deck0, deck1}`。牌組值與選單的 option value 相同(`preset:<id>` 或自訂牌組 id;NPC 牌組可為 `npc:random`)。
- **在選單變更時就存**,不是開始時才存:玩家可能在設定頁選好牌組後先去構築器看一眼,回來時應保持原本的選擇。
- 與朋友對戰的模式只在玩家自己切換時存;由加入連結打開的加入模式不覆蓋記住的值。
- 還原:選單重新產生後,若記住的值是選單中可選(存在且未禁用)的選項就選它,否則用缺省。牌組被刪除或變得不合法,因此自然回到缺省。
- 房號不記住(每次都不同,記住反而容易誤加入舊房)。
- localStorage 讀寫包在 try/catch 中;不可用時一律用缺省,不影響流程。
- 暱稱維持現行的 `gash-nick`,在開始時才存。

### D7:選單的刷新

`renderLanding()` 仍負責首頁與設定頁的文字,以及所有牌組選單的重新產生;重新產生後依 D6 還原選擇。構築器返回時照舊呼叫它,選擇就不再被重設。直接呼叫 `renderLanding()` 刷新選單的既有測試(`tests/test_npc_ui.py`)照常可用。

### D8:規格修正與現行行為的記錄

- **加入連結**:規格「經連結加入」寫「自動加入該房」,與實作不符。實作停下來讓加入者選牌組比較合理(加入後就開局,沒機會再換牌組),所以以實作為準修正規格:先顯示設定頁並預填房號,加入者按加入後才加入;並補上測試。
- **本機測試的暱稱**:規格「玩家暱稱」寫面板會預填上次的暱稱,但本機測試的兩個暱稱從未存或預填。兩個欄位共用一個記住的暱稱並不合理,維持現行行為,在規格中寫明。

### D9:介面文字

新增 `ui.landing.friend`(與朋友對戰)、`ui.landing.friend_desc`(建立房間邀請朋友,或輸入房號加入)、`ui.setup.back`(返回)。建立 / 加入的切換標籤與說明沿用 `ui.landing.create` / `join` 與 `create_desc` / `join_desc`;NPC 與本機測試的送出按鈕沿用 `ui.landing.go`(開始)。順帶修正:目前 `.entry input` 的大寫顯示也套到暱稱欄,改為只套在房號欄。另外,頂欄的「規則」按鈕在 rules-page 時漏了樣式(顯示為瀏覽器預設按鈕),一併套用與其他頂欄按鈕相同的樣式。

## Risks / Trade-offs

- [開一局多點一下] → 設定頁會記住上次的選擇,通常進去直接按開始即可。
- [記住的牌組指到已刪除或不合法的牌組] → 還原時只選可選的選項,否則回缺省(有測試)。
- [點首頁按鈕的既有測試失效] → 一併改成「點入口 → 在設定頁操作 → 開始」。
- [已分享出去的舊加入連結] → 格式不變(`?join=房號`),只是落在設定頁而不是首頁,仍可用。
- [手機返回手勢仍會離開網頁] → 與現狀相同;設定頁有明顯的返回按鈕,返回手勢另案。
