## Context

- 盤面卡片是固定尺寸:桌面 104×124、魔物欄寬 120;手機 88×112、欄寬 92(`style.css` 的 CSS 變數)。
- 目前負傷是 `.card.injured { transform: rotate(90deg) scale(.82) }`:接近正方形的卡框整張轉過去再縮小,看起來像方塊(專案負責人提供的截圖)。
- 卡圖是整張實卡的掃描(例:465×679,約 0.69),盤面以 `object-fit: cover` 顯示上半部。
- 專案負責人確認的方向:排版維持現狀(卡圖在上、卡名在下,整張轉;卡名側躺),只把卡框改成實卡比例;保留虛線直框與橫卡形成十字。

## Goals / Non-Goals

**Goals:**

- 負傷卡橫放後有實卡的長寬比。
- 虛線直框與橫卡交叉成十字。
- 魔物欄尺寸與相鄰欄位都不受影響。

**Non-Goals:**

- 改變健康卡的尺寸或排版。
- 改變搭檔卡(搭檔不會負傷)。

## Decisions

### D1:旋轉前的卡框改成實卡比例,旋轉後不縮放

- 負傷時卡片改用另一組尺寸,旋轉前:
  - 高 = 魔物欄寬(桌面 120 / 手機 92)
  - 寬 = 高 × 0.716(實卡 63:88)≈ 86 / 66
- 轉 90° 後外觀恰為「欄寬 × 約 0.7 欄寬」,長邊不超出欄位。
- 尺寸以 CSS 變數由 `--cell-w` 推得(`--injured-h: var(--cell-w)`、`--injured-w: calc(var(--cell-w) * .716)`),桌面與手機自動跟著切換,不另寫兩組定值。
- 卡片內部排版不變:卡圖高度沿用 `--art-h`,卡名在下。卡框變窄時,卡圖依 `object-fit: cover` 裁切。
- 替代方案「維持整張轉再縮放」:比例仍接近正方形,就是目前的問題。不採用。

### D2:虛線直框是欄內的獨立元素

- 負傷時,魔物欄內先放一個與健康卡同尺寸的虛線框(沿用空欄虛框的樣式),再放橫卡。兩者都在欄內置中,所以中心自然對齊。
- 旋轉的中心是卡片中心,旋轉前的版面盒(86×120)本來就容得進欄位(120×124),置中即可。
- 虛線框不接收點擊;點擊由卡片處理(放大檢視照常)。

### D3:互動與動畫沿用

- 懸停:`rotate(90deg) translateY(-3px)` 這類組合,保留目前的上浮回饋。
- 使用中描邊、負傷紅閃(`fx-hit`,作用於 box-shadow)隨卡片一起旋轉,不需改動。
- 送墓動畫量的是卡片的外框(旋轉後的外觀),會落在橫卡的位置,不需改動。

## Risks / Trade-offs

- [卡框變窄後卡圖裁切變多] → 仍以卡圖上半部為主(`object-position: top`),與健康卡一致;可接受。
- [手機欄寬 92,橫卡寬也是 92,與相鄰欄只剩欄間距] → 不超出欄位即不重疊;以瀏覽器測試在窄螢幕量測。
