# Design

## Context

- 篩選目前由 `renderCardPoolFilters`(`frontend/app.js`)建三個 `<select>`,構築器(`B`)與金手指共用;篩選狀態是 `ftype` / `fmamodo` / `fproduct` 三個字串,`matchesMamodoFilter` 處理「無」與事件暫停。
- 規則頁已有從卡圖裁出單一圖示的機制:`ART_BOXES`(卡號 + 原圖座標)、`probeArt`(逐張探測卡圖是否可載入)、`.icon-crop`(以 background-size / position 百分比裁切),缺圖時退回文字。`ART_BOXES.type` 正是 M-001 左上的類型徽章。
- 卡圖 465×679,版型一致;插圖區在卡名列(約 y=415)以上。卡圖不進 git:開發時在 `frontend/assets/cards/`,正式站的 `/static/assets/` 對應 volume,不是 repo。
- `cards.json` 的 `sets` 只有前端產品篩選在讀;英文 xlsx 目前也只為 `sets` 被讀取。
- `data/cards_ja.csv` 的 `sets_ja` 格式為「產品　稀有度/販售形式」,以 `|` 分隔;237 張卡都有值。抓取錯誤兩筆:E-024 第二行風味文被當成產品、P-018「TBB　N」實為 TBB2(atwiki 頁標籤「THE BEST BOOSTER 2」)。
- 預組由 `data/decks/*.json` 掃描提供(`GET /api/decks`),構築器「複製起手」、建房與 NPC 牌組選單、NPC「隨機」候選都直接用掃描結果;加預組只需加檔與 `name_key` 翻譯。

## Goals / Non-Goals

**Goals:**
- 構築器與金手指共用一套圖示篩選;圖示資源缺失時功能不受影響。
- 產品分排與魔物順序由一個設定檔決定,調整不需改程式。
- `sets` 只依日文來源產生,轉換工具不再依賴 xlsx。

**Non-Goals:**
- 魔物代表卡的個別指定(全部用預設;要換時再加設定欄位)。
- 魔物插圖的逐張裁切位置調整(一律取卡名列以上的同一區域)。
- 稀有度、販售形式(パック / 自販機 / スターター)的篩選。
- 篩選狀態跨頁面保存。

## Decisions

### 篩選狀態:類型為集合,魔物與產品單選

`ftypes` 為 `Set`(空集合不篩選);`fmamodo` / `fproduct` 為選取的鍵,`null` 不篩選。判斷:類型集合非空時卡片類型須在其中;有選魔物且類型集合不是只有 `event` 時,卡片的對應魔物須為所選(「無」對應指令戰術;事件的對應魔物為空,自然被排除,即使用者選的 B 規則);有選產品時卡片 `sets` 須包含它。魔物篩選停用只在類型集合恰為 `{event}` 時,停用時保留選擇。

- 原本三組都是多選,使用者實際試用後決定只有類型多選。單選時點選即收起網格,按鈕摘要也能完整顯示所選項目的圖示與名稱(多選時只放得下小圖與 `+N`)。

- 替代方案:有選魔物時事件仍全部顯示(A 規則)。使用者選 B:與現行「類型全部 + 選某魔物時不顯示事件」一致,要看事件把魔物清回「全部」即可。

### 篩選列與彈出網格

篩選列一行:4 顆類型徽章是切換按鈕(`aria-pressed`),圖示旁有類型名稱;魔物、產品各一顆按鈕(`aria-expanded`),按鈕內顯示目前選擇的圖示與名稱,未選擇顯示「全部」。網格是篩選列下方的浮層,同時只開一個;點外面、Esc 或再點按鈕收起。網格內每格是圖示加名稱,點選即套用到卡池並收起網格(不需「確定」)。窄螢幕的類型徽章與按鈕改成上圖下字,讓一行放得下。

- 圖示旁留文字是使用者試用後的要求:魔物插圖與產品盒圖不一定認得出來。

- 替代方案:橫向捲動的圖示列。30 個魔物 + 6 個產品太長,且手機寬度只看得到幾個;使用者選彈出網格。

### 圖示裁切共用規則頁的機制

把規則頁的裁切抽成共用函式(卡號 + 原圖座標 → 裁切元素,缺圖時回傳文字標籤),規則頁、類型徽章、魔物圖示都用它。`ART_BOXES` 增加 P-001 / S-001 / E-001 的類型徽章座標(與 M-001 同位置,實作時目視確認)與「插圖區」座標(所有魔物卡共用一個框)。不另外產生裁切後的圖檔:卡圖本來就要載入,裁切圖檔會在正式站的卡圖 volume 之外再多一份要部署的資源。

### 設定檔 `frontend/pool-filters.json`

```
{
  "products": [["level-1"], ["level-2", "mahon-file"], ["level-3", "cardset-gash-nakama", "cardset-zeon"]],
  "mamodo": ["ガッシュ・ベル", "ブラゴ", ...]
}
```

- `products`:每個內層陣列是一排;只列出的產品會顯示,再收錄產品(`tbb1`、`tbb2`、`re`、`file-1`、`level-s`)不列即不顯示。另外照舊只顯示有開放卡片的產品。
- `mamodo`:家族識別鍵(`related_mamodo`)的順序;初始內容依代表卡卡號產生,使用者之後直接調整。沒列出的家族依代表卡卡號接在後面,新彈加入的魔物不會因忘了改設定檔而消失。
- 放在 `frontend/` 而不是 `data/`:這是介面呈現的設定,不是卡片資料;與前端一起部署。

### 產品圖與產品名稱

產品圖取自使用者 Drive 產品照片資料夾(補充包 / 卡組盒照片、魔本ファイル第1弾的照片),長邊縮到 400px 轉 WebP。產品圖放 `frontend/products/<代號>.webp`(進 git,經 `/static/products/` 提供),不放 `frontend/assets/`(正式站該路徑是卡圖 volume)。產品名稱放在介面字典 `product.<代號>`,四種語言都要有;繁中先翻、使用者校對,簡中由 `tools/build_zh_cn.py` 從繁中產生,英文用官方英文名稱或直譯,日文用 atwiki 產品名。

### 產品代號與 `sets` 的產生

`tools/build_cards_json.py` 以產品對照表(日文產品名 → 代號)把 `sets_ja` 轉成代號清單,移除 xlsx 讀取(`load_tts` 與 Sets 欄沿用舊值的邏輯)。對照表沒有的產品名直接報錯:新產品頁抓進來時必須有人決定代號與是否列進篩選。代號為穩定識別,介面字串與圖檔都以它為鍵。兩個カードセット商品的代號加 `cardset-` 前綴(`cardset-gash-nakama`、`cardset-zeon`),與同名的預組 id 區分,也對應商品名中的「カードセット」。

- 替代方案:`sets` 直接存日文產品名。名稱含冒號與中點,不適合當檔名與 i18n 鍵,且需要另一張對照表才能接圖檔與翻譯。

### 抓取錯誤以登記修正

比照「已知的效果文錯誤」,在 `tools/scrape_ja_effects.py` 登記 E-024(最後一段多一行風味文)與 P-018(`TBB　N` → `TBB2　N`),找不到登記的原文時報錯。修正後只重抓這兩張卡(自 `cards_ja.csv` 移除兩列後以卡號範圍重抓),其他列不變。E-024 兩行風味文以換行併入 `flavor_ja`;哪一行屬於哪個版本是推論(第一行標了「(LEVEL:S)」),不影響遊戲行為。

### 「卡片資料轉換」需求的情境直接改主規格

`sets` 規則移到新需求「收錄產品資料」。原「卡片資料轉換」的 `sets` 條目與兩個 xlsx 情境(「新卡的收錄產品取自 xlsx」「卡號在 xlsx 中無對應列」)在 reconciliation 時直接從主規格刪除,「cards.json 不含卡圖連結」情境的「xlsx 的卡圖超連結不讀取」一併拿掉:OpenSpec 的 MODIFIED 不能刪除既有情境,REMOVED 與 ADDED 也不能用同一個需求名稱(已驗證兩者都被 validate 拒絕),而需求名稱是其他文件引用的錨點,不改名。

### 預組

新增 `data/decks/gash-nakama.json`、`data/decks/zeon.json`,頁序取自 atwiki pages/2056、2057 的魔本リスト(已解析確認各 32 頁、卡都已開放),`source` 記來源網址;`name_key` 為 `deck.gash-nakama` / `deck.zeon`,四種語言翻譯。

## Risks / Trade-offs

- [個別卡圖的插圖區位置不同,裁到文字或切到臉] → 版型一致,實作時以全部魔物代表卡目視檢查;真有例外再加逐卡座標(目前不做)。
- [`sets` 值全部改變,依賴英文標籤的測試與既有斷言失效] → 只有前端篩選與少數測試讀 `sets`,一併更新。
- [產品圖缺檔] → 只顯示名稱,功能完整;補圖不需改程式。
- [NPC「隨機」候選多兩個預組] → 屬預期;候選上限 64 不受影響。
- [篩選從下拉改為按鈕,既有瀏覽器測試大量依賴 `select`] → 測試改以新的按鈕操作,篩選邏輯另以純函式測試覆蓋。

## Migration Plan

純前端與資料變更,無伺服器狀態;部署後瀏覽器重新載入即可。篩選狀態不保存,沒有舊狀態需轉換。回滾即還原程式與資料檔。
