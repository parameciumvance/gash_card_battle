## Context

- 伺服器只在房間內有連線:每個房間的 `Room.sockets` 是 `[(websocket, viewer)]`,`viewer` 為 0 / 1 / `"spectator"`;連線在 `room_ws` 接受後加入,`WebSocketDisconnect` 或推送失敗時移除。首頁、構築器、規則頁沒有任何連線。
- 前端開 WebSocket 的時機:線上房建房後等待對手、加入、NPC 對戰、觀戰、重連。本機測試完全不開(由 HTTP 回應更新盤面)。
- 觀戰者共用房間的同一個 `spectator_token`,無法以 token 區分不同的人。
- 房間狀態只在單一行程的記憶體裡;這次不新增任何持久資料。
- 動機見 proposal.md「Why」。

## Goals / Non-Goals

**Goals:** 用現有的連線算出「對戰中」人數,不新增在場偵測機制;首頁顯示並在停留時更新。

**Non-Goals:** 累積人次與持久化;首頁 / 構築器的在場偵測(心跳或全站 WebSocket);對戰與觀戰分開顯示;依 IP 去重。

## Decisions

### D1:計數規則

```text
count = |{(房號, 座位) : 玩家連線}| + 觀戰連線數      (加總所有房間)
```

- 玩家依 (房號, 座位) 去重:同一玩家多開分頁、或重連時舊連線尚未移除,都只算一人。
- 觀戰者依連線數:共用 token,無法再細分;同一人開多個觀戰分頁會多算,可接受。
- NPC 在伺服器內執行、沒有連線,自然不計入。本機測試房沒有連線,也不計入;本機測試是測試工具,不需要為了計數讓它開 WebSocket。
- 等待對手的建房者、對局已結束但還留在結果畫面的人都有連線,照算。
- 計數放在 `RoomStore.online_count()`:`RoomStore` 持有所有房間。
- 替代方案:直接算連線數。更簡單,但同一人多開分頁會重複計算;去重的成本一樣低。

### D2:新端點 `GET /api/online`

- 回應 `{"count": N}`,不需 token,不含房號、暱稱或其他房間資訊,私人房的存在與內容都不外洩。
- 替代方案:放進 `GET /api/meta`。前端只在啟動時抓一次 meta,從對局回到首頁不會更新;meta 的定位是執行環境資訊(卡圖、版本);healthcheck 也每 30 秒打一次 meta。獨立端點才能單獨重新抓取。
- `/api/` 不經前端資源的快取中介層;Cloudflare 預設不快取沒有副檔名的動態回應,不需另外處理快取標頭。

### D3:標籤是「對戰中」而不是「在線」

首頁本身沒有連線,看首頁的人不會算到自己。寫「在線 0 人」會與看的人自己正在線上的事實矛盾。這個數字實際上是「正在對戰或觀戰的其他人」,所以用「目前 N 人對戰中」。觀戰者也算在內,不另外標示。

英文沒有複數處理(`t()` 不支援),以不需要變化的句型表示:`In battle now: {n}`。

### D4:首頁顯示與更新時機

- 位置:`#landing-foot` 最上方、免責聲明之前的獨立一行 `#landing-online`,小字、置中,與版本號行同一套樣式。不放進版本號那一行:版本號行是給在意版本的人看的,人數是給所有玩家看的。
- 文字:N ≥ 1 為 `ui.online.count`(「目前 {n} 人對戰中」),0 為 `ui.online.none`(「目前沒有人對戰」)。顯示 0 而不隱藏:如實告知目前沒有其他玩家,也不會因數字有無造成版面跳動。行首的圓點有人時為綠色,0 人時為灰色。
- 抓取:`show("landing")` 時立即抓取並開始每 30 秒更新;離開首頁(`show` 其他畫面)時停止。`visibilitychange` 變為隱藏時停止;變為可見且仍在首頁時立即抓取並重新開始。
- 尚未取得、或最近一次取得失敗時隱藏這一行:失敗後不留著舊值,也不把失敗當成 0。重新抓取期間(例如回到首頁的瞬間)保留上一次的值,避免這一行每次都先消失再出現。
- 多個請求交錯時(例如快速離開又回到首頁),以序號只採用最後一次發出的請求結果。

## Risks / Trade-offs

- [網路突然斷線時,伺服器要等 uvicorn 的 ping 逾時(約 20 到 40 秒)才移除舊連線] → 期間玩家若已重連,會依 (房號, 座位) 去重;觀戰者可能短暫多算一人。可接受。
- [數字不含停在首頁、構築器的人] → 標籤寫「對戰中」而不是「在線」,語意與實際一致。
- [請求量] → 每個停在首頁的分頁每 30 秒一次,隱藏時不送;計算是記憶體內的迴圈,房間數以百計時仍可忽略。

## Migration Plan

純新增,部署後即生效;回退時舊版前端不會呼叫這個端點。
