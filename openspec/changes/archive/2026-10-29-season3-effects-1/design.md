## Context

範圍與動機見 proposal.md。這批大多可以直接用既有的效果樹節點與登記表實作,以下只記錄需要擴充的地方,以及效果文沒有寫清楚、需要解讀的部分。

既有機制的對應:

| 卡 | 沿用 |

| 香草戰術、Ex-018 / 019(防禦獲勝時無效) | 資料驅動,不註冊(`cards/spells.py` 開頭的清單補上卡號) |
| Ex-014 / 016(反擊) | `spell_rider(counter=True)`(同 S-003;【反擊】需要登記,實作時發現) |

## Goals / Non-Goals

**Goals:**
- 50 張全部依效果文實作並開放,每張非香草卡至少一個依效果文寫的行為測試。
- 新增的機制以一般化的方式加進引擎,供之後的批次使用(例如魔物效果攻擊次數、名稱比對的戰術加成)。

**Non-Goals:**
- 第 3 批以後的卡。
- 改變既有卡的行為。

## Decisions

### D1 白板魔物

- 不註冊任何東西。引擎以「有沒有登記」決定能不能啟動效果,沒有登記就拒絕。
- 前端的效果按鈕與作用中效果都依登記表或卡片資料判斷;白板魔物的 `effect_ja` 為空,放大檢視不顯示效果區塊。
- 實作時先寫測試確認放出、攻擊、作為戰術使用者、拒絕啟動效果都正常;若引擎或畫面有假設「魔物一定有效果」的地方,再修正並記錄。

### D2 「本場遊戲中」時效(M-064)

- 新增 `DUR_GAME`:`_expires_now` 永不到期。
- modifier 綁定魔物槽 UID,魔物離場時已經會一起失效,所以「到該魔物離場為止」不需要另外處理。
- 不沿用空字串 duration:目前空字串剛好也不會到期,但語意不清楚,不依賴這個巧合。

### D3 E-048 依場上魔物數重算

- 新增玩家層級的 modifier 種類 `power_per_own_mamodo`(比照 E-023 的 `power_partnered`):`power_breakdown` 對使用者的每隻魔物加上 `amount × 當下場上魔物數`。
- 時效 `DUR_UNTIL_END_NEXT_TURN`。
- 依 atwiki 卡頁 FAQ(Q1「魔力が必要なときに改めて計算しなおします」、Q2「新たに場に出した魔物は、魔力をふやせる？→ふやせます」),不在使用時選定魔物、也不在使用時固定數值。
- 效果文「自分の魔物すべてを選ぶ」只是描述對象,不因此改成逐隻掛 modifier。

### D4 合計魔力的場上加成(Ex-036)

- 新增登記表 `STATIC_TOTAL_POWER`:`fn(game, player, battle, side) -> int`,在計算合計魔力時加入,明細項目種類 `static_total`。
- 加在合計魔力上,所以魔物效果攻擊(固定合計魔力)也會加:「そのバトルの合計魔力を+2000」說的是合計,不是魔物或戰術的魔力。這是解讀(Inferred),見「行為決定與理由」。

### D5 依戰術名稱的加成與減費(PR-004 / PR-010)

- PR-004:新增 `STATIC_SPELL_POWER` 登記,`side_breakdown` 對使用中的戰術以名稱完全比對(`name_ja == "ザケル"` 且 `related_mamodo` 為ガッシュ・ベル)後加上。
- PR-010:本回合的 modifier `spell_named`(名稱、本來費用增減、魔力增減)。費用在 `_base_spell_cost_items` 以名稱比對後加一項 `base_delta`(不低於 0);魔力在 `side_breakdown` 加上。
- 戰術「屬於ガッシュ・ベル」以卡片的 `related_mamodo` 判斷,和由哪隻魔物使用無關(M-029 可以使用「ザケル」時也適用)。

### D6 限定家族、用一次就消耗的本來費用待命

- 擴充 `spell_bonus` 待命,加入 `base_zero` / `base_delta`:在 `_base_spell_cost_items` 套用(屬於「本来のコスト」,追加費用不受影響),在戰鬥開始(攻擊)或宣告防禦時與魔力加成一起消耗。
- 不另開新的待命種類:`spell_bonus` 已經有「依家族篩選」與攻擊、防禦兩邊的消耗流程(P-007 / M-008)。
- 依既有決定「『このターン中の次のバトル』只作用於下一場」(card-effects design):下一場戰鬥沒有使用對應家族的戰術時,待命隨該戰鬥結束而消失,不留到之後的戰鬥。沿用 `expires="next_battle"`(下一場戰鬥開始時改為 `battle`,戰鬥結束時清除),同 P-007。
- 追加費用照付:依卡頁引用的舊規則官方 FAQ(Ex-011「追加でふやすコストは０にはなりません」),和現行 S-088、最後一頁的處理一致。

### D7 魔物效果攻擊的次數

- `MAMODO_ATTACK` 的登記加 `per_turn`(預設 1)。`used_abilities` 改為計數:以 `mamodo_attack:<卡號>` 的出現次數和 `per_turn` 比較。
- M-068 登記 `per_turn=2`。之後 Ex-026「1ターンに2回まで」的啟動效果也會需要同樣的計數,但那張在第 5 批,這次只做魔物效果攻擊。

### D8 結束階段的場上觸發(PR-011)

- 新增 `END_PHASE` 登記(比照 `START_PHASE`),在結束階段效果的解決流程中執行。
- 結束階段有多個效果時由回合玩家選擇順序(E-041 / E-042 已實作的流程),PR-011 加入同一個清單。
- 觸發條件以 `reg.end_phase(when=...)` 登記,條件不成立時不列入結束階段的效果(不會出現不必要的定序選擇);同一張卡每次結束階段只解決一次。判斷時點是結束階段的效果解決時,在強制翻頁(MP +2)之前,同 E-038。
- 「この効果は、自分のエンドフェイズに自分のMPが1以下なら使える」視為觸發條件,條件成立時自動解決、不詢問。依 M-002「自分のスタートフェイズに、自分のMPが2以下なら」的既有處理;常駐效果的條件不是「〜できる」的可選效果。

### D9 擲幣次數依場上卡數(E-046)

- `Coin.count` 允許傳入函式,在執行時計算。E-046 傳入「自己場上魔物數 + 已裝備的搭檔數」。
- 次數為 0 時不擲幣、MP 不變,事件卡仍視為已使用(效果文沒有使用條件)。這是解讀(Inferred)。

### D10 反擊勝利時才擲幣(S-109)

- `on_win` 是攻擊方獲勝時的掛鉤,不適用。新增 `SpellRider.on_counter`:【反擊】戰術的防方獲勝時取代預設的反擊傷害,由效果樹自行處理到戰鬥結束。S-109 為 `Coin(then=CounterBookDamage(), otherwise=EndBattleWithoutCounter())`;預設的反擊傷害抽成 `engine.counter_book_damage` 共用。
- 時機依效果文「魔力勝負で勝ったとき、コインを投げて」,不在宣告時擲幣(AGENTS.md:效果文明寫其他時機時以效果文為準)。

### D11 被保護時的觸發(S-112)

- `SpellRider` 加 `on_protected`:這個戰術造成的傷害被保護時呼叫,翻對手魔書 1 頁。
- 一次攻擊只翻 1 頁:S-112 的傷害只有一份,保護最多發生一次。

### D14 擁有者的下一個開始階段(M-067)

- 既有的開始階段待命(E-001、S-064)在「下一個開始階段」解決,不分是誰的回合;回合結束時也會清掉比本回合更早建立的待命。
- `NextStartPhase(own=True)` 在待命 data 標記 `own_start`:只在擁有者的開始階段解決,且回合結束的清理不移除它。時效顯示為 `expires="own_start"`。

### D15 使用時機

- 這批的啟動效果都沒有「バトル」圖示,依規則只能在戰鬥外使用,一律 `timing="nonbattle"`(同 M-033 等)。效果文寫「自分のバトルフェイズに」(M-056、Ex-027)另加 `own_turn=True`。
- Ex-007 類比照 P-007:攻防都有作用,不限自己的回合。

### D16 卡號順序(實作中發現)

- 全套測試發現:開放 Ex- 卡後,構築器以字串比較卡號,卡池魔物從 Ex-001 開始、ブラゴ的代表卡變成白板的 Ex-028、未列在設定檔的家族排序也受影響。
- 使用者同意:卡號順序為原有前綴(M- / P- / S- / E-)→ Ex- → PR-,同前綴依編號;前端 `compareCardNumbers` 共用於卡池排序、代表卡與家族排列。寫進 deck-builder「卡池排序」。
- 新家族(ニャルラト、ノリトー・ハッサミー、グリサ、パティ、キッド)依卡號加在 `pool-filters.json` 魔物順序的最後。
- 產品分排的測試原本寫死「拡張シート不顯示」,改為依「有開放卡片的產品」計算。

### D12 同一張常駐效果卡多張在場時疊加

- `STATIC_POWER` 目前對同一卡號只取第一張在場的(`power_breakdown` 的 `break`)。改成每一張各自計入;新增的 `STATIC_SPELL_POWER`、`STATIC_TOTAL_POWER` 同樣各自計入。
- 理由:效果文沒有寫「重複しない」就沒有不疊加的依據(使用者 2026-10-29 決定)。P-003 / P-004 / P-006 的不疊加來自效果文「(この効果は重複しない)」,不是通則。
- 對既有行為沒有影響:同名魔物與搭檔同場限 1 張,目前只有 M-024 有例外,而它沒有常駐魔力效果。PR-003 / PR-004 也受同名限制,一般情況不會有兩張同時在場,這裡是確保之後有例外時行為正確。
- 被「使えない」擋下的那一張不計入,其他張照常計入(目前的 `card_effect_blocked` 判斷保留,只是不再在第一張後停止)。

### D13 需求命名

- 不以批號命名需求(`card-effects-family-requirements`、`split-multi-behavior-requirements` 的整理原則)。
- 開放清單用「第 3 賽季卡片的開放」:之後各批以 MODIFIED 累加卡號,不再每批新增一條。
- 機制寫成獨立需求,以機制命名(必要時括號標代表卡號);其餘解讀併入既有家族需求(ガッシュ・ベル、ウマゴン、キャンチョメ、ウォンレイ),新家族另立(ニャルラト、グリサ),事件卡依卡號命名。

## Risks / Trade-offs

- [風險] 白板魔物是第一批沒有效果的魔物,前端或 NPC 可能有假設「魔物一定有效果文」的地方。
  → D1 先寫測試;自我對戰測試把白板魔物排進牌組跑一輪。
- [風險] `used_abilities` 從集合判斷改成計數,可能影響其他以 `mamodo_attack:` 判斷的地方。
  → 修改前搜尋所有使用處,既有的魔物效果攻擊測試要繼續通過。
- [取捨] 50 張的批次比之前大。
  → 大部分沒有新機制;tasks 依機制分組,每組完成就跑快速測試。
