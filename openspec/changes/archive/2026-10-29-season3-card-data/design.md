## Context

第三彈的資料流程(`2026-10-13-level3-card-data`)沿用至今:
1. `scrape_ja_effects.py` 從 atwiki 商品頁抓 `cards_ja.csv`。
2. `build_cards_json.py` 轉成 `cards.json`。
3. `build_card_texts.py` 產生日文、英文卡片文字。
4. 繁中由翻譯寫入,再用 `build_zh_cn.py` 轉出簡中。
5. `download_images.py` 從 Drive 下載卡圖。

這次的新卡來源和現有格式有幾處不同(用快取的 atwiki 頁面確認過):

| 來源 | 卡 | 與現有格式的差異 |
|---|---|---|
| pages/59 LIMITED EDITION Ⅰ | M-054~058 | 無 |
| pages/58 魔本ファイル | M-059~061 | 需 `--range`;卡頁收錄產品與第1弾同為「別売魔本」 |
| pages/56 スペシャルボックス | M-062~069、S-107~112、P-036~043、E-044~049 | 無 |
| pages/52、53 魔本拡張シート LEVEL:1 / 2 | Ex-001~048 | 卡號是 `Ex-`,現有正規式只認大寫;頁面另有シート1~12 分組重複列出同一批卡 |
| pages/61 特典カード | PR-001~011 | 有 `<li>` 卡號清單,但沒有「収録カード」區塊與類型分類 |

尚未開放的卡不會出現在卡池與產品網格(`deck-builder`「卡池不顯示尚未開放的卡」)。因此這次新增的產品在畫面上暫時看不到,要等之後各批效果實作、卡片開放後才會出現。

## Goals / Non-Goals

**Goals:**
- 95 張卡的資料、文字和卡圖完整收錄,全部尚未開放。
- 產品篩選的設定與呈現先就緒,卡片開放後不必再改。

**Non-Goals:**
- 卡片效果實作,之後分批進行。
- `Ex-000` 與第 4 賽季以後的卡。
- 翻譯校對,由使用者另行進行。

## Decisions

### D1 抓取工具的擴充

- `CARD_LI_RE` 的卡號改為 `[A-Z][A-Za-z]*-\d+`,以接受 `Ex-`。
- 拡張シート頁:`parse_product_page` 只認 魔物 / パートナー / 術 / イベント 四個分類,其他分類(シート1~12)略過,並以卡號去重。
  - 不採用「只取第一次出現」的做法:シート分組也是 `<li>` 格式,若排在類型分類前面,會讓類型變成未知分類。
- 特典卡頁:沒有「収録カード」區塊時,工具改為讀取整頁的卡號清單,分類記為「未知」。
  - 類型改由卡頁資料頭的第一個類型 token 決定。
  - 只在指定 `--untyped` 時才允許這種情況,避免一般商品頁格式改變時被靜默當成無分類。
- 收錄產品沿用卡頁第二段的每一行。新寫法(`LTD1`、`SPBOX|TBB1|RE`、`拡張1　R`、`プロモ`)都適用「取全形空白前的產品名」規則。
- 新卡出現未知的資料頭 token 時照舊報錯,逐一確認後再處理,不先放寬。
- 拡張シート卡頁的版面與既有卡不同(實作時發現):
  - 「X第N の術」「魔物＝X」等尾行印在最後一段開頭。
  - 有些卡沒有風味文。
  - 有些卡有「(スナック)」「(TBB)」兩行風味文。
- 對應方式:最後一段改依內容分類。
  - 開頭的尾行移回效果文。
  - 第一個收錄產品行(產品名在 `PRODUCT_NAMES`,與 `build_cards_json.PRODUCTS` 一致,有測試檢查)之前是風味文,之後是收錄產品。
  - 既有 237 張的解析結果不變(重新轉換後逐卡比對 `cards.json`)。
- 已知錯誤的登記:
  - Ex-005:風味文印在第一段尾行之後,登記 `KNOWN_MISPLACED_FLAVOR`。
  - Ex-002:效果文多一個「,」,登記 `KNOWN_TEXT_ERRORS`。
  - 兩者在來源改變時都會報錯。
- 白板魔物:
  - Ex-001、004、005、006、028、029、030 沒有效果文。
  - 卡片文字的效果文為空字串,涵蓋測試改為「有日文效果文的卡才要求翻譯」。
  - 卡表仍有英文效果名(例如 Ex-001「Strong Resolve」),使用者校對時決定對齊日文:日文 `attr` 為空時英文也為空,`build_card_texts.build_en` 不取卡表的效果名。
- 繁中 `attr` 的《》:
  - 介面以 `ui.card_with_attr` 加上《》,資料本身不帶,與日文一致。
  - 校對時發現部分搭檔卡(P-001、P-008 等既有卡與新卡)的繁中 `attr` 帶《》,一併移除,並加測試檢查。
  - 第 1、2 彈的 P-002~007、P-010~019 日文有效果名而繁中為空,依使用者要求補上譯名(初譯待校對),並加測試檢查繁中與日文的 `attr` 有無一致。

### D2 收錄產品代號

- `PRODUCTS` 依產品發行與系列順序加入新代號:LTD1、SPBOX、拡張1、拡張2、プロモ。
- 魔本ファイル第2弾的處理:
  - atwiki 卡頁把第1、2弾都寫作「別売魔本」,只有商品頁分開列出第1弾、第2弾。
  - 轉換時以卡號區分:`MAHON_FILE_2 = {"M-059", "M-060", "M-061"}` 的「別売魔本」轉為 `mahon-file-2`。
  - 不採用在抓取時改寫 `sets_ja` 的做法:`cards_ja.csv` 應保留來源原文,這只是代號對應。
- `EXPECTED_COUNT` 由 237 改為 332。

### D3 外部來源的 `EX-` 對應

- 卡號一律採 atwiki 的 `Ex-`。
- TTS 卡表與 Drive 卡圖資料夾都寫作 `EX-`,只在讀入這兩個來源時把 `EX-` 前綴換成 `Ex-`。
- 其他前綴不動,也不改 Drive 上的檔名(使用者維護的資料夾)。

### D4 產品篩選的分排與換行

- `pool-filters.json` 的 `products` 每個內層陣列代表一個賽季的系列,不再因為寬度拆排。
  - 第 3 賽季一排有 7 個產品:LEVEL:3、仲間達、ゼオン、LIMITED Ⅰ、スペシャルボックス、魔本ファイル第2弾、拡張シート2。
  - `promo` 自成最後一排。
- 呈現方式:
  - `.filter-row` 改為 `flex-wrap: wrap`,用懸掛縮排表現續行:整排 `padding-left: <縮排>`,第一格 `margin-left: -<縮排>`。
  - 換行點由實際寬度決定,桌面寬度可一行放下時就不換行。
  - 不採用固定「每行 3 格」:桌面上會浪費空間,而且 7 格會留下單獨 1 格的末行。
- 產品圖:
  - 從產品照片資料夾轉檔,長邊 400px,WebP。
  - `limited-1` ← `limited-1-0311.jpg`
  - `special-box` ← `starterset0312-special-box.jpg`
  - `mahon-file-2` ← `mahon-file-2-0311.jpg`
  - `ex-sheet-1` / `ex-sheet-2` ← 「魔本拡張シート LEVEL：1 / 2.jpg」(2026-10-27 更新的版本,不用「+」版)
  - `promo`:以 PIL 產生「PR」字樣的方形圖,配色取自介面的強調色。
- 產品名稱 `product.<代號>` 補四語(zh-CN 由轉換產生):
  - 繁中(使用者校對後):LIMITED EDITION Ⅰ、SPECIAL BOX、魔書卡本 第二彈、魔書擴充片 LEVEL:1 / 2、特典卡。

### D5 前端卡號格式

- `app.js` 的 `cardRefs` 與 `anim.js` 的 `CARD_NO` 原本是 `^[EMPS]-\d{3}$`,改為 `^(?:[EMPS]|PR|Ex)-\d{3}$`。
- 新卡現在都尚未開放,不會出現在對局中。但這兩處決定行動記錄能否辨認卡號、動畫的來源卡,趁資料進來時一起改,避免之後實作效果時遺漏。

### D6 翻譯

- 沿用第三彈的做法:
  - 英文卡名取自 TTS 卡表(經 D3 對應)。
  - 英文效果文、繁中卡名與效果文依 `effect_ja` 起草,標為初版待校對。
- PR 卡與既有卡同名(例如 PR-001 ガッシュ・ベル)時,卡名沿用既有譯名。

## Risks / Trade-offs

- [風險] 新卡的資料頭出現未知 token 或新的版面(例如 PR 卡的特殊格式),抓取報錯。
  → 依既有原則逐一確認;確定是頁面漏刊時登記 `KNOWN_DATA_GAPS`,並在 tasks 記錄。
- [風險] atwiki 有反爬限制。
  → 開發環境目前可直接抓;已存在的卡號會跳過,可分批續抓。
- [風險] 新卡的卡圖在 Drive 缺檔或非公開。
  → 照舊列入 `_failed.txt`,以文字卡面顯示,並在交付時列出缺圖清單。
- [取捨] 新產品在卡片開放前看不到,產品圖與分排要等之後才能目視確認。
  → 用測試替身清空尚未開放清單,在瀏覽器測試驗證分排與換行縮排。
- [取捨] 95 張的翻譯量大,初版品質有限。
  → 依第三彈慣例先歸檔,翻譯維持初版待校對,不阻擋後續效果實作。

## Migration Plan

- 資料檔只有新增卡號,不影響既有魔書與預組。
