## Context

- 目前的顯示:
  - 頂欄:「第 N 回合|回合玩家」、階段名、「輪到 X 行動」。
  - 玩家區塊:等待輸入的一方有綠色外框(`renderPlayerZone` 的 `active`)。
  - 行動欄:只有玩家名與 Pass / 翻頁 / 迎戰 / 不防禦等按鈕。
- 規則書的時機:
  - 開始階段:回合玩家翻頁。
  - 戰鬥階段:
    - 非戰鬥中:輪流行動。可放卡、使用場上效果;「自己的回合」圖示的卡只有回合玩家能用,「對手的回合」圖示的卡只有非回合玩家能用;宣告攻擊只有回合玩家。
    - 戰鬥中:戰鬥開始確認 → 防禦 → 效果使用(只能用帶「戰鬥」圖示的效果)→ 魔力勝負 → 傷害。
  - 結束階段:自動處理,只有「魔物消失處理」需要玩家選頁時會停下。
- 快照裡能判斷目前時機的欄位:`phase`、`battle_in`、`battle.step`、`pending`、`turn_player`、`action_player`。結束階段沒有自己的 `phase` 值(引擎在結束處理期間 `phase` 仍為 battle),停下時由 `pending.kind == "deploy_page"` 判斷。
- 放大檢視的行動按鈕由 `zoomActions(ctx)` 產生,每個按鈕帶 `disabled`,已含 MP、時機、圖示等前端判斷。

## Goals / Non-Goals

**Goals:**

- 「誰的回合」「現在的時機」「輪到誰、能做什麼」三件事分開、一眼可見。
- 所有判斷都從快照推得,不改伺服器。

**Non-Goals:**

- 前端的合法性判斷變得更精確(仍以伺服器為準;發光是提示)。
- 教學式的逐步引導。

## Decisions

### D1:時機由快照推得,集中成一個函式

`currentTiming()` 回傳目前這一步,供時機指示、行動欄摘要與詳細提示共用:

```text
game_over                          → over
pending.kind == deploy_page        → end
phase == start                     → start
battle_in                          → battle_in    (戰鬥中:開始確認)
battle.step == defense             → defense      (戰鬥中:防禦)
battle.step == effects             → effects      (戰鬥中:效果)
其他                                → nonbattle    (非戰鬥中)
```

中途決策(pending)期間仍顯示發生決策的那一步。

### D2:時機指示放在中線

- 中線(`#battle-stage`)上方加一列步驟,目前這一步亮起。
- 戰鬥中時,步驟列之下照常顯示原本的攻防內容。
- 窄螢幕時只完整顯示目前所在的大段(例如「戰鬥中:開始確認 → 防禦 → 效果」),其餘縮短,避免換行過多。

### D3:區塊標示

- 回合玩家記號:`renderPlayerZone` 在名稱旁加上記號(依 `turn_player`)。
- 「行動中」標籤沿用現有的 `active` 判斷(等待輸入的一方)。
- 輪到自己時(`active` 且 `iControl`),行動欄加上醒目樣式。

### D4:行動欄摘要與詳細提示

- **摘要**:依 `currentTiming()`、等待輸入的玩家與回合玩家組成。
  - 輪到自己:「輪到你(<你的 / 對手的>回合・<時機>)」。
  - 輪到對手:「等待 <名稱> 行動(…)」。
  - 本機測試模式與觀戰以玩家名稱稱呼。
- **詳細提示**:依時機與「是否回合玩家」取 i18n 條目,內容對應規則書的表:
  - `hint.nonbattle.turn`:放卡、場上效果、「自己的回合」圖示的卡、宣告攻擊、Pass。
  - `hint.nonbattle.other`:放卡、場上效果、「對手的回合」圖示的卡、Pass。
  - `hint.battle_in`:迎戰,或插入 1 個行動使確認失效。
  - `hint.defense`:點帶「防禦」圖示的術宣告防禦,或不防禦。
  - `hint.effects`:只能使用帶「戰鬥」圖示的效果,或 Pass。
  - `hint.start`:翻 0~3 張,每張 MP +2。
  - `hint.end`:選擇要放出的魔物。
- 展開 / 收起按鈕放在摘要旁,狀態存 localStorage(`gash-action-hints`),缺省收起。

### D5:可用卡發光

- 渲染場上魔物、夥伴與魔本翻開頁時,對可操作的一方(`iControl`)以 `zoomActions(ctx)` 取按鈕,有任一個未停用就加上 `usable` 樣式。
- 觀戰者 `iControl` 恆為假,自然不發光。
- 代價是每次重繪多算一次按鈕,卡數少(最多 3 + 3 + 2 張 × 2 方),可接受。

### D6:回合開始橫幅

- `anim.js` 的時間軸遇到 `turn_started` 時,不論 `actor`,都插入一格「回合開始」(只看聚焦設定;關時不顯示)。停留時間同 pass(一半)。
- 文字:回合玩家是自己時為「你的回合」,否則為「<名稱>的回合」。
- `turn_started` 從文字聚焦的分類中移除,避免重複。
- 同一批裡橫幅之前的結果行不受影響;橫幅自成一格,之後的事件另起一格。

### D7:實作中的調整

- **放大檢視按鈕的判斷補強**:發光與按鈕共用判斷,原本的判斷會讓不能用的卡發光,所以補上:
  - 夥伴卡:對應魔物不在場上、或已裝有夥伴時停用。
  - 事件卡:「對手的回合」圖示的卡在自己的回合停用(原本只檢查「自己的回合」圖示)。
  - 魔物卡不判斷場上是否已滿:M-007 / M-010 / M-027 可以疊放,前端無從得知哪些卡能疊放,以伺服器為準。
- **開局也有回合開始橫幅**:開局的事件含第 1 回合的 `turn_started`,所以一進對局就顯示誰先攻。
  - 聚焦的瀏覽器測試改為先等開局橫幅播完再操作。
  - `Anim` 新增 `idle()`(目前排隊的播放全部結束時完成),供測試使用。
- **中線不可被壓扁**:窄螢幕時盤面比視窗高,`#board`(直向 flex)會壓縮可壓縮的子項;中線原本只有 4px 最小高度,時機指示會溢出蓋到玩家區。改為 `flex-shrink: 0`。這也修正了手機上戰鬥中對決舞台可能被壓扁的既有問題。

## Risks / Trade-offs

- [前端判斷可用與伺服器不一致,發光的卡被拒絕] → 與放大檢視按鈕同一套判斷,不一致時兩者一起錯,修一處即可;伺服器仍為裁決。
- [窄螢幕中線高度增加] → 步驟列只佔一行小字;縮短非目前的大段。
