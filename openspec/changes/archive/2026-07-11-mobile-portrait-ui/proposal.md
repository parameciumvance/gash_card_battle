# Proposal: mobile-portrait-ui

## Why

standalone-release 讓玩家 B 點連結即可加入,而 B 最可能用手機開——目前 UI 為 ~1500px 桌面設計(零響應式 media query),手機直向(360–430px)完全不可用。需要手機直向可完整遊玩的盤面與構築器。

## What Changes

- **手機直向盤面**:窄螢幕(直向)改為縱向堆疊,由上而下:對手魔本(對頁+MP)→ 對手搭檔列 → 對手魔物列 → 中線 → 我方魔物列 → 我方搭檔列 → 我方魔本(對頁+MP)。魔物在中線對峙。卡片與框格改用 CSS 變數定義的手機尺寸組(仍為固定尺寸,不彈性伸縮);盤面可縱向捲動,action-bar 維持 sticky。
- **行動按鈕統一移入放大檢視**(桌面與手機一致,**BREAKING** 互動變更):盤面卡面不再有任何行動按鈕;點卡開啟放大檢視,檢視內呈現完整資訊 + 該卡實例此刻可用的行動按鈕。全域行動(翻頁/pass 等)仍在 action-bar。狀態更新時開啟中的檢視同步刷新。
- **行動記錄改為可展開抽屜**(窄螢幕):log 側欄在手機摺疊為底部頁籤/抽屜;桌面維持側欄。
- **構築器手機直向**:上下分割——上半魔本 16 對頁(縮小、可捲動)、下半卡池(篩選器收合為一列);點選互動不變,拖拉維持桌面。
- 觸控目標:放大檢視內的行動按鈕與對話框選項在手機達到足夠觸控尺寸。

## Capabilities

### New Capabilities
(無)

### Modified Capabilities
- `battle-ui`: 「盤面呈現」增加窄螢幕直向堆疊佈局;「卡圖與文字卡面」行動按鈕自卡面移除、改於放大檢視內呈現與操作;「行動記錄」窄螢幕改為抽屜;「操作與決策互動」卡片層級操作入口改為放大檢視。
- `deck-builder`: 「對頁編輯」增加窄螢幕上下分割佈局(魔本上/卡池下、篩選收合)。

## Impact

- **程式碼**:`frontend/style.css`(尺寸抽 CSS 變數 + 直向 media query 佈局)、`frontend/app.js`(zoom 檢視改為「卡片實例 + 行動」面板、卡面按鈕移除、log 抽屜、盤面堆疊渲染順序)、`frontend/decks.js` 與構築器相關樣式。
- **後端**:無(純前端;快照/指令協定不變)。
- **互動變更**:桌面玩家原本卡面一鍵行動 → 改為點卡兩段式(開檢視 → 按行動)。防禦/決策對話框不受影響。
- **不變**:桌面寬螢幕的鏡像對角佈局、固定尺寸哲學(改為兩組定值)、i18n、動畫管線(FLIP 量測點需隨 DOM 結構調整驗證)。
