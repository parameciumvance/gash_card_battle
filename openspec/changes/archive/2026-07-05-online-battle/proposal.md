## Why

v1 只能同機雙人(hotseat)。要讓兩位玩家各自從自己的瀏覽器約戰,需要玩家身分、即時推送與斷線重連;同時 hotseat 掩蓋了一個規則層問題——實體遊戲中魔本翻開頁對對手是保密的(使用時才展示,E-014/M-011 的「檢視」效果即為此而存在),v1 的全知快照在線上會變成開 DevTools 即可看穿對手手牌。線上化必須一併補上「每位觀看者一個視角」的資訊模型。

## What Changes

- 新增房間系統:建房產生房號/加入連結與玩家 token,對手 join 後開局;無帳號、無配對,房號約戰。指令改由 token 判定玩家身分(**BREAKING**:指令不再信任 payload 中的 `player` 欄位)。
- 新增視角化資訊過濾(API 層,引擎不動):`snapshot(game, viewer)` 對非持有者隱藏翻開頁的卡片內容;含 viewer 標記的事件(檢視魔本/偷看頁面)與決策選項只送給當事玩家;觀戰者只見公開資訊。
- 新增 WebSocket 事件推送;斷線重連沿用既有 `state + events?since=N`(事件序號機制)。
- 新增回合計時器(房間選項:關/30/60/120 秒每動作):逾時由伺服器代送安全預設動作(pass/不防禦/讓過/不庇護/保留硬幣結果),對局不卡死、不判負。
- 新增觀戰模式:觀戰連結進房,純公開視角,人數不限。
- 前端改版:首頁兩個入口(本機對戰/建立房間);線上模式「自己在下方」的視角翻轉、只能操作自己的行動、連線狀態與計時顯示。本機(hotseat)模式保留現行全視角行為。
- 不含:帳號系統、配對/排名、聊天、對局持久化(伺服器重啟即失局,文件註明)。

## Capabilities

### New Capabilities
- `online-room`: 房間生命週期——建房/加入/開局、玩家與觀戰者 token 身分、回合計時器與逾時代打、斷線重連語意。

### Modified Capabilities
- `battle-api`: 指令身分改由 token 判定;狀態快照與事件依觀看者過濾(翻開頁對非持有者隱藏、決策選項只送決策方);新增 WebSocket 推送通道。
- `battle-ui`: 新增首頁入口(本機/建房/加入);線上模式視角翻轉與操作權限、連線狀態、計時顯示;本機模式維持現行為。

## Impact

- 受影響程式碼:`src/gash/api/`(房間管理、視角過濾、WS 端點、計時器)、`frontend/`(入口頁、視角、WS client)。`src/gash/engine/` 不變更(事件已帶 viewer 欄位,過濾在 API 層即可完成)。
- 新增相依:無(FastAPI 原生支援 WebSocket;前端原生 WebSocket API)。
- **BREAKING**:`POST /api/games` 直接建局的舊介面由房間流程取代;指令的 `player` 欄位改為伺服器端由 token 推導(本機模式由本機 token 對映)。既有測試需隨 API 介面調整。
- 對局仍存於記憶體;單一伺服器行程,無水平擴展考量。
