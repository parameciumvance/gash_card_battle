# Design

## Context

- 保護:`_protect_choice` 建立 `pending(kind="protect")`,選項為「不保護」與可保護的魔物;`pending.info` 目前只有 `damage`(`_damage_info`)。選擇後由 `_handle_choose` 結算:保護的魔物承受傷害(健康 → 負傷,已負傷 → 棄掉),`_maybe_discard_protector` 處理 P-012「保護的魔物直接棄掉」,其他卡的保護 / 棄掉時效果也在這條路徑上。`pending.info` 是現有的公開決策脈絡,快照只給決策者(`views.py`)。
- 翻頁:`end_flip_loses(game, player)` 以目前的 `pos` 判定;開始階段的翻頁按鈕由前端依魔書翻閱位置產生(battle-ui「開始階段依魔書翻閱選擇翻頁張數」)。
- 預估魔力:`spell_power_preview` 建一個不掛到狀態的假設戰鬥,呼叫 `side_breakdown`。宣告時的戰術自身加成(S-016 / S-017 / S-092 的 `AddAttackSelfBonus` 等)實戰時寫進 `battle.data["<side>_spell_power"]`,`side_breakdown` 會加總,預估時這一項是空的。
- NPC 已經有 `npc/settle.py` 的 `clone(game)`:複製狀態(含 rng)在副本上送指令。

## Goals / Non-Goals

**Goals:** 保護前知道哪隻會離場與原因;翻頁前知道會不會因此落敗;預估魔力含確定的宣告時加成。

**Non-Goals:** 不列「之後將無法使用的戰術」、不提示只會負傷的結果、不擴及其他決策種類(棄掉魔物、效果對象)——使用者決定只做會離場或可能敗北的情況。不改規則與卡片效果。

## Decisions

### D1 保護後果以副本實際結算判定

對每個保護選項:`clone(game)` 後在副本上 `choose(該魔物)`,看保護的魔物最後是否還在場上;不在時從副本發出的事件取原因(棄掉事件的 `reason` 與來源卡;已負傷再受傷為「已負傷」)。
- 用實際結算而不是逐條規則推算:雪莉與之後新增的「保護時 / 棄掉時」效果都自動涵蓋。這次的 bug 正是「只看負傷狀態」漏了卡片效果。
- **不確定時不標示**:以兩個不同的 rng 種子各跑一次,結果不同(取決於擲硬幣)就不標示;副本停在新的決策(例如其他效果要玩家選擇)而保護的魔物還在場上時,也不標示。只在「確定離場」時標示。
- 副本不會影響實際狀態與 rng(`clone` 複製 rng 後另設種子)。
- 計算放在建立保護決策時(`_protect_choice`),結果寫進該保護選項本身(`options` 的項目加 `leaves: true` 與 `leave_reason`:`"injured"` 或來源卡號)。不放 `pending.info`:快照的 `info` 對所有視角公開,`options` 才只給決策者。保護的選項通常 1–3 個,每個跑兩次副本,成本可接受;強制保護(Ex-047)不詢問,不計算。
- 替代方案:逐條規則推算(負傷 + 已知的離場效果)。每張新卡都要記得補,漏了就再出現同樣的問題。

### D2 翻頁後落敗:推廣 `end_flip_loses`

新增 `end_flip_loses_after(game, player, flips)`:以 `pos + 2 × flips` 代替目前的 `pos`,其餘條件相同(回合玩家、未結束、沒有 `skip_end_flip` 待命);原本的 `end_flip_loses` 改為呼叫它(`flips = 0`)。開始階段輪到回合玩家時,快照該玩家附 `flip_end_loses`(依張數 0…可翻上限的布林陣列)。只依公開資訊,所有視角都可以有,但只在開始階段、回合玩家身上附。

### D3 預估魔力的確定宣告加成:在戰術的宣告時效果樹上做預覽求值

`spell_power_preview` 建假設戰鬥後,對該戰術的 `on_declare` 樹做唯讀的預覽:
- `When(cond, then)`:`cond` 在假設戰鬥上求值;只支援不需要隨機或選擇的條件(`SideIs`、`OpponentUsedAttrLastTurn` 等依公開狀態的條件)。
- 自身魔力加成節點(`AddAttackSelfBonus`、`AddDefenseSelfBonus`、`AddSpellSelfBonus`)產生與實戰相同的明細項,寫進假設戰鬥的 `<side>_spell_power`。
- 遇到 `Coin`、`Choose` 等需要隨機或選擇的節點,不往下走(其下的加成不算)。
- `Sequence` 依序處理;其他節點略過(不影響魔力)。
- 明細項沿用實戰的格式,前端以既有的明細文字顯示,標示來源戰術與「攻擊時 / 防禦時」。
- 替代方案:在副本上實際宣告攻擊再讀魔力。宣告會觸發擲硬幣與各種選擇,要處理中斷與隨機,比在固定幾種節點上求值複雜得多。
- 目前涵蓋 S-016、S-017、S-092、Ex-043(依對手上一回合是否用過該屬性)。S-040、S-108 在擲硬幣下,不算。

### D4 前端

- 保護警告:`cardMenuButtons` 產生保護目標的「選擇」時,依該選項的 `leaves` / `leave_reason` 在按鈕上方加 `.card-menu-warning`;詳情面板(`setDetail` 的內容)同樣顯示。原因文字:`injured` →「已負傷」,卡號 →「{卡名} {卡號}」。
- 翻頁加註:產生「翻 N 張」/「不翻頁」按鈕時,`flip_end_loses[N]` 為真則在按鈕旁加醒目說明。
- 預估魔力:附註鍵 `ui.zoom.power_preview_note` 改為「不含擲硬幣與戰鬥中的效果」(四語);新的明細種類若需要文字,沿用 `breakdown.*` 的格式。

## Risks / Trade-offs

- [副本的結算用到對手的隱藏資訊(例如對手魔書的頁)] → 只回報保護的魔物是否離場與原因;這是保護後就會公開的結果,不回報副本中的其他資訊。若之後出現「離場與否取決於隱藏資訊」的效果,兩次 rng 不會讓它變得不確定,需要另外檢查(目前沒有這種卡)。
- [副本與實際結算不一致] → 共用同一條結算路徑;測試以「預告會離場的,實際選擇後確實離場」逐項比對。
- [效果樹新增節點時預覽不認得] → 預覽只認列舉的節點,不認得的略過,最多是少算加成(回到原本的行為),不會多算。測試涵蓋「與宣告後實際的合計魔力相同」。
