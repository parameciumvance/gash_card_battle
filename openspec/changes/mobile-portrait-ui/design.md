# Design: mobile-portrait-ui

## Context

前端無框架、全量 re-render(`render()`)+ FLIP 動畫;style.css 僅一條 media query(reduced-motion),盤面卡固定 104×150、log 側欄固定 300px、魔本側 `min-width: max-content`,設計目標 ~1500px。使用者已確認:直向堆疊序(對手魔書→搭檔→魔物→我方魔物→搭檔→魔書)、構築器上下分割、**行動按鈕統一(桌面同步)移入放大檢視**。

放大檢視(#zoom-card)現為純展示、只知卡號;卡片行動按鈕散在 `cardEl`/`slotEl`(出術、放置、攻擊、魔物攻擊、效果等)並依 `canActNow` 過濾。

## Goals / Non-Goals

**Goals:**
- 手機直向(360–430px)完整打完一場 + 完整構築一副牌。
- 桌面/手機共用一套 DOM 與互動模型;桌面寬佈局視覺不變(按鈕移入檢視除外)。
- 保留「框格固定尺寸」哲學:兩組定值(桌面/手機),不彈性伸縮。

**Non-Goals:**
- 橫向手機佈局最佳化(直向為準;橫向落在桌面佈局的縮小版即可)。
- 手勢操作(滑動翻頁等)、PWA/離線、原生 app。
- 觀戰/等待頁的深度手機化(隨主佈局自然適配即可)。

## Decisions

### D1. 尺寸抽 CSS 變數,media query 只切變數值

`:root` 定義 `--card-w/--card-h/--art-h/--gap-*` 等(桌面=現值 104/150/75);`@media (max-width: 700px)` 覆寫為手機組(約 88×127/64)。所有寫死 104/150/75 的規則改引變數。固定尺寸哲學不變,只是有兩組定值。

替代:transform scale 整體縮放——文字小到不可讀,否決;彈性尺寸——回到抖動問題,否決。

### D2. 直向堆疊:CSS 重排為主,DOM 順序微調為輔

窄螢幕下 `.zone-body` 改 `flex-direction: column`,以 `order` 重排各 block:對手 zone 內魔本區排最前、場區(搭檔列在魔物列上方)排後;我方 zone 相反,魔物列緊貼中線。魔本區與 MP 托盤同列置中。若純 CSS `order` 不足(現 DOM 為左右 zone-side 結構),允許 `renderPlayerZone` 依 `isNarrow()`(matchMedia)輸出不同容器結構——但渲染函式與子元件(`renderBookBlock`/`renderFieldBlock`)共用,只變組裝。

盤面允許縱向捲動;action-bar 維持 sticky bottom;FLIP 動畫量測在 re-render 前後照常工作(Anim 以 DOM rect 量測,與佈局無關),實作後以 E2E 驗證。

### D3. 行動按鈕統一入放大檢視(桌面+手機一致)

- `cardEl`/`slotEl` 不再渲染 `.btns`;卡片 click = 開放大檢視。
- 放大檢視改為「卡片實例面板」:開啟時傳入**實例上下文**(如 `{kind:"slot", p, idx}`、`{kind:"page", p, page}`、`{kind:"partner", ...}`),按鈕生成邏輯自 `slotEl`/`cardEl` 原位遷移,依同樣的 `canActNow`/合法性過濾;按下即送指令並關閉檢視。
- 純展示場合(卡池、記錄、魔本檢閱、對手卡背)開啟的檢視無按鈕區,行為同現狀。
- **狀態更新時**(WS/指令回應觸發 re-render):開啟中的檢視依實例上下文重取快照刷新按鈕;實例已不存在(卡離場)則自動關閉。
- 防禦/庇護/選擇等決策維持既有對話框(#dialog-options),不併入檢視。
- 手機上檢視為近全螢幕、按鈕 ≥44px 觸控高度;桌面維持現有置中卡窗+按鈕列。

替代:手機限定雙路徑——兩套按鈕邏輯並存、卡面仍要容納按鈕,否決(使用者已選統一)。

### D4. log 抽屜(窄螢幕)

窄螢幕下 #log-panel 改為固定於 action-bar 上方的收合抽屜:平時一列頁籤(顯示最新一條),點開為半屏高、可捲動,再點收合。桌面不變(300px 側欄)。純 CSS + 一個 toggle class,不動 log 渲染邏輯。

### D5. 構築器上下分割(窄螢幕)

`#builder` 兩欄(46%/54%)改為上下:上=魔本對頁網格(縮小卡、約 4 對頁一行、獨立捲動),下=卡池(篩選器收合為一列橫向下拉 + 展開鈕、網格捲動)。點選放卡/移除/兩點互換照舊;drag 維持桌面。合法性提示列固定於分割線或頂部可見處。

### D6. 斷點與偵測

單一斷點 `max-width: 700px`(直向手機與極窄視窗);JS 端以 `window.matchMedia("(max-width: 700px)")` 提供 `isNarrow()`,監聽變更觸發 re-render(桌面拉窄視窗即可測試,E2E 以 viewport 375×812 驗證)。

## Risks / Trade-offs

- [桌面多一次點擊(開檢視→按行動)] → 使用者已權衡選擇統一;檢視開啟輕量(無動畫延遲)、按下即關,把成本壓到最低。
- [zoom 改實例面板是本案最大重構,按鈕合法性邏輯遷移易漏] → 逐按鈕對照既有 `slotEl`/`cardEl` 生成條件遷移;E2E 覆蓋主要行動(出術/放置/攻擊/效果)在檢視內可用且卡面無按鈕。
- [FLIP/翻頁動畫在新 DOM 結構下量測失準] → Anim 量測基於元素 rect 與 key,結構無關;直向佈局下 E2E + 人工目視驗證,異常則對 narrow 模式降級為淡入。
- [6 列堆疊超出視窗高度需捲動] → 中線置中設計 + sticky action-bar;魔書在頂/底端,捲動查看符合「翻自己書」的心智模型。
- [對話框/檢視在小螢幕溢出] → 對話框與檢視設 `max-height` + 內捲。

## Migration Plan

純前端漸進:先 D1(變數化,桌面零視覺變化)→ D3(按鈕入檢視,桌面互動變更點)→ D2/D4(直向佈局)→ D5(構築器)。每步桌面 E2E 回歸。回滾=還原前端檔案。
