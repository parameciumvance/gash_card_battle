# Design

## Context

見 proposal。

- **規則依據**:規則頁「アイコン」寫明「バトル:このアイコンがついた効果は、バトル中の『効果の使用』で使う(非バトル中には使えない)」;「③効果の使用」寫明「攻撃側も防御も、バトルアイコンのついた効果を使うことができます」;「③魔本にあるカードの効果を使う」寫明事件卡從今のページ使用。
- **目前的引擎**:戰鬥中的 `STEP_EFFECTS` 只接受 `use_field_ability` 與 `use_borrowed_effect`;`_use_book_card` 不看戰鬥圖示。
- **既有先例**:E-036 / P-034 依「限制的分類」取除持續或待命中的效果,被取除的效果整個取除。

## Decisions

### D1:戰鬥中使用魔書的事件卡(E-053)

**引擎的時機判斷**
- `STEP_EFFECTS` 輪到的玩家可以送 `use_book_card`,但只限今のページ上有戰鬥圖示(`effect_icon == "battle"`)的事件卡。
- 之後的處理比照 `use_field_ability`:效果的 pass 計數歸零。沒有 pending 時換對方;有 pending(保護選擇、干擾詢問)時,等決策解決後再換(`pending_flip`)。
- `_use_book_card` 對有戰鬥圖示的事件卡,在非戰鬥中與バトル・イン確認時一律拒絕(`event.timing`)。

**照舊適用的規則**
- A/D 欄:E-053 是 D,只有非回合玩家,也就是防禦方能用。
- 其他照舊:每回合事件卡張數、「不能使用事件卡」的限制、費用、M-032 / Ex-034 的干擾(快照還原)。
- 待研究:規則頁「バトル中には『バトル効果』『バトル防御』『バトル』アイコンが付いた効果しか使えません」,干擾圖示不在其中,M-032 / Ex-034 可能不能在戰鬥中干擾 E-053(使用者 2026-11-08 提出)。同一原則也牽涉 M-026(戰鬥中的魔物效果與魔物效果攻防,既有決定依規則書第 42 頁)與 M-065。使用者決定這次先照常提供,之後另行研究。

**前端與 NPC**
- 前端:戰鬥中的「効果の使用」輪到自己時,今のページ上有戰鬥圖示的事件卡顯示「使用」按鈕;非戰鬥中這類卡的按鈕停用,理由是 `ui.why.battle_only`。
- NPC:戰鬥中的候選加入這類事件卡。

### D2:E-053 的效果

1. 選自己場上的 1 隻魔物(`OwnMamodo`),以 `cause: effect` 造成 1 次傷害,走一般傷害流程:
   - 可以由自己其他魔物保護(使用者決定:規則頁的「かばう」沒有限定傷害來源)。
   - 「かばうことができない」的限制照常作用,例如 E-013 的待命套用時,使用者的對手不能保護。
2. 傷害流程結束後(含保護選擇),使這場戰鬥的攻擊無效(`NegateAttack`)。
   - 「ダメージがあたえられたかどうかにかかわらず」:魔物不受傷害(S-095、M-051 等)或被保護,都照樣無效。
3. 自己場上沒有魔物時不能使用(`event.condition`)。

「このバトルの、相手の攻撃1つ」:一場戰鬥只有一個攻擊,就是目前的攻擊。

### D3:效果編號

- `GameState` 加一個計數器(`use_seq`)。`run_effect` 從根節點開始解決時,把新編號寫進 ctx(`use_id`);`resume` 沿用 ctx 裡的編號。解決期間 `GameState.current_use` 是目前的編號,結束後還原外層的值;不在效果樹解決中時為 None。
- `add_modifier` 與 `schedule_standby` 把目前的編號記在 `Modifier.use_id` / `Standby.use_id` 欄位。不放進 `data`,避免改動既有的 data 內容與呼叫端傳入的 dict。
- 新節點 `SeparateEffects(steps)`:效果文用「●」列出、各自是獨立效果時使用,每一步各給一個新編號。目前只有 Ex-021 需要:它的加魔力是【ステイ】,結束階段棄掉是【スタンバイ】,兩者各自獨立。
- 用途:Ex-070 取除一筆紀錄時,同一個編號的其他紀錄一起取除(複合效果整個取除)。

### D4:Ex-070 取除提升魔力的效果

**判斷依據**
`engine.raises_power(entry)` 依紀錄的種類判斷。持續效果都算「ステイ」,待命都算「スタンバイ」:

| 分類 | 持續效果(modifier) | 待命(standby) |
|---|---|---|
| 魔物魔力 | `power`(amount > 0)、`power_partnered`、`power_per_own_mamodo` | 子樹含提升魔物魔力節點的 `Standby`(E-001;節點標 `raises_power`) |
| 戰術魔力 | `attr_power`(S-062)、`spell_named` 有 `power > 0`(PR-010) | `spell_bonus` 有 `power_delta > 0`(P-007、P-023;M-008 是減魔力,不算)、`attack_spell_boost`(PR-006)、`after_battle` 的 `attr_power` |
| 合計魔力 | `side_power`(MJ-002 / MJ-005) | `attack_power_from_mamodo`(S-089) |

**取除的範圍**
- 雙方的效果都取除:效果文沒有指定對象,卡頁 FAQ 說自己的也會被取除。
- 判斷符合的紀錄,連同同一個效果編號的其他紀錄一起取除。沒有編號的紀錄(引擎直接建立的,例如 S-062 戰鬥結束時開始的屬性加成)只取除它自己。例如 M-052 的傷害 +1、PR-006 的任意頁待命、PR-010 的減費(同一筆紀錄)。

**不取除**
- 減魔力的效果(Ex-002、S-033 的 `power` amount < 0)。
- 「設為某值」的 `power_set`(M-035、P-011):使用者決定,這是「設成某個值」,不是「上げる」。
- 常駐效果(`STATIC_*`)、戰術自身的宣告時加成(`battle.data` 的加成,不是持續或待命)。

**其他**
- Ex-070 是非戰鬥事件卡,使用時不會有「このバトル中」的效果(M-001 等)。判斷仍照種類寫,不另外排除。
- 事件 `power_ups_removed` 帶被取除效果的來源卡,比照 `restrictions_removed`。

## Risks / Trade-offs

- **戰鬥中的傷害流程**:目前戰鬥中造成傷害的是攻擊結算,E-053 是第一個在「効果の使用」造成傷害的效果。
  - 風險:`_finish_damage` 可能誤推進戰鬥步驟。
  - 對策:測試涵蓋保護選擇、傷害後換對方使用效果、之後進入魔力勝負。
- **效果編號只對新產生的紀錄有效**:不影響舊存檔,因為遊戲狀態不跨版本保存。
- **以種類判斷可能漏掉新的加魔力種類**:登記新種類時要更新 `raises_power`;game-engine/design.md 記下這條規則。
