# Design

## Context

規則原文(atwiki 規則頁 pages/94「④バトル・インの確認」):攻撃する効果を使い、非バトル中からバトル中に突入することを「バトル・イン」という。バトル・インする前に、非ターンプレイヤーに「バトル・インしていいですか?」と確認をとる。非ターンプレイヤーがアクションをしなければターンプレイヤーはバトル・インし、アクションをしたら確認は無効になる。

## Decisions

- 三個用語分開:步驟(バトル・インの確認)、非回合玩家的回應(認める)、回合玩家的動作(バトル・イン)。非回合玩家按的不是「バトル・イン」,而是同意對方進入戰鬥,所以按鈕為「同意進入戰鬥」(使用者採用)。
- 不提供「進入戰鬥,不防禦」:進入戰鬥後到防禦步驟之間,引擎還要處理攻擊的宣告時效果(擲硬幣的「不能防禦」、加魔力、攻方的選擇、防方的ジャマー),不能完全合併成一步;使用者決定不加只合併一半的選項。
- 只改文字,行為不變;引擎的錯誤代碼(`battle_in.*`)不變。

## Risks / Trade-offs

- [規格(spec.md)的需求文字仍有「戰鬥開始確認」「迎戰」] → 規格以 delta 修改,範圍大;另行處理(見 tasks)。design 已直接改用新用語。
