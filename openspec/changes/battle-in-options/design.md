# Design

## Context

- 戰鬥開始確認:`battle_in_response allow` 後 `_start_battle` 依序處理戰鬥開始的待命、攻擊時待命、魔物效果攻擊的ジャマー、攻方的選擇、宣告時效果,之後才到防禦步驟(`battle.step == "defense"`)。
- 自動 pass(auto-pass)已在前端處理「沒有可用防禦時自動不防禦」。

## Decisions

### 「進入戰鬥,不防禦」在前端記住,不改引擎

按下時送出 `battle_in_response allow`,並記下 `PRESET_NO_DEFENSE = {player, turn_no, attacker}`。每次重繪行動欄時:這場戰鬥(同回合、同攻方)進入防禦步驟、輪到該玩家、沒有 pending,就送出 `no_defense` 並清除;換回合、戰鬥開始確認被中斷(`battle_in` 與 `battle` 都沒有)時清除。
- 不改引擎:防禦步驟本來就是一個獨立的回應點,前端代為回應與自動 pass 同一個機制;斷線時由既有的逾時代打(不防禦)處理,結果相同。
- 替代方案:引擎的 `battle_in_response` 加參數,進入防禦步驟時直接處理不防禦。要在每個可能停下的地方(ジャマー、攻方選擇)之後檢查,改動較大,而結果相同。
- 送出前檢查沒有送出中的指令(`SENDING`),避免與自動 pass 同時送出。

### 用語

規則術語「バトル・イン」:繁中「進入戰鬥」(簡中由工具產生)、日文「バトル・イン」、英文「Battle in」。「進入戰鬥,不防禦」:繁中「進入戰鬥,不防禦」、日文「バトル・イン(防御しない)」、英文「Battle in, no defense」。

## Risks / Trade-offs

- [預先不防禦後,宣告時效果讓攻擊變得很危險] → 這是玩家選擇放棄「看完再決定」;提示寫明「進入戰鬥」可以在下一步再決定。
